# 27 · Octop 体验差距复核（第二轮）

> 本文是差距记录；**封版基线以 [`28`](28-需求追踪矩阵.md)–[`32`](32-模块接口与状态机.md) 为准**。

> 结论先说：**现在不是"和 Octop 差不多"，而是"看起来像、主要路径能点"的高保真原型。**
> 布局骨架已经接近，但表单、数据视图、权限态、失败回滚和真实状态管理仍明显弱于 Octop。
> 本文只谈体验差距，不重复功能清单。

## 2. 为什么"看起来像、用起来不像"

### 2.1 按钮演示入口（已清零）

此前 `data-act="toast-demo"` 有 49 处：

- 管理端：模型配置、存储浏览、插件详情/卸载、安全规则保存、备份、HTTPS、更新
- 设置：更换头像、修改资料、通知开关
- 技能/专家：部分编辑、导出
- 工作台：终端/浏览器卡片

这些入口已在 2026-11 清零：能改状态的改为真实操作，纯后端能力改为明确禁用/说明。

### 2.2 表单只"长得像"，没有表单系统

Octop 的表单能力：

- 字段级 rules（必填、长度、正则、URL、密钥格式）
- 字段级错误，不丢输入
- 脏状态提示（离开前确认）
- 保存中 loading、失败保留、成功回写列表
- 部分字段"测试连接"后再允许保存
- 危险操作二次确认 + 回滚

我们只有：

- 邀请邮箱、环境变量、连接器名称做了校验
- 大多数抽屉/弹窗保存后只 toast，不改数据
- 之前没有 dirty guard；现已在表单/邀请弹窗接入，关闭前确认放弃。

### 2.3 表格/列表缺"数据视图"能力

Octop 的列表普遍有：

- 搜索、筛选、排序、分页
- 列显示/隐藏
- 批量选择 + 批量操作
- 行 hover 操作、空态、加载态
- 点击行进详情/抽屉

我们目前：

- 知识库：搜索 + 批量 + 预览定位（较好）
- 用户/模型/插件/技能/审计：基本是静态表
- 没有排序、分页、列配置；大数据量会直接铺满
- 空态只覆盖知识库/连接器/管理

### 2.4 抽屉字段没有真正驱动页面

专家抽屉、连接器抽屉、存储配置、模型配置都"有字段"，但：

- 专家保存不改变列表里的名称/模型
- 连接器保存不改变卡片状态/工具数
- 模型配置不改变对话模型菜单
- 存储配置不改变数据地图
- 技能/插件安装是内存数组，刷新即回退

这会直接造成"点了没发生什么"的感觉。

### 2.5 布局还有"拼出来"的痕迹

- 设置页内容宽 900，右侧大留白；管理页却铺满
- 页面标题有的用 `cfgHead`，有的手写，间距不完全一致
- 连接器两层 Tab（一级 + 已启用/内置/自定义）略重
- 扩展市场 3 张大卡，信息密度低于 Octop
- 侧栏 8 项 + 3 组，底部留白仍大（8+3 的必然结果）
- 表格列宽/行高不统一，长文本没有统一 ellipsis

## 4. 和 Octop 的真实差距

Octop 的"完善"来自四层，不只是页面：

1. **真实 API + 状态回写**：保存后列表/详情/对话模型都变。
2. **表单/表格基础组件**：AntD Form/Table 自带校验、分页、排序、空态。
3. **异常路径**：401、403、409、超时、部分失败、重试、回滚。
4. **权限与多租户**：按钮不是"能不能点"，而是"这个人能不能看"。

原型目前有第 1 层的视觉、第 2 层的部分结构，缺第 3/4 层。

## 6. 什么情况下可以说"差不多"

至少满足：

- 任一页面主操作都能完成一次真实状态变更；
- 表单错误不丢输入，保存失败可回滚；
- 表格 100 行数据仍可搜索/排序/分页；
- 每个按钮都有 loading/disabled 原因/权限判断；
- 401/403/网络失败有可恢复路径；
- 1280/1024/移动端布局不破。

目前还差得远，但骨架已经够用，下一步应该做"厚度"，不是继续铺页面。

## 8. 权限与错误模型（2026-11）

### 角色

| 角色 | 可访问 | 说明 |
|---|---|---|
| 管理员 `admin` | 全部 | 含管理后台 |
| 成员 `member` | 对话/任务/专家/知识/连接/扩展/工作台/用量/设置 | 无管理后台 |
| 只读审计 `auditor` | 对话/任务/知识/用量/设置 | 无管理、连接、扩展、工作台；知识库只读 |

入口：

- 账户菜单 →「角色（演示）」切换
- `?role=member#/chat`、`?role=auditor#/chat`

行为：

- 侧栏按角色隐藏入口；无权限按钮 `disabled` + “当前角色无权限”；
- 只读审计进入对话时显示只读 banner，输入框/发送/新建对话禁用；
- 直接访问无权限路由显示 403；
- 403 页可「请求访问」或「切换为管理员」；
- 知识库审计角色隐藏上传/删除/重建，仅保留预览/检索。

### 错误页

| 码 | 标题 | 主操作 |
|---|---|---|
| 401 | 登录已过期 | 跳转登录页 |
| 403 | 没有访问权限 | 请求访问 / 切换管理员 |
| 409 | 版本冲突 | 刷新 / 覆盖保存 |
| 500 | 服务暂时不可用 | 重试 |

入口：账户菜单 →「错误页（演示）」；或 `?error=401|403|409|500`。

### 保存失败 / 冲突 / 列表失败

- 表单值含 `conflict`：弹 409 冲突弹窗，可刷新或覆盖。
- 表单值含 `fail`：保留已填内容并显示保存失败，可重试。
- `?state=listfail`：表格显示统一“列表加载失败 + 重试”。
- 空态统一使用表格/卡片空态组件，带主操作。

### 仍缺

- 真实登录态/Token 刷新；
- 后端 409 冲突合并；
- 字段级权限（只读字段/隐藏字段）；
- 权限变更后的实时踢出/刷新。

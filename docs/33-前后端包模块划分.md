# 33 · 前后端包模块划分（v1.0 定稿）

> 目的：把"模块边界"落到**目录、包、依赖方向、导入规则**，避免实现时又回到 Octop 那种 `infra/` 平铺 + 上帝对象。
> 参考 Octop：`src/octop/api` + `infra/<domain>` + `dashboard/src/pages|components|api` 的分层；
> 我们修正：domain 先于技术层、kernel 独立、前端按 feature 切、API 类型生成、依赖方向可检查。

---

## 1. 结论

| 层 | 是否敲定 | 说明 |
|---|---|---|
| 后端领域边界 | **是** | 16 个 domain，见 §3；admin 降为 application service |
| 后端包/目录 | **是** | 本文 §3 为最终树；`02 §2.3` 的初版树被本文替代 |
| 后端依赖方向 | **是** | kernel ← platform ← domains ← api/workers；见 §4 |
| 前端技术栈 | **是** | React + TS + Vite + TanStack Query + 轻量 external stores |
| 前端 feature 划分 | **是** | 每个一级路由一个 feature，见 §5 |
| 前端 shared UI | **是** | `components/ui` 无业务；`layouts` 负责壳 |
| 共享契约 | **是** | `contracts/spec` → `schemas` → `generated/{py,ts}` |
| 单仓多包 | **是** | 单仓；后端一个 Python 包，前端一个 Vite app；不拆 npm workspace（v1） |
| 模块 owner/CODEOWNERS | 待定 | 实现期按团队补 |

### 3.1 每个 domain 内部固定结构

```
domains/<name>/
├─ __init__.py       # 只导出 service/ports/公开 DTO
├─ models.py         # dataclass/DTO，不依赖 ORM
├─ ports.py          # Protocol（跨域依赖只在这里）
├─ service.py        # 用例/事务边界
├─ repo.py           # SQL，只访问本域表
├─ errors.py         # DomainError 子类/错误码
├─ events.py         # 本域事件构造
└─ handlers.py       # 订阅其他域事件（可选）
```

禁止：

- `domains/a/repo.py` import `domains/b/repo.py`
- `api/routers/*` 直接写 SQL
- `kernel/*` import `domains/*` 或 `platform/*`
- `platform/*` import `domains/*`
- 一个 `service.py` 超过 ~600 行；按用例拆 `services/`。

## 4. 后端依赖方向

```
kernel        （只依赖 stdlib + kernel 自身）
   ↑
platform      （可依赖 kernel 的 Protocol？否；只提供技术能力）
   ↑
domains       （可依赖 kernel + platform；跨域只依赖 ports/events）
   ↑
api / workers / cli
```

更精确：

- `kernel` 不 import `platform`/`domains`；模型/工具适配器由 `domains` 注入。
- `platform` 不 import `domains`；通用能力，不知道业务。
- `domains` 可以 import `kernel`、`platform`、`contracts` 生成类型。
- `api`/`workers` 组合 domains，不写业务规则。
- 跨域调用：`A.service -> B.ports.Protocol`，实现由 DI 容器注入。
- 跨域副作用：`outbox` 事件，不直接调用 B 的 repo。

### 4.1 依赖注入

```python
@dataclass
class Container:
    clock: Clock
    ids: IdGen
    db: Database
    events: EventStore
    outbox: Outbox
    model_gateway: ModelGateway
    identity: IdentityPort
    conversations: ConversationPort
    tickets: TicketPort
    agents: AgentPort
    capabilities: CapabilityPort
    connectors: ConnectorPort
    knowledge: KnowledgePort
    memory: MemoryPort
    channels: ChannelPort
    control: ControlPort
    cloud: CloudPort
    usage: UsagePort
```

`create_app()` 只组装一次；测试用 fake 替换。

### 4.2 事务边界

- `service.py` 开事务；`repo.py` 只接收 connection。
- `api` 不 commit；`workers` 每个 step 一个事务。
- 事件与投影同事务；外部副作用进 outbox。
- 跨域最终一致，读模型允许延迟。

### 5.1 前端分层规则

- `routes/*` 只做页面组合，不写请求/SQL 风格逻辑。
- `features/*` 拥有自己的组件、hooks、store、api；跨 feature 通过 `components/ui`/`lib`。
- `components/ui` 不含业务；不 import `features`。
- `lib/api` 统一错误映射、401 刷新、403 跳转、trace header。
- `lib/stream` 统一 SSE/WS；组件不直接 new EventSource。
- `stores` 只存客户端状态；服务端数据用 TanStack Query。
- `types/generated.ts` 从 `generated/ts` 复制/软链，禁止手写重复类型。

### 5.2 状态归属

| 状态 | 归属 |
|---|---|
| 会话列表/当前会话 | TanStack Query + session store |
| 消息/事件流 | stream store + query cache |
| 草稿/队列 | chat feature store |
| Dock/侧栏/主题/快捷键 | ui store + storage |
| 表单 | 组件本地 state + zod |
| 权限 | auth context + `can()` |
| 服务端错误 | Query error + error boundary |

### 5.2.1 流式状态机（D-16，`useStream` 契约）

```
idle ──send──> optimistic ──server_ack──> streaming ──completed──> idle
                   │                          │
                   │ack超时2s/网络错            │断线
                   ▼                          ▼
                rollback(撤回乐观消息)      reconnecting ──after_seq 回放──> streaming
                                              │回放失败(EVENT_GAP)
                                              ▼
                                          snapshot(拉快照重建) ──> streaming
streaming ──error{retryable}──> error(可重试，保留已生成) ──retry──> streaming
streaming ──error{!retryable}──> failed(消息标错，不回滚)
```

**乐观更新回滚规则**：用户消息先本地插入（`clientPendingId`），服务端 ack（`turn.queued`）后替换为真实 ID；2s 未 ack 或发送失败 → **撤回本地消息 + 恢复输入框内容 + toast 说明**，不吞输入。插话/已读/停止按钮同理：乐观生效，NACK 回滚。

**渲染分层**：文本 delta 走 50ms 批 paint；结构化帧（审批/错误/工具卡）跳过批队列立即 paint（NFR-18）。

## 6. 共享契约

```
contracts/spec/api.py       # 端点/模型唯一源
contracts/spec/events.py    # 事件唯一源
schemas/api/openapi.json    # 生成
schemas/events/*.json       # 生成
generated/py/poly_contracts # 生成
generated/ts/src/*.gen.ts   # 生成
```

规则：

- 改 API/事件必须先改 `contracts/spec`，再 `make contracts`。
- 前端只能 import `generated/ts`，不手写同名类型。
- 后端 router 的 response_model 用生成类型或 domain DTO 显式映射。
- CI 检查生成物是否落后。

## 9. 与 Octop 的差异

| 项 | Octop | PolyOpus |
|---|---|---|
| 后端 | `infra/` 20 子包平铺 | `kernel/platform/domains` 三层 |
| 领域 | 多个 manager 上帝对象 | 每域 service/repo/ports |
| 前端 | pages/components 混放 | routes/features/components 三层 |
| 类型 | 手写 + 局部生成 | contract 单一源，全量生成 |
| 事件 | trajectory 分散 | events + outbox + projection |
| 依赖 | 跨层 import 常见 | 依赖方向 CI 检查 |

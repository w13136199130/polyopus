# 30 · 按钮与页面状态总表

> 目的：合并 `15`（按钮级交互）、`22`（Octop 逐按钮）、`23`（专家抽屉）、`24`（连接器/知识库）、`25–27`（差距审计/体验复核），形成唯一权威的"页面 × 控件 × 状态 × 权限 × API"总表。
> Octop 的可借鉴点：一页一个主操作、危险操作靠右、行内操作文字化、低频进 `⋯`、异步按钮 loading、空态给主操作、错误用稳定 code 分支、配置页不叠第二层菜单。

---

## 1. 设计不变量

1. **一级导航只有 8+3**；配置页二级用页内 Tab，不再长第二侧栏。
2. **一页最多一个主按钮**（主色实心），次按钮在左侧，危险按钮最右。
3. **行内操作**用文字按钮；低频/危险进 `⋯`。
4. **所有异步按钮**：点击后 disabled + loading，防重复；失败保留输入。
5. **所有危险操作**：确认弹窗，确认按钮在右，默认焦点在取消。
6. **所有表单**：必填 `*`、字段级错误、help、dirty guard。
7. **所有列表**：搜索/排序/分页/空态/失败重试；批量操作 sticky。
8. **所有权限**：无权限按钮 disabled + title；无权限路由 403。
9. **所有错误**：稳定 code 分支，不解析文案。
10. **所有页面**：1280 不溢出，960 侧栏收起，移动端可完成主路径。

## 13. 表单规则

| 规则 | 说明 |
|---|---|
| 必填 | label 后 `*`，空提交字段级错误 |
| 长度 | 前端即时，后端二次校验 |
| 格式 | URL/邮箱/ID/密钥分别校验 |
| 错误 | 错误在字段下方，不丢输入 |

| 保存 | loading + disabled；失败保留并显示重试 |
| 回滚 | 服务端失败恢复上次快照 |
| 冲突 | 409 弹刷新/覆盖 |
| 危险 | 二次确认，确认按钮在右 |
| 成功 | toast + 关闭 + 列表回写 |

### 14A.6 敏感操作 step-up（全局弹层）

| 控件 | 触发 | 状态 | 失败 | API |

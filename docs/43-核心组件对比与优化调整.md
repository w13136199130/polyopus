# 43 · 核心组件对比与优化调整（执行器 / 上下文 / 记忆 / 知识 / 模型 / 流畅交互）

> 范围：对照 Octop **1.0.3b4** 运行时代码，逐组件回答三件事——**Octop 做对了什么、
> PolyOpus 设计的弊端在哪、怎么调整**。重点在用户可感的七个核心组件：
> 流畅、交互、上下文、记忆、知识库、模型、执行器。
> 结论先行：**PolyOpus 赢架构、Octop 赢引擎**；当前最大风险不是功能面，而是
> 四个"引擎级"规格深度不足：**执行器管线、模型网关、前端流式性能、上下文计量**。

---

## 0. 差异化定位（先说不追什么）

| 维度 | Octop b4 | PolyOpus | 定位 |
|---|---|---|---|
| 执行引擎 | 现成包（octop-harness 1.0.8 + deepagents），成熟但黑盒 | 自研薄内核（规格态） | **必须超越**：可控恢复语义是我们的立身之本 |
| 交互打磨 | 两年踩坑（50ms paint、锚定、审批恢复） | 原型级 | **照抄资产清单**（`04 §12`），不重新发明 |
| 上下文/记忆 | 引擎强（五层记忆、中间件压缩） | 设计对但薄 | **借机制**：分档预算、规则晋升已收；补计量与批参 |
| 知识库 | 明显短板（固定切片+暴力余弦） | 全面领先 | **保持**；补就绪门禁与启动恢复 |
| 模型层 | 散落但功能多（健康换模/预置/Responses） | 端口统一但功能少 | **补齐三件**：健康探测、预置同步、价格表 |
| 状态/租户/治理 | 结构性缺陷（四套真相/无租户/五套治理） | 全面领先 | 不追平，保持 |

**一句话**：不追"功能数量"，追"引擎规格深度"；Octop 的交互资产逐条搬，Octop 的架构问题一条不学。

## 1. Octop 做得好的地方（证据级）

### 1.1 执行器（Octop 最强项）

- **有序中间件链**：`AgentManager` 在 harness 基础上按固定顺序追加宿主中间件
  （`manager.py:4248-4263`：插件链 → 配额 → 推理 → 知识提示 → 浏览器 profile →
  二进制保护 → MCP 错误整形 → 图片落盘 → artifacts → octop_ui 卸载）。
  每个横切关注点一个中间件，顺序即语义。
- **interrupt 式 HITL**：`tool_guard` 用 LangGraph `interrupt()` 暂停，`approve|reject` 恢复，图状态可序列化。
- **ACP 外接执行器**：OpenCode/Claude Code/CodeBuddy/Codex 作为 runner 统一接入。
- **response_mode**：按平台能力自动选流式/整段。

### 1.2 流畅（前端）

- **50ms 批量 paint**（`STREAM_PAINT_MS`）+ 不可变快照 + `useSyncExternalStore`。
- **虚拟列表前插锚定**（`react-virtuoso` firstItemIndex 倒扣）：加载历史不跳。
- **在飞尾部缓存**（sessionStorage 80k/条、1.5MB）：刷新不丢半条回答。
- **慢消费者合并 delta**（`coalesced:true`），队列 256 满则丢最旧帧。

### 1.3 交互

- **审批可恢复**：`pending_id` 落库，历史重载注入审批卡，刷新仍可批。
- **插话乐观行**：`steer:{clientPendingId}` + ack/drained/removed 三段 settle。
- **工具 UI 插件协议**：`octop_ui{renderer,version}` + `data_ref:"artifact"` + 错误边界回落。
- **轨迹（trajectory）**：user/assistant/tool/context/compacted 时间线，"重播这一轮"。

### 1.4 上下文

- 压缩 `0.85 × max_input` 触发、保留最近 10%；摘要输入 8k→4k→占位的三级降级。
- 工具结果 >20k token 卸载到文件、保留头尾 5 行 + 路径，模型可 `read_file` 取回。
- **CJK 感知的 token 估算**（中文 1.6 字/token、JSON 3.0、拉丁 4.0）+ provider usage 定期校准。
- 记忆召回拼在 **user 消息后缀**（不破坏 system/tool 缓存前缀），Anthropic 断点标记。

### 1.5 记忆

- 规则优先晋升（value→evidence→entity→duplicate→conflict），LLM 只兜底。
- 抽取批参：单批 ≤10k raw、≤20 候选、2048 completion token；复核单次 ≤20 atoms。
- 召回 1500 token / 200ms 硬预算；60s 缓存。

### 1.6 知识库（弱中有三点可学）

- **就绪门禁**：功能开启前校验模型已下载/凭证/可嵌入性（`gate.py`），启动时容器层丢依赖会大声告警。
- **启动恢复**：`resume_pending_index_jobs` 把卡在 processing 的文档重置并重新入队。
- **无 KB 隐藏工具**：检索工具的描述每轮按绑定 KB 重写，无 KB 时整个工具从模型视野移除。
- OCR 拒答检测（防"请上传图片"进索引）。

### 1.7 模型

- **进程内健康熔断**（`providers/health.py`）：`classify_model_failure` → 失败分类，
  open/half-open 冷却，AUTO 路由"预留一个健康模型"；健康不落库只影响运行时。
- 预置模型启动同步；失效默认模型自动替换；OpenAI Responses API；用量大额缩写。

图例：每条 = 弊端 → 调整 → 落点。**P0 = M1 前必须改，P1 = GA 前，P2 = 登记**。

### 2.1 执行器（差距最大）

## 3. 关键设计（落地稿）

### 3.1 内核中间件管线（EX-1，进 `03 §5`）

```
TurnEngine 执行一个 step 的固定管线（每步可单测；kernel 只编排+落 checkpoint）：
 1. 请求组装   ModelRequest 构造（消息、工具表、采样参数）
 2. 缓存标记   稳定前缀断点标记（provider 相关）
 3. 上下文预算 预算表分档 → 超限先 clearing 再压缩（CT-1/CT-2）
 4. 记忆召回   命中注入当前输入尾部（不破坏前缀）
 5. 知识提示   绑定 KB 时重写检索工具描述；无 KB 则移除该工具（KB-3）
 6. 策略闸门   evaluate()；懒 Ticket 升级判定（EX-4）；ask → 落 approvals + 暂停
 7. 模型调用   ModelGateway.stream()（健康路由 MD-2）
 8. 流式分发   delta → 事件总线（慢消费者 coalesce）
 9. 工具执行   ToolRuntime.invoke()（执行期二次校验，spike S3 语义）
10. 结果规整   大输出卸载 artifact（>2k token）；图片落缓存（CT-4）
11. 用量计费   三扣减点统一读 model_prices（MD-1）
12. step 落盘  checkpoint：已完成步骤 + 幂等键（EX-3 恢复依据）
```

规则：中间件不得互相 import；顺序变更走 ADR；每步产生的事件/指标在 `11` 定义。

### 3.2 ExecutorEvent（EX-2，进 `32 §6`）

```python
class ExecutorEvent(TypedDict): ...   # 判别联合
# delta{content} | reasoning{content} | tool_call{tool_key,args} |
# tool_result{ref,artifacts} | progress{pct,summary} | heartbeat{at} |
# report{state,summary,facts,artifacts,usage} | error{code,retryable}
class Executor(Protocol):
    async def execute(self, ctx) -> AsyncIterator[ExecutorEvent]: ...
    async def resume(self, run_id: str) -> AsyncIterator[ExecutorEvent]: ...  # 从 checkpoint 续
    async def cancel(self, run_id: str) -> None: ...                          # 同步取消+异步 best-effort
```

### 3.3 模型网关 v2（MD-1..3，进 `02 §5.1`）

- `ModelCaps{max_input, max_output, supports_tools, supports_vision, supports_responses_api, cache_style}`。
- 健康状态机：失败分类（网络/限流/鉴权/内容）→ open 冷却 60s → half-open 试探一次；AUTO 路由 `reserve_healthy()`。
- 预置同步：启动 merge 预置 `models` 行，用户改过的（`updated_by` 非空）不覆盖。
- 计费：ModelGateway / ToolRuntime(embedding) / 评估三个入口统一按 `model_prices.version` 计 `cost_micros`。

# 32 · 模块接口与状态机

> 目的：把模块边界、端口签名、状态机、事务边界写死，避免"文档有模块名，代码里互相 import"。
> **最终目录/包划分见 [`33-前后端包模块划分.md`](33-前后端包模块划分.md)；边界决议见 [`34-模块边界ADR.md`](34-模块边界ADR.md)。**
> 参考 Octop：
> - 路由/服务/仓储分层，`OctopError` 跨边界；
> - `ToolRuntime`、`InboxManager`、`ConnectorManager` 等能力对象通过 server 组合；
> - 事件驱动 UI，trajectory 追加写；
> - 迁移与 repo 按域拆分。
>
> 我们修正 Octop 的薄弱点：进程内 InboxManager → 持久化邮箱；单实例用户 → 租户；内存队列 → outbox；事件/步骤 → 可回放。

## 1. 模块与依赖

```
api (HTTP/SSE)
  ├─ identity (auth, tenant, RBAC)
  ├─ conversations (thread/turn/run/step/event)
  │    ├─ kernel (model gateway, prompt, tool loop)
  │    ├─ executor (builtin | codex | claude_code | dsh)
  │    ├─ capabilities (tools, skills, plugins, MCP)
  │    ├─ memory
  │    └─ knowledge
  ├─ intake (source/trigger/eval)
  │    └─ tickets (ticket/mandate/assignment/report)
  ├─ agents (expert/version/file)
  ├─ connectors (catalog/instance/oauth)
  ├─ extensions (plugin/skill-package)
  ├─ attention (approval/question/blocked)
  ├─ channels (IM)
  ├─ usage / billing
  ├─ audit / observability
  └─ admin / settings
```

规则：

- 上层可依赖下层；同层只能通过端口/事件，不直接读对方表。
- `conversations` 不 import `connectors` 实现，只依赖 `ConnectorPort`。
- `intake` 不直接调用 Executor；它创建 Ticket，由 `assignments` 调度。
- `api` 只做校验/权限/序列化，不写业务事务。
- 每个模块一个 repo；跨模块事务用 outbox/最终一致。

## 3. identity

### 职责

登录、会话、刷新、用户、角色、租户、权限、SSO/MFA、邀请。

### 端口

```python
class IdentityPort(Protocol):
    async def authenticate(self, email: str, password: str) -> AuthResult: ...
    async def current_user(self, token: str) -> Principal: ...
    async def require(self, principal: Principal, permission: str) -> None: ...
    async def issue_tokens(self, user_id: str) -> TokenPair: ...
    async def revoke(self, session_id: str) -> None: ...

@dataclass(frozen=True)
class Principal:
    user_id: str
    tenant_id: str
    role: str
    permissions: frozenset[str]
```

### 状态

```
anonymous -> authenticated -> expired -> anonymous
           -> locked
```

### 规则

- 登录失败不区分账号/密码。
- refresh 旋转，旧 refresh 立即失效。
- 权限判断只在 API 层 + 服务层各一次；repo 不做权限。
- 租户不匹配 → `TENANT_MISMATCH` 403。

## 4. conversations / Turn

### 职责

thread、message、turn、run、step、event、steer、approval pause、context。

### 端口

```python
class ConversationPort(Protocol):
    async def create_thread(self, cmd: CreateThread) -> Thread: ...
    async def append_user_message(self, cmd: SendMessage) -> Turn: ...
    async def stop_turn(self, turn_id: str, actor: str) -> Turn: ...
    async def steer(self, turn_id: str, text: str) -> Steer: ...
    async def withdraw_steer(self, steer_id: str) -> None: ...
    async def edit_resend(self, message_id: str, text: str) -> Turn: ...
```

### Turn 状态机

```
queued
  └─> running
        ├─> waiting_approval ─> running
        ├─> waiting_input ─────> running
        ├─> completed
        ├─> failed
        └─> cancelled
```

规则：

- `running` 才能 approve/steer；`queued` 可 cancel。
- `completed/failed/cancelled` 终态，不可再写 delta。
- 同一 thread 同时只允许一个非终态 turn（`THREAD_TURN_ACTIVE`）。
- 停止保留已生成内容；事件写 `turn.finished(status=cancelled)`。

### Run 状态机

```
leased -> running -> waiting -> running -> completed
                 └-> failed
leased -> expired -> queued (retry)
```

- `lease_until` 到期可被其他 worker 抢占。
- `attempt` 递增，旧 run 标 `expired`。
- 每个 step 追加写，`last_step_idx` 只前进。

### 事务

`send message`：

```
BEGIN
  insert messages(user)
  insert turns(queued)
  append event(message.started)
  outbox.enqueue("turn.queued")
COMMIT
```

worker：

```
claim run (lease)
append step.started
call model/tool
append event(delta/tool)
update projections
COMMIT per step
```

## 5. kernel / model gateway

> ADR-007：kernel 只做无状态执行循环；Turn/Run/Step 持久化状态机归 `conversations`。kernel 不写 DB、不发事件、不 import platform/domains。

### 端口

```python
class ModelGateway(Protocol):
    async def stream(self, req: ModelRequest) -> AsyncIterator[ModelDelta]: ...
    async def complete(self, req: ModelRequest) -> ModelResponse: ...
    def capabilities(self, model: str) -> ModelCaps: ...

@dataclass(frozen=True)
class ModelDelta:
    kind: Literal["text", "reasoning", "tool_call", "usage", "done"]
    text: str | None
    tool: ToolCall | None
    usage: Usage | None
```

### 规则

- 不重试非幂等 tool call；文本 delta 可重试但必须从 last_seq 续。
- 超时/限流 → `MODEL_RATE_LIMITED`/`MODEL_NOT_AVAILABLE`。
- 用量写 `usage_ledger`，超预算 → `TURN_BUDGET_EXCEEDED`。
- prompt 组装只读，不写 DB；context snapshot 单独表。

## 6. executor

### 端口

```python
ExecutorEvent = Literal[
    "delta", "reasoning", "tool_call", "tool_result",
    "progress", "heartbeat", "report", "error",
]
# delta{content} | reasoning{content} | tool_call{tool_key,args} |
# tool_result{ref,artifacts} | progress{pct,summary} | heartbeat{at} |
# report{state,summary,facts,artifacts,usage} | error{code,retryable}

class Executor(Protocol):
    async def execute(self, ctx: ExecutionContext) -> AsyncIterator[ExecutorEvent]: ...
    async def resume(self, run_id: str) -> AsyncIterator[ExecutorEvent]: ...
    async def cancel(self, run_id: str) -> None: ...
    def capabilities(self) -> ExecutorCaps: ...

@dataclass(frozen=True)
class ExecutionContext:
    tenant_id: str
    turn_id: str
    ticket_id: str | None
    mandate: Mandate
    workspace: Path
    trace: TraceContext
```

**恢复与取消语义**：`resume` 从最后一个完成的 step 之后继续，未完成 step 重执行、工具按幂等键去重；`cancel` 对同步工具取消执行、对异步工具 best-effort cancel 并发 `tool.async_cancelled`；`heartbeat` 至少每 30s 一次，超时由 Watchdog 判 stalled。

### 规则

- **`ticket_id` 可空，但语义受限**：为空仅允许“只读、无副作用、`risk=low`、无预算/审批”的直接对话；一旦调用写工具、需要审批/预算/异步，必须先创建 Ticket 并回填 `turn.ticket_id`（`02 §3.6.1` / `ADR-012`）。
- 外部 executor（Codex/Claude/DSH）只能通过 `report()` 影响 Ticket，不能直接改 Ticket 状态。
- 外部进程崩溃 → assignment `dead`，由调度重建。
- 所有工具调用前校验 `mandate.scope`；`ticket_id` 为空时 `mandate` 只含只读 scope。
- 产物写 artifacts，不写 workspace inbound。

class IntakePort(Protocol):

### 状态机

```

         -> duplicate
         -> evaluating -> accepted -> ticket

```

规则：

- `(source_id, dedupe_key)` 唯一。
- Gate 必须写 disposition，不能静默丢。

- Ticket 的 Mandate 不可变；扩大 scope 必开新 Ticket。

### 端口

```python
class TicketPort(Protocol):

### 状态

```

## 9. agents

> ADR-005：agents 只做 expert/agent 配置与版本，不再有 `kind=team`；团队归 `orchestration`。

### 端口

```python
class AgentPort(Protocol):
    async def create(self, cmd: CreateAgent) -> Agent: ...
    async def update_draft(self, agent_id: str, patch: AgentPatch) -> Agent: ...
    async def publish(self, agent_id: str) -> AgentVersion: ...
    async def rollback(self, agent_id: str, version: int) -> AgentVersion: ...
    async def resolve_for_turn(self, agent_id: str) -> AgentSnapshot: ...
```

### 规则

- 发布生成不可变 `agent_versions`。
- **版本锁定（D-12 定稿）**：
  1. `threads.agent_version_id` 在**创建 thread 时**锁定为当时的 current 版本；
  2. 每个 **Turn 开始时**把该版本快照进 `turns.agent_version_id`——同 thread 升级后新旧 Turn 可混用不同版本，逐 Turn 迁移而非一刀切；
  3. 发布新版本 / 回滚**只影响新 Turn**，进行中 Turn 不受影响；
  4. 显式"升级会话"操作才改 `threads.agent_version_id`（弹窗提示"新消息起用 vN"）；
  5. 回滚 = 发布一个指向旧 `config_json` 的新版本号（版本号只增不回退），保证审计与引用不断链。
- 名称/ID 租户内唯一。
- 草稿与发布分离；试运行使用草稿快照。

## 13A. 补齐状态机（2026-11）

> 每个状态变更必须有事件；非法迁移返回 409，不允许静默忽略。

| 对象 | 状态迁移 | 触发 | 事件 |
|---|---|---|---|
| **ControlSession** | `starting → running → closed`；`starting/running → error` | 创建/关闭/进程退出 | `control.started/ended` |
| **CronJob** | `enabled → disabled`；`disabled → enabled` | 用户启停 | — |
| **CronRun** | `queued → running → succeeded/failed/skipped` | 调度/执行/错过 | `cron.fired` |
| **CloudOp** | `pending → running → succeeded/failed` | 云 API 调用/回执 | —（落 `cloud_ops`） |
| **Delegation** | `pending → running → ended/dead`；`dead → pending`（retry） | 派工/回报/重试 | `delegation.started/ended` |
| **MemoryAtom** | `candidate → active → retired`；`candidate → dropped`；`active → pending_review → active/retired` | 抽取/晋升/冲突/删除 | `memory.written/updated` |
| **Plugin** | `installed → disabled → enabled`；`installed/enabled → failed` | 安装/启停/加载失败 | `plugin.installed/failed` |
| **Notification** | `unread → read`；`unread → expired`（TTL） | 用户已读/清理 | `notification.created` |
| **Subscription** | `active → ended` | Ticket 结束 | `subscription.created` |

**规则**

- `CronRun` 的 `succeeded/failed` 必须带 `trigger_id` 或 `skip reason`。
- `Delegation` 的 `dead` 只能由 attempts 超限或人工停止触发；retry 必须保留原 `dedupe_key`。
- `CloudOp` 的 `pending` 必须先写库再调云 API；云侧失败也要落 `failed`。
- `MemoryAtom` 的 `retired` 不可回到 `active`，纠错生成新 atom + `supersedes`。
- 通知已读幂等；已过期通知不再出现在未读计数。

## 13B. 数据不变量（2026-11）

> 这些是“实现时必须成立的约束”，不是建议；违反即 409 或启动失败。

| 域 | 不变量 |
|---|---|
| 派工 | `delegations` 唯一键是 `(tenant_id, dedupe_key)`；`running` 必须有 `lease_until` 与 `last_heartbeat_at`；超时由 Watchdog 重派，`next_retry_at` 控制退避 |
| 外部身份 | `triggers.actor_id` / `channel_messages.actor_id` 必须引用 `source_actors.actor_id`；没有 actor 的入站消息拒绝入库；不得回填 Agent owner |
| 策略 | 每租户同时只有一个 `active` policy bundle；`policy_rules.bundle_id` 必须指向存在的 bundle；发布/回滚只切 active，不改历史 bundle |
| 策略可用性 | 策略加载失败时使用 last-known-good；没有 LKG 时只拒绝写工具，读工具可降级放行并告警 |
| ACL | `resource_group_grants.effect` 默认 allow；`expires_at` 到期自动失效；grant 变更必须使权限缓存失效并写审计 |
| 知识索引 | `knowledge_bases.embedding_version/chunker_version` 必须与 chunk 生成时一致；换模型/切片必须新建索引版本，禁止原地改维度 |
| 知识检索 | ACL 必须先过滤 KB/doc 再检索；空结果必须区分“无文档/被过滤/低分/上游不可用” |
| SSO | 首登必须过 `allowed_email_domains / allowed_groups`；不匹配返回 `SSO_NOT_ALLOWED`；`auto_provision` 默认 false；首登角色固定，`role_sync` 显式配置 |
| Token | 只接受 Authorization header 或 httpOnly cookie；query token 返回 `TOKEN_IN_QUERY`；登出撤销 refresh family |
| 多实例 | 实例心跳 15s、超 60s 判离线；配置/权限/策略/ACL 变更必须递增 `config_versions` 并触发各实例缓存失效；cron 由租约保证单飞 |
| 密钥 | 轮换采用双版本（新写旧读），旧版本保留一个轮换周期；失败告警并写审计；Provider 密钥与用户密码分储 |
| 提示注入 | 外部内容必须带 `untrusted` 标记且不进 system prompt；工具大输出只回摘要+引用；记忆/知识片段必须带来源标记 |
| 注意力 | `attention` 只能由结构化来源创建（`Report.state=waiting` + `question{text,options,blocking}` 或 `approval.requested`）；禁止解析自由文本；缺字段的 waiting 降级为 `blocked` |
| 订阅 | `subscriptions` 只做上下文扇出，**不提供授权**；任何工具调用仍按 `mandate.scope` + policy 现算 |
| 工单 | `tickets.status` 不跟随 executor session；executor 只能通过 `Report` 影响 Ticket |

## 13C. 拒绝概念清单（负向不变量）

> 与 13B 互补：13B 是"必须成立"，这里是"**不许出现**"。新增概念前先对照本表。

| 拒绝的概念 | 原因 | 替代 |
|---|---|---|
| Subscription 级准入检查 | 授权只应在 Mandate 求值一次；扇出不授予权限 | `09 §6.3` Mandate 校验 |
| Ticket 状态跟随 Executor Session | 执行器崩溃不应改变工作语义 | `Report` + 租约重派 |
| "等待中"的 Eval 状态 | Eval 无状态，等待是 Assignment/Ticket 的事 | `attention` + `ticket.waiting` |
| 从报告自由文本推断 Attention | 语义不可测、易误判 | 结构化 `question` 字段 |
| 让 Eval 自己排延迟任务 | 调度属于 `schedule` source 与 effect 退避 | `09 §8.1` 退避 |
| 跨来源身份"当提示词文本" | 多租户下不可审计 | `source_actors` |
| 一个 Thread 只能一个 Ticket | 同一 PR 可并行多件事 | `09 §7.3` |
| 用执行器内存状态做恢复依据 | 双真相 | `events` 重放（S1） |
| 面板上存在没有对应 API 的动作 | 不可测、不可自动化 | `coverage_check` 硬门禁 |

## 14. 关键时序

### 14.1 发消息

```
API -> identity.require(chat:write)
    -> conversations.send_message (tx: message+turn+event+outbox)
    -> return turnId
worker -> claim run -> kernel.stream -> events -> SSE
       -> tool -> runtime.invoke -> approval? -> attention
       -> turn.completed
```

### 14.2 审批

```
runtime -> attention.open(pending)
user -> POST /attentions/{id}/answer (idempotent)
     -> CAS status pending->answered
     -> append attention.resolved
     -> outbox resume_run
worker -> resume from last_step
```

### 14.3 Intake

```
source.receive -> trigger insert (dedupe)
gate -> filtered/duplicate
assessor -> decision
ticket.open + mandate
assignment.create -> executor
report -> ticket timeline
```

## 15. 事务与一致性

- 每个命令一个事务；跨聚合用 outbox。
- 事件与投影同事务写；投影失败可重建。
- 外部副作用（发 IM、调工具）不在 DB 事务内；用 outbox + 幂等。
- 读模型允许延迟；写后读用 same-connection/primary。
- 所有命令带 `trace_id`，全链路可追。

## 17. 与 Octop 的差异

| 项 | Octop | PolyOpus |
|---|---|---|
| 消息总线 | 进程内 InboxManager | 持久化邮箱 + outbox |
| 事件 | trajectory 追加 | events + steps + 投影 |
| 多租户 | 单实例用户 | tenant_id 全链路 |
| 执行器 | 内置 + ACP | Executor 端口，外部从属 Mandate |
| 权限 | user_permissions | roles + scope + 字段级 |
| 连接器 | manager 单例 | ConnectorPort + oauth_states |
| 迁移 | 分功能 SQL | 分功能 + checksum/回滚 |
| 错误 | ErrorCode | 同 + 幂等/版本冲突/事件缺口 |

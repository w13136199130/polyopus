# PolyOpus 模块设计与详细实现思路

> **参考文档**：最终端口签名以 `32` 为准，包/目录以 `33` 为准，边界决策以 `34` 为准；本文用于模块职责与 Octop 复用地图。
>
> 每个模块给出：**职责边界 → 领域模型 → 对外接口 → 关键流程 → 实现要点 → 失败模式 → 测试 → Octop 源码复用地图**。
> 复用地图的读法：`借鉴` = 可以照着数据结构/协议实现；`重写` = 能力要保留但实现必须换；`别抄` = Octop 的做法有已知问题，反面教材。

## 0. 模块总览与依赖

```
            ┌───────────────────────────────────────────────┐
            │ api/ (routers, ws, sse)   cli/   channels/     │
            │ intake/ (sources → triggers → tickets)         │
            └───────────────┬───────────────────────────────┘
                            │
   ┌────────────────────────▼────────────────────────────────┐
   │ domains: identity │ agents │ conversations │ capabilities│
   │          knowledge │ memory │ orchestration │ channels   │
   │          intake │ billing │ audit                       │
   └────────────────────────┬────────────────────────────────┘
                            │
   ┌────────────────────────▼────────────────────────────────┐
   │ kernel: loop · model gateway · tool executor · prompt    │
   │         context · steer · events                         │
   └────────────────────────┬────────────────────────────────┘
                            │
   ┌────────────────────────▼────────────────────────────────┐
   │ platform: db · queue · events · storage · secrets ·      │
   │           telemetry · i18n · config                      │
   └──────────────────────────────────────────────────────────┘
```

**跨模块通信规则**：同步调用只允许"上层→下层 + 同层 public service"；跨模块的副作用（发通知、记审计、触发索引）一律走**领域事件**（进程内 bus + 可选 outbox），避免 Octop 里那种 `AgentManager` 直接 import 团队、记忆、插件的网状耦合。

```python
# platform/events/bus.py
class DomainEvent(BaseModel):
    name: str                 # "turn.completed", "document.indexed"
    tenant_id: str
    aggregate_id: str
    payload: dict
    occurred_at: datetime

class EventBus(Protocol):
    async def publish(self, evt: DomainEvent) -> None: ...
    def subscribe(self, name: str, handler: Callable[[DomainEvent], Awaitable[None]]) -> None: ...
```

## 1. platform（平台底座）

### 职责
配置、数据库连接与迁移、事务、队列、事件总线、对象存储、密钥、遥测、i18n。**不含任何业务概念**。

### 关键设计

**配置优先级**：CLI 参数 > 环境变量 `POLY_*` > `config.toml` > 默认值。启动时打印生效配置摘要（脱敏），`poly config doctor` 做连通性自检。

**DB 与迁移**
- 单一 DDL 源：`migrations/NNN_name.yaml`（或 SQL 模板）→ 生成 `NNN.sql`（SQLite）与 `NNN.pg.sql`（PG）。Octop 手写两份 25 组迁移，已出现 `migrate.py` 2220 行的补丁山；不能重蹈。
- 事务：`async with db.tx() as tx:`，repo 只接受 `tx`，禁止隐式全局连接。
- SQLite：WAL、`busy_timeout=5000`、`foreign_keys=ON`、写连接单写者（asyncio 锁）；PG：`psycopg_pool`。

**队列（关键抽象）**

```python
class JobQueue(Protocol):
    async def enqueue(self, job: Job, *, delay_s: float = 0) -> str: ...
    async def claim(self, kinds: set[str], worker_id: str, lease_s: int) -> Job | None: ...
    async def heartbeat(self, job_id: str, worker_id: str) -> bool: ...
    async def complete(self, job_id: str, worker_id: str) -> None: ...
    async def fail(self, job_id: str, worker_id: str, err: str, retryable: bool) -> None: ...
```

实现：`PgJobQueue`（`FOR UPDATE SKIP LOCKED`）、`SqliteJobQueue`（`BEGIN IMMEDIATE` + `UPDATE ... RETURNING`）、`RedisJobQueue`（可选）。**默认实现必须无外部依赖**。

**对象存储**

```python
class BlobStore(Protocol):
    async def put(self, key: str, stream: AsyncIterator[bytes], *, content_type: str) -> BlobRef: ...
    async def get(self, key: str) -> AsyncIterator[bytes]: ...
    async def presign_put(self, key: str, ttl_s: int) -> str | None: ...   # 远程后端才支持
    async def delete(self, key: str) -> None: ...
```

实现：`LocalCasStore`（`~/.polyopus/artifacts/<sha256 前 2 位>/<sha256>`，内容寻址）、`S3Store`（兼容 COS/OSS/MinIO，path-style）。

**密钥**：`secrets` 表存 `AES-256-GCM` 密文，主密钥来自 `POLY_MASTER_KEY`（32B base64）或 `~/.polyopus/secrets/master.key`（0600）。支持轮换：`rotated_at` + 双密钥解密窗口。

**i18n**：`locales/{en,zh}/*.json` 按命名空间拆分；`t(key, locale, **fmt)`；CI 校验 key 树一致（Octop 的 `tests/unit/i18n` 做法直接借鉴，很有效）。

### 失败模式
| 场景 | 处理 |
|---|---|
| 迁移失败 | 事务内执行；失败回滚并拒绝启动，输出"当前版本/目标版本/失败语句" |
| 队列租约过期 | 任务回到 `queued`，`attempts+1`；超限进 `dead` 并告警 |
| 磁盘满 | 启动自检 + 写入前预检 + 明确错误码 `STORAGE_FULL` |

### 测试
迁移在空库/旧库/双 dialect 上各跑一遍（矩阵测试）；队列并发领取（100 协程抢 10 个任务，断言无重复）；BlobStore 契约测试（三实现共用一套）。

### Octop 复用地图
| 主题 | 结论 |
|---|---|
| `infra/db/repos/` 的"一表一 repo + 只写 SQL" | **借鉴**，但 repo 必须接收显式连接/事务 |
| `db/migrate.py`（2220 行手写补丁） | **别抄**；改用单一 DDL 源生成 |
| `infra/errors.py` 的 `ErrorCode` + 本地化 envelope | **借鉴**，错误码表作为契约测试对象 |
| `i18n/loader.py` + key 树一致性测试 | **借鉴** |
| `config.py`（env 驱动） | **借鉴**思路，补 TOML 与自检 |

## 2. identity（身份与访问）

### 职责
租户、用户、成员关系、角色与权限、API Key、SSO 提供方、MFA、邀请、会话令牌。

### 领域模型
```
tenants(tenant_id, name, plan, created_at)
users(user_id, tenant_id, username, email, password_hash, status, locale, ...)
memberships(user_id, tenant_id, role_id, status)
roles(role_id, tenant_id, name, permissions_json)      # 内置: owner/admin/member/viewer
api_keys(key_id, user_id, tenant_id, name, scopes_json, rate_limit, expires_at, last_used_at)
sso_providers(kind, tenant_id, config_json, enabled)
user_mfa(user_id, totp_secret_enc, webauthn_credentials_json, recovery_codes_enc)
invites(token, tenant_id, email, role_id, expires_at, used_at)
refresh_tokens(family_id, user_id, token_hash, expires_at, revoked_at, ua, ip)
```

### 对外接口
```python
class AuthService:
    async def login(self, username: str, password: str, *, ip: str, ua: str) -> TokenPair: ...
    async def refresh(self, refresh_token: str) -> TokenPair: ...
    async def logout(self, refresh_token: str) -> None: ...
    async def verify_access(self, token: str) -> Principal: ...

class AuthzService:
    async def can(self, principal: Principal, action: str, resource: ResourceRef) -> bool: ...
    async def require(self, principal: Principal, action: str, resource: ResourceRef) -> None: ...
```

**Principal**：`{user_id, tenant_id, role, permissions, scopes}`，随请求注入，不读全局状态。

### 关键流程
1. **登录**：查用户 → argon2 校验 → 失败计数（Redis/内存 + DB 落盘）→ 签发 access(15m) + refresh(14d, family) → 审计。
2. **刷新**：校验 refresh 哈希 → 检测复用（同一 token 二次使用 → 撤销整个 family 并告警）→ 轮换。
3. **授权**：`can()` 先看租户角色权限，再看资源 ACL（`resource_acl` 表），最后看特殊规则（owner 直通）。
4. **API Key**：`pk_xxx` 前缀可识别，哈希存储；校验时加载 scopes 与速率桶。

### 实现要点
- 权限点用字符串常量 + 枚举生成，前端通过 `GET /api/v1/me/permissions` 获取，菜单与按钮都按它渲染（Octop 已有雏形，但权限点与路由表是两处维护，易漂移）。
- 所有 repo 查询强制带 `tenant_id`；用一个 `@tenant_scoped` 装饰器/基类统一注入，配合测试断言"跨租户查询返回空"。
- 禁止在 JWT 里放权限列表（会过期不一致）；JWT 只放 `sub, tenant, sid, exp`。

### 失败模式
账号锁定 → `423 LOGIN_LOCKED`；token 过期 → `401 TOKEN_EXPIRED`（前端静默刷新一次）；权限不足 → `403 FORBIDDEN` 且不泄露资源是否存在。

### 测试
- 越权矩阵：5 个角色 × 12 类资源 × 6 个动作，断言允许/拒绝。
- 刷新令牌复用检测。
- WebAuthn 注册/登录的 mock ceremony。

### Octop 复用地图
| 主题 | 结论 |
|---|---|
| `api/routers/auth*.py` 的多 provider 流程 | **借鉴** provider 抽象；**重写** 为统一接口，去掉 3 套复制的 start/callback/exchange |
| `infra/users/permissions.py` 模块级权限 | **借鉴**；升级为"权限点 + ACL" |
| 登录锁定/验证码 | **借鉴** 锁定；验证码**暂缓** |
| JWT 24h 长效 | **别抄**；改短 access + refresh 轮换 |

## 3. agents（Agent 注册与模板）

### 职责
Agent 的创建/配置/版本/发布/共享/删除；模板库（专家库）；运行时的装配参数（模型、工具、技能、知识、记忆）以**声明式 spec** 表达。

### 领域模型
```sql
agents(agent_id, tenant_id, owner_id, name, kind, icon, status, current_version_id, created_at)
agent_versions(version_id, agent_id, version, spec_json, created_by, created_at, published_at)
agent_bindings(binding_id, agent_id, kind(tool|skill|kb|mcp|plugin|channel), ref_id, config_json, enabled)
agent_templates(template_id, source, manifest_json, files_json, version)   -- 内置/导入
agent_shares(agent_id, subject_type, subject_id, role)
```

**spec_json 结构**（版本化，`spec_version: 1`）：
```json
{
  "spec_version": 1,
  "identity": {"name": "...", "avatar": "...", "description": "..."},
  "prompt": {"files": ["SOUL.md", "AGENTS.md"], "variables": {}},
  "model": {"provider": "openai", "model": "gpt-5", "fallback": ["..."], "params": {}},
  "tools": {"enabled": ["fs.*", "web.search"], "disabled": [], "policy_overrides": {}},
  "skills": ["doc-writer"],
  "knowledge": {"kb_ids": ["kb_1"], "top_k": 6, "mode": "hybrid"},
  "memory": {"enabled": true, "budget_tokens": 1200},
  "limits": {"max_steps": 30, "max_tokens_per_turn": 60000, "timeout_s": 300},
  "ui": {"welcome": "...", "quick_prompts": [...]}
}
```

### 对外接口
```python
class AgentService:
    async def create(self, tenant_id: str, owner_id: str, draft: AgentDraft) -> Agent: ...
    async def update_draft(self, agent_id: str, patch: AgentDraftPatch) -> Agent: ...
    async def publish(self, agent_id: str, note: str) -> AgentVersion: ...
    async def rollback(self, agent_id: str, version: int) -> AgentVersion: ...
    async def resolve_spec(self, agent_id: str, *, version: int | None) -> AgentSpec: ...

class TemplateService:
    async def list(self, locale: str) -> list[TemplateSummary]: ...
    async def instantiate(self, template_id: str, name: str) -> Agent: ...
    async def export(self, agent_id: str) -> bytes: ...      # .poly 包
    async def import_(self, pkg: bytes) -> Agent: ...
```

### 关键流程
1. **创建**：写 `agents` + `agent_versions(v1, draft)` → 初始化 workspace（模板文件落盘）→ 发布领域事件 `agent.created`。
2. **发布**：校验 spec（schema + 引用存在性 + 权限）→ 写新版本 + `published_at` → 更新 `current_version_id`。
3. **运行时**：`resolve_spec(agent_id, version=thread.pinned_version)` → 构造 `AgentRuntimeConfig`。**会话锁定版本**，避免"用户改配置导致进行中的对话行为突变"。
4. **删除**：检查有无活跃 thread / 定时任务 / 团队引用 → 软删 → 异步清理 workspace 与索引。

### 实现要点
- **文件即配置**：workspace 里 `SOUL.md`、`AGENTS.md`、`skills/` 是权威；`spec_json` 只存"引用与参数"。两者一致性由 `AgentWorkspace` 负责（Octop 用 BackendWorkspace 抽象隔离后端，这点很好）。
- **模板 = 目录包**：`manifest.json`（i18n 名称/描述/欢迎语/快捷提示/示例任务/配色/图标）+ 提示词 md + `skills/` + `references/`。Octop 的 23 套模板是这个格式，**直接借鉴**。
- 版本 diff 用 JSON Patch，UI 可展示"改了什么"。

### 失败模式
发布校验失败 → 返回字段级错误；workspace 初始化失败 → 回滚事务并清理目录（Octop 的 `_abort_incomplete_create` 思路可借鉴）。

### 测试
spec schema 兼容性（v1 快照回归）；模板实例化后的文件树快照测试；版本发布/回滚的状态机测试。

### Octop 复用地图
| 主题 | 结论 |
|---|---|
| `experts/library/*/manifest.json` 格式 | **借鉴**（字段与 i18n 结构都成熟） |
| `AgentManager`（3963 行，含 CRUD/记忆维护/VACUUM/团队装配） | **别抄**；按本节拆成 AgentService / RuntimeSupervisor / MemoryMaintenance |
| `workspace/` + BackendWorkspace 抽象 | **借鉴**；保留"内容文件只经 workspace 访问"的硬规则 |
| MBTI 人格生成 | **暂缓**；用模板变量替代 |
| 专家共享布尔位 | **重写** 为版本化发布 + ACL |

## 4. conversations（会话、轮次、事件）

### 职责
线程生命周期、轮次排队与状态机、事件写入与回放、消息投影、审批、插话、运行轨迹。

### 领域模型
见架构 §4.3；补充：
```sql
threads(thread_id, tenant_id, agent_id, agent_version, origin, session_key,
        title, pinned, archived_at, last_active, active_turn_id, pinned_message_id)
messages(message_id, thread_id, turn_id, seq, role, content_json, status, speaker_agent_id)
thread_policies(thread_id, kind(hitl|model|...), value_json, expires_at)
```

`content_json` 是块数组（文本/图片/文件/工具结果/引用），与前端渲染契约一致。

### 对外接口
```python
class ConversationService:
    async def create_thread(self, agent_id: str, origin: str) -> Thread: ...
    async def submit(self, thread_id: str, input: UserInput, *,
                     delivery: Literal["auto","steer","follow_up"] = "auto") -> Turn: ...
    async def cancel(self, turn_id: str, *, scope: Literal["turn","turn_and_tools"]) -> None: ...
    async def resolve_approval(self, approval_id: str, decision: Decision) -> None: ...
    async def steer(self, turn_id: str, item: SteerItem) -> SteerAck: ...
    async def list_events(self, thread_id: str, after_seq: int, limit: int) -> list[Event]: ...
    async def history(self, thread_id: str, before: Cursor | None, limit: int) -> Page[Message]: ...
```

### 关键流程

**提交一轮**
```
submit()
 ├─ 校验 agent 可运行（spec 可解析、模型可用）
 ├─ 同 thread 活跃 turn？
 │    ├─ 是 + delivery=auto/steer → 入 steer_items（上限校验）
 │    └─ 是 + follow_up       → 创建 queued turn（seq+1）
 ├─ 否 → 创建 turn(queued) + message(user) + event(turn.queued)
 └─ enqueue(TurnJob{turn_id}) → 返回 turn_id
```

**执行**：worker 领取 → `runs.claim` → 发 `turn.started` → kernel 循环 → 每步写 `run_steps` + `events` → 终态 `turn.finished`。

**审批恢复**：
```
approval.requested → turn.status=awaiting_approval → 释放 lease
用户决策 → approvals.status=approved → enqueue(ResumeJob{approval_id})
worker → 校验决策与当前 step 匹配 → 执行工具 → 继续循环
```

**事件写入**：`EventStore.append(thread_id, events)` 在事务内分配连续 seq：
```sql
UPDATE threads SET last_seq = last_seq + :n WHERE thread_id = :t RETURNING last_seq;  -- 单语句原子
```
（SQLite 用 `BEGIN IMMEDIATE` + 同样语句。）

### 实现要点
- **seq 单调**：每 thread 一条序列，DB 分配，禁止应用侧 UUID 排序。
- **投影幂等**：`messages` 由 `message.started/delta/completed` 聚合；writer 记录 `last_applied_seq`，重放安全。
- **分页**：`before_seq` 游标，禁止 offset。
- **删除**：软删 thread → 异步清理附件引用（引用计数）→ 审计。
- **审批单可读化**：服务端生成 `title/summary/args_preview`（不是把原始 JSON 丢给用户），脱敏后返回。

### 失败模式
| 场景 | 处理 |
|---|---|
| turn 执行中进程崩溃 | lease 过期 → 另一 worker 恢复；UI 收到 `turn.resumed` |
| 用户关闭页面 | 不取消（除非显式 cancel）；事件继续落库，重连补发 |
| 审批人离开 | 超时 deny（可配）；`approval.expired` 事件 |
| 事件写失败 | 整个步骤失败并回滚，turn 标记 failed，不产生半截消息 |

### 测试
状态机迁移矩阵（每个状态 × 每个事件）；崩溃恢复（在 model/tool step 处 kill）；seq 并发分配（10 并发写同一 thread，断言连续无洞）；投影重放一致性。

### Octop 复用地图
| 主题 | 结论 |
|---|---|
| `api/routers/chat/ws.py` 帧设计（user_turn/subscribe/cancel/steer_*） | **借鉴** 语义；**重写** 为统一信封 + seq 回放 |
| `gateway/steer/` 队列 | **重写** 持久化 |
| `hitl/` 审批单与多端协调 | **借鉴** 展示结构；**重写** 存储与恢复 |
| `history/trajectory` 轨迹账本 | **借鉴**（事件类型与 UI 呈现） |
| 四套会话存储并存 | **别抄** |

## 4B. intake（工作入口，新增域）

> 完整概念与 DDL 见 `07-SuperAgent评审与修订.md` §4。本节只给工程视角的模块设计。

### 职责
把"外部世界发生的事"变成"被授权的工作"：接入来源、去重、判断、开单、派工、收回报告。**不执行任务**（执行在 Executor），**不做工具审批**（那是 capabilities 的策略）。

### 领域模型
`sources` `triggers` `event_threads` `trigger_threads` `policies` `evaluations` `tickets` `ticket_threads` `assignments` `reports` `attentions`（11 张，见 `02` §4.2）。

### 对外接口
```python
class IntakeService:
    async def ingest(self, source_id: str, raw: RawEvent) -> TriggerAck: ...
    async def evaluate(self, event_thread_id: str) -> Decision | None: ...
    async def open_ticket(self, decision: Decision) -> Ticket: ...
    async def assign(self, ticket_id: str, executor: ExecutorKind) -> Assignment: ...
    async def report(self, assignment_id: str, report: Report) -> None: ...
    async def answer(self, attention_id: str, answer: Answer) -> None: ...
    async def stop(self, ticket_id: str, actor: User) -> None: ...

class SourceAdapter(Protocol):
    kind: str
    async def poll(self, cursor: Cursor) -> list[RawEvent]: ...
    async def ack(self, event: RawEvent) -> None: ...
    async def reply(self, target: ChannelTarget, msg: Outbound) -> SendResult: ...
    def to_thread(self, event: RawEvent) -> str: ...      # thread_key
    def is_self(self, event: RawEvent) -> bool: ...
```

### 关键流程
```
ingest: 验签 → 归一化 → is_self 丢弃 → dedupe → 写 triggers
      → 解析 thread_key → trigger_threads(disposition=pending)
      → enqueue(EvalJob{event_thread_id})  （同 thread 串行）
eval:   取该 thread 的 Trigger 批次 + 最近 20 条消息 + 活动 Ticket + 当前 Policy
      → gate（确定性）→ assessment（便宜模型）
      → 写 evaluations + trigger_threads.disposition
      → accept → open_ticket（写 mandate）；stop → 更新 Ticket
assign: 选 Executor（ticket.executor_hint 或默认）
      → assignments(pending) → 领取 → running（lease）
      → executor.start(assignment, ticket, workdir)
report: 写 reports；progress → 更新卡片；waiting → 开 attention
      → ready → ticket.ended(completed) + channel.reply
      → blocked/failed → attention 或重派
```

### 实现要点
- **读取位点**：`sources.read_position_json` 每次 poll 后原子更新；启动时先 recover（拉历史窗口）再进入实时。
- **去重键**：优先平台原生 id（comment_id / delivery_id），其次 `hash(source, thread, actor, body, minute)`。
- **Gate 必须可单测**：纯函数，输入 `(policy, source, actor, trigger, rate)`，输出 `pass/filter(reason)`。
- **Assessment 失败**：`unavailable` + 重新入队（指数退避，上限 3 次），不阻塞 Thread。
- **Ticket 恢复**：人消息到达 → 若 Ticket ended 且未被 stop → 复用原 Mandate 续跑（不再 Eval）；否则交给 Eval。
- **成本**：每次 Assignment 汇总 tokens/cost 回写 `tickets.budget_json` 的消耗；超限阻断。
- **幂等**：`report` 用 `(assignment_id, seq)` 去重；重复报告返回同结果。

### 失败模式
| 场景 | 处理 |
|---|---|
| Source 宕机/限流 | 位点不前进 + 退避；UI 显示"来源异常" |
| webhook 重复投递 | dedupe 命中，直接 200 |
| Eval 模型超时 | `unavailable`，Trigger 留在队列 |
| Executor 崩溃 | lease 过期 → 重新 assign（attempt+1） |
| Attention 超时 | 按 Policy 保持/拒绝/升级 |
| Policy 变更影响在途 | 投递 `ticket.mandate_invalidated` 事件，不强制停 |

### 测试
- Gate 规则表驱动（每条 1 正 1 负）；
- 重放 1000 条 webhook，断言去重与位点；
- 崩溃恢复：assign 中 kill，重启后 attempt+1 且不重复回复；
- 端到端：GitHub 评论 → PR → 回到评论。

### Octop 复用地图
| 主题 | 结论 |
|---|---|
| `gateway/` 渠道适配与 `InboundMessage` | **借鉴** 归一化字段；**重写** 为 Source/Trigger |
| `cron/` 触发器 DSL | **借鉴** 作为 schedule Source |
| `bridge/` 的隧道与版本协商 | **暂缓** |
| Octop 无 Ticket/Assignment/Policy | **新建** |

## 5. kernel（Agent 内核）

### 职责
把"一次 turn 怎么跑"做成可测试的纯逻辑：模型调用、工具调用、提示词组装、上下文压缩、插话注入。**不认识数据库、HTTP、租户。**

### 接口
```python
class TurnEngine(Protocol):
    async def run(self, ctx: TurnContext) -> AsyncIterator[EngineEvent]: ...

@dataclass
class TurnContext:
    agent: AgentSpec
    messages: list[ChatMessage]
    tools: list[ToolSpec]
    model: ModelGateway
    executor: ToolExecutor
    approvals: ApprovalGate
    steer: SteerQueue
    budget: TokenBudget
    trace: TraceContext
    cancel: asyncio.Event
```

### 循环（展开版）
```
for step in range(max_steps):
    await budget.ensure()
    if steer.pending(): inject_at_boundary()
    completion = await model.stream(messages, tools)
    if completion.has_tool_calls:
        for call in completion.tool_calls:
            decision = await approvals.gate(call)      # allow/ask/deny
            if decision == ask:  yield ApprovalRequested; return
            if decision == deny: messages += tool_error("denied")
            else: messages += await executor.run(call)
        continue
    return                                     # 纯文本回答结束
raise MaxStepsExceeded
```

### 中间件管线（2026-11 定稿，对照 Octop 中间件链）

每个 step 按**固定 12 步管线**执行；每步是一个可独立单测的中间件，kernel 只做编排并**以事件形式产出 checkpoint 数据**（落盘归 `ConversationService`，见实现要点；`43 §3.1`）。顺序即语义，变更须走 ADR；中间件之间禁止互相 import。

```
 1. 请求组装    ModelRequest 构造（消息、工具表、采样参数）
 2. 缓存标记    稳定前缀断点标记（provider 相关；Anthropic cache_control 等）
 3. 上下文预算  预算表按 ModelCaps 分档；超限先 clearing 再压缩（13 §3）
 4. 记忆召回    命中注入当前输入尾部，不破坏前缀（13 §4.2）
 5. 知识提示    绑定 KB 时重写检索工具描述；无 KB 则移除该工具（本篇 §7）
 6. 策略闸门    policy.evaluate；懒 Ticket 升级判定（首个写/risk≥medium 请求
                → 创建 Ticket 回填 turn_id 再放行，ADR-012）；ask → 落 approvals 暂停
 7. 模型调用    ModelGateway.stream()（健康路由 + fallback，02 §5.1）
 8. 流式分发    delta → 事件总线；慢消费者合并（coalesced，29 §6）
 9. 工具执行    ToolRuntime.invoke()：执行期二次校验（spike S3 语义）、沙箱、审计
10. 结果规整    大输出（>2k token）卸载 artifact 只留摘要+引用；图片 sha256 落缓存
11. 用量计费    model / embedding / 评估三入口统一按 model_prices 计 cost_micros
12. step 落盘   checkpoint：已完成步骤 + 工具幂等键（崩溃恢复与防重依据）
```

**恢复语义**：`resume` 从最后一个完成的 step 之后继续；未完成的 step **重执行**，工具按幂等键去重；stop 传播 = 同步工具取消、异步工具 best-effort cancel + `tool.async_cancelled`（`32 §4/§6`）。

### 实现要点
- **纯函数式事件**：内核只 `yield` 事件，不写库；`ConversationService` 负责持久化。这样内核可以用内存假件做毫秒级单测。
- **上下文压缩**：当 `tokens > 0.75 * window` 时触发；保留 system + 最近 K 轮 + 摘要；摘要用便宜模型，产出 `compacted` 事件。
- **工具并发**：只读工具可并发（`asyncio.gather`），有副作用工具串行；并发上限 4。
- **取消**：`cancel` 事件 + `asyncio.Task.cancel`；模型流与工具都要响应 `CancelledError` 并清理子进程。
- **重试**：模型层重试（指数退避 + jitter），工具层不自动重试非幂等调用。

### 失败模式
模型 429 → 退避重试（最多 3 次，尊重 `Retry-After`）→ 仍失败则 fallback → 全失败返回 `MODEL_UNAVAILABLE`（可重试标记）。工具超时 → `TOOL_TIMEOUT`，结果以"错误观察"回给模型，让它换策略。

### 测试
用 `FakeModelGateway`（脚本化响应序列）覆盖：纯文本、单工具、多工具并发、工具失败、审批中断、超步数、取消。**内核测试不需要数据库与网络**，这是与 Octop 最大的可测性差异（Octop 的对话逻辑散在 `GlobalProcessor`，测一轮要起半个服务器）。

### Octop 复用地图
| 主题 | 结论 |
|---|---|
| `octop-harness` 的中间件/工具抽象 | **借鉴** 概念；不直接依赖（否则被库版本绑架） |
| `GlobalProcessor.iter_turn_chunks`（2109 行类里的 380 行） | **别抄**；拆成内核 + 服务 |
| `process/stream_project.py`（IM 投影） | **借鉴** 思路：同一事件流投影到不同渠道 |

```python
class ToolRegistry:

class PolicyEngine:
    async def evaluate(self, req: PolicyRequest) -> PolicyDecision: ...
```

### 策略求值顺序
```
deny 规则（安全优先） → tenant 强制策略 → agent 覆盖 → 默认（risk>=high → ask）
```

### 异步工具（全双工，2026-11 新增）

长任务（CI、浏览器、批处理）不应阻塞 turn：

```python
@dataclass(frozen=True)
class ToolSpec:
    ...
    execution: Literal["sync", "async"] = "sync"

# async 工具返回 handle，不返回结果
{"handle_id": "h_1", "status": "running", "poll_after_s": 5}
```

- `ToolExecutor.start()` 立即返回；结果通过 `tool.async_completed` 事件回到同一 turn。
- 每个 turn 最多 4 个并发 async 工具；结果回来时 turn 已结束 → 开 continuation turn（标注 `continuation_of`）。
- 长任务的进度写 `run_steps`，UI 用进度条（来自插件 renderer 或默认卡）。
- 取消：`cancel` 传播到 async 工具（best-effort），并写 `tool.async_cancelled`。

**策略求值顺序（不变）**

`when` 表达式用受限 DSL（不 eval Python）：
```yaml
- id: block-destructive-shell
  priority: 100
  when: { tool: "shell.exec", args.cmd_matches: "(rm -rf /|mkfs|dd if=)" }
  effect: deny
  reason: "destructive command"
- id: ask-external-write
  priority: 50
  when: { tool.scope: "net:write", agent.kind: "shared" }
  effect: ask
```

### 插件生命周期
```
install(zip/path) → 校验 manifest/api_version/permissions → 解压到 plugins/<id>/<version>
→ 记录签名与来源 → 默认 disabled → 启用时 import main.py 调 setup(ctx) 注册工具/技能/钩子
→ 禁用时卸载注册（保持进程不重启，工具表热更新）
```

### 实现要点
- **工具名唯一**：`<source>.<name>`，如 `builtin.http_get`、`plugin.weather.get_weather`、`mcp.github.create_issue`。避免 Octop 里插件工具与内置工具重名的处理逻辑。
- **输出规范化**：所有工具结果统一 `{content: [...], artifacts: [...], ui?: {...}, usage?: {...}}`；大文本截断 + 提示"完整内容见 artifact"。
- **UI 渲染器**：`ui.renderer` 指向插件注册的 renderer id；前端 `ToolRendererRegistry` 动态加载（Octop 的 `toolRenderers` 机制借鉴）。
- **MCP**：连接池 + 工具列表缓存（TTL 60s）+ 变更检测（hash 比对）+ 单工具超时 60s；连接失败降级为"该组工具不可用"，不阻塞整轮。

### 失败模式
插件 import 抛错 → 记录 `plugin_load_failed`，禁用该插件，不影响其他；MCP 服务不可达 → 工具标灰并给模型明确错误；策略求值异常 → **默认 deny**（fail-closed）。

### 测试
策略规则表驱动测试（每条规则至少 1 正 1 负）；插件加载/卸载/热更新；工具 schema 校验拒绝非法参数；MCP mock server 契约测试。

## 7. knowledge（知识与 RAG）

### 职责
文档入库、解析、切片、向量化、检索、引用、评测。

### 领域模型
```sql
knowledge_bases(kb_id, tenant_id, name, embedding_model, embedding_dim, embedding_version,
                chunk_config_json, chunker_version, visibility)
kb_documents(doc_id, kb_id, source, filename, mime, size, sha256, status, error, pages)
kb_chunks(chunk_id, doc_id, kb_id, idx, text, tokens, heading_path, page_from, page_to,
          char_start, char_end, embedding vector, tsv tsvector)
kb_jobs(job_id, doc_id, stage, status, attempts, error)
knowledge_acl(kb_id, subject_type, subject_id, role)
```

### 管线
```
upload → 病毒/类型/大小校验 → 存 blob → 建 job(doc, stage=parse)
parse   : pdf/docx/pptx/xlsx/md/html → 结构化文档（blocks + 页码 + 标题树）
normalize: 去页眉页脚/合并断行/表格转 markdown/代码块保护
chunk   : 按 heading 层级切；目标 400–800 tokens，overlap 10–15%；
          表格整块保留（可跨页合并）；超长段落再按句切
enrich  : 生成 chunk 摘要 + 关键词（可选，用便宜模型）
embed   : 批量 64，维度记录，失败重试 3 次
index   : dense(pgvector/sqlite-vec) + sparse(BM25/tsvector)
```

### 检索
```
query → 改写（可选，指代消解）→
  dense topK=40  +  sparse topK=40  → RRF 融合 → topK=20 →
  （可选）cross-encoder/LLM rerank → topK=8 → MMR 去冗余 →
  ACL 过滤（在 SQL 里先过滤再排序）→ 组装引用（doc/page/heading/span）
```
低置信（最高分 < 阈值）→ **abstain**："知识库中没有找到依据"，而不是硬编。

### 实现要点
- **ACL 过滤必须在检索 SQL 内**（`JOIN kb_acl`），不能检索后再过滤（会泄露存在性且浪费）。
- 每个 chunk 存 `heading_path` 与页码，引用可跳转。
- 换 embedding 模型 → 新列/新表 + 后台重建，不原地改维度。
- 入库幂等：`sha256` 相同则跳过（除非显式重建）。

### 就绪门禁与启动恢复（2026-11，借 Octop gate/jobs）

- **摄取并发上限**：每实例解析/embedding 并发 ≤2（解析内存重，Octop 用 `Semaphore(1)` 保护内存）；单文档解析内存超限标 `failed(RESOURCE)`，不拖垮进程。
- **就绪门禁**：创建 KB / 开启知识功能前校验——embedding 后端可达、模型与维度已知、凭证有效；不满足返回 `KB_NOT_READY`（含缺什么），不静默。启动时本地依赖（如 onnx 模型）缺失要大声告警。
- **启动恢复**：进程启动时 `resume_pending_jobs`——把卡在 `processing` 的文档重置为 `pending` 重新入队，不留给用户手动"重建"。
- **无 KB 隐藏检索工具**：`ToolRegistry.resolve()` 在 Agent 未绑定任何 KB 时，把 `kb.search` 从模型可见工具表中**整体移除**（而非提示"不要调用"）；绑定时每轮用 KB 名/描述重写该工具描述。

### 失败模式
解析失败 → 文档 `status=failed` + 可读原因 + 允许重试；embedding 限流 → 退避重试；部分成功 → 记录成功页数，UI 显示"已索引 12/15 页"；**检索上游不可用 → 结构化错误 + 事件，不返回空串**。

### 测试
黄金集（50 问）测 recall@5 / answer faithfulness；切片快照测试（同一文档切片稳定）；ACL 负向测试（B 用户检索不到 A 的 KB）。

### Octop 复用地图
| 主题 | 结论 |
|---|---|
| `knowledge/parse.py` 多格式解析 | **借鉴**（可直接用其依赖组合：pypdf/python-docx/python-pptx/openpyxl） |
| `chunk_text(800,120)` | **别抄**；结构感知切片 |
| `knowledge/index.py` 每 KB SQLite 向量 | **重写**（sqlite-vec / pgvector） |
| `citations.py` | **借鉴** 引用结构 |
| 无评测 | **新增** |

## 8. memory（记忆）

> 详细的写/读路径、冲突与 TTL、防投毒、Build vs Adopt 评估见 `13-记忆与上下文设计.md`。本节只保留模块边界。

### 职责
把"值得记住的事"从对话中抽取、去重、冲突消解、分层存储，并在合适的时候以预算内方式注入。

### 领域模型
```sql
memory_atoms(atom_id, tenant_id, agent_id, kind(fact|preference|episode|profile|skill), text,
             embedding, confidence, status(candidate|active|retired|pending_review),
             valid_from, valid_to, supersedes, source, evidence_json, payload_json)
memory_events(event_id, atom_id, kind(raw|promoted|merged|superseded|deleted), payload_json, created_at)
```
> 逻辑三层 `raw → candidate → atom`；物理上 raw 复用 `memory_events`，candidate 复用 `memory_atoms.status='candidate'`。
> `episode` / `profile` 用 `kind` 区分，不单建表；图谱 v1.5。

### 管线
```
turn 完成（异步，不阻塞回复）
  → raw（只收 user/assistant，≥12 字符；工具/思考不进）
  → 抽取候选（LLM，结构化 JSON）
  → candidates（status='candidate'，带 evidence/confidence/source）
  → 规则优先晋升：value → evidence → duplicate → conflict；规则不决才升级 LLM
  → 近邻去重（embedding cosine > 0.92）→ 合并/新增/冲突
  → 冲突：保留双方 + sources + valid_from/to，标记 requires_review（不静默覆盖）
  → 写入 atoms + memory_events
夜间/空闲 → 情景摘要（kind=episode） + 画像更新（kind=profile，需确认）
```

### 注入
打分 = `0.5*相关性（向量/BM25）+ 0.2*新近度 + 0.2*重要度 + 0.1*使用频次`，取预算内 topN（≤1500 token、p95 ≤100ms），每条带 `atom_id` 以便引用与"忘记这条"。

### 实现要点
- **可解释**：每条记忆可追溯来源 turn / trigger / tool_call。
- **可删除**：单条删除 + 按来源删除 + 全量导出；删除写审计。
- **不污染**：工具输出、网页内容默认**不写入**长期记忆。
- **provider**：默认 `PgMemoryProvider`；`OctopMemoryProvider` / `Mem0Provider` 只做适配器，见 `13 §4.9` 与 `ADR-009`。

### Octop 复用地图
| 主题 | 结论 |
|---|---|
| `memory/` 分层（raw/candidate/atom/episode/entity） | **借鉴** 分层与规则优先晋升；首版不做 entity/page |
| `manual-review` 冲突处理流程 | **借鉴** 交互；实现自研 |
| `octop-memory` 库 | **可选适配器**（ADR-009）；license/版本核对后再接，不作默认 |
| `memory_storage.py` 维护/恢复 | **暂缓** |

## 9. orchestration（团队、委派、工作流、定时）

### 职责
多 Agent 协作、任务分解与派发、DAG 执行、定时与事件触发。

### 领域模型
`teams / team_members / delegations / workflows / workflow_runs / schedules`（delegations DDL 见架构 §6.2）。

### 团队执行
```
用户 → 协调者 turn
  → 协调者输出 plan（结构化 JSON：任务、指派、依赖）
  → 对每个可执行任务 enqueue(delegation)
  → 成员在自己的 child_thread 执行，事件带 speaker 推入房间
  → 全部完成/失败 → 回叫协调者（compose_followup）
  → 协调者总结 → turn 结束
```

### 工作流（新增）
```yaml
id: weekly-report
trigger: { cron: "0 9 * * 1", timezone: Asia/Shanghai }
nodes:
  - id: collect
    type: tool
    tool: kb.search
    args: { kb_id: "kb_ops", query: "本周进展" }
  - id: draft
    type: llm
    model: default
    prompt: "基于 {{collect.output}} 写周报"
    depends_on: [collect]
  - id: approve
    type: approval
    depends_on: [draft]
  - id: send
    type: channel
    channel: feishu
    depends_on: [approve]
```

执行器：拓扑排序 + 每节点持久化状态 + 失败重试策略（节点级）+ 补偿（可选 `on_failure` 分支）。

### 实现要点
- 派工幂等：`UNIQUE(tenant_id, dedupe_key)`；`dedupe_key = hash(parent_run_id + member_id + task_id)`。
- 成员忙：入队而非拒绝（Octop 是直接失败）。
- 停止语义：停协调者 ≠ 停成员（保留 Octop 的决策，合理）；但提供"停止整个房间"。
- 租约：`running` delegation 必须有 `lease_until/last_heartbeat_at`；超时由 Watchdog 重派，`attempts/max_attempts/next_retry_at` 控制退避。

## 10. channels（IM 渠道）

### 职责
平台接入、消息归一化、会话映射、媒体、幂等、限流。

### 接口
```python
class ChannelAdapter(Protocol):
    kind: str
    async def start(self, cfg: ChannelConfig, sink: InboundSink) -> None: ...
    async def send(self, target: ChannelTarget, msg: OutboundMessage) -> SendResult: ...
    async def stop(self) -> None: ...
    def capabilities(self) -> ChannelCaps: ...   # 支持流式/卡片/文件/引用?
```

`InboundMessage`：`{channel_kind, platform_msg_id, chat_id, chat_type(dm|group), sender, text, media[], mentions[], raw}`。

### 关键流程
```
平台回调 → 验签 → 幂等检查(platform_msg_id) → 归一化 → 会话映射(session_key)
→ 若是 slash 命令 → 本地执行 → 回复
→ 否则 → ConversationService.submit → 订阅事件 → 按 channel 能力投影成消息段
```

### 实现要点
- **幂等表** `channel_messages(channel_id, platform_msg_id UNIQUE)`，重复回调直接 ack。
- **流式**：平台支持则流式编辑消息；不支持则"发送占位 → 完成后编辑"或"整段发送"。
- **群聊激活**：@机器人 / 关键词 / 白名单，规则可配。
- **媒体**：下载到本地 blob（平台 URL 会过期），再以 artifact 引用给模型。

| 主题 | 结论 |
|---|---|
| `octop-gateway` 归一化 | **可复用**（独立库，接口清晰） |
| `stream_project.py` 投影 | **借鉴** |
| `response_mode.py` | **借鉴** |

## 11. control（浏览器/终端/桌面）

### 职责
受控的"动手能力"，含会话管理、输入注入、画面回传、录制回放、审计。

### 接口
```python
class BrowserSession(Protocol):

    async def act(self, action: BrowserAction) -> ActionResult: ...
    async def screenshot(self) -> bytes: ...

class TerminalSession(Protocol):
```

## 13. API 层约定

- 版本前缀 `/api/v1`；资源复数；`PATCH` 局部更新；删 `DELETE` 返回 204。
- 错误信封：`{"error": {"code","message","details","trace_id"}}`（借鉴 Octop，补 trace_id）。
- 列表统一：`{items: [...], next_cursor: "..."}`。
- 幂等：写操作支持 `Idempotency-Key` 头（创建会话/提交消息/审批）。
- 流式：WS 主通道；SSE 仅用于"一次性续传"（如审批恢复）与事件回放。
- OpenAPI 导出 → `web/src/api/generated/`（openapi-typescript + 手写薄封装）。

## 14. 模块实施顺序（依赖驱动）

```
M0: platform → identity → api 骨架
M1: agents → conversations → kernel → 单机聊天闭环
M2: capabilities（内置工具+策略）→ knowledge → memory
M3a: intake（Source/Trigger/Eval/Ticket/Attention）→ 任务中心 UI
M3b: channels（作为 Source）→ schedules → 通知 → 预算
M4: 多租户/配额/审计 → 团队（Executor 内模式）→ 工作流 → 观测与评测
M5: control（浏览器/终端）→ 外部 Executor → 插件生态 → 联邦
```

每个模块的"可并行度"与"外部依赖"：

| 模块 | 可并行 | 依赖 | 风险 |
|---|---|---|---|
| platform | 否（地基） | 无 | 迁移器设计错→返工 |
| identity | 是 | platform | 权限模型变更成本高 |
| kernel | 是 | 无（纯逻辑） | 过度抽象 |
| conversations | 否 | platform, agents, kernel | 状态机遗漏 |
| capabilities | 是 | kernel | 策略表达力 |
| knowledge | 是 | platform, capabilities | 检索质量 |
| memory | 是 | kernel, conversations | 噪声写入 |
| orchestration | 否 | conversations, agents | 并发与恢复 |
| channels | 是 | conversations | 平台差异 |
| control | 是 | platform | 安全 |

# PolyOpus 界面与交互设计

> **交互参考**：控件级状态/权限/API 以 `30` 为准；v1.1 页面（团队/渠道/控制面/云主机）以 `30 §14A` 为准。
>
> 目标：给出**完整可实现的界面规格**——信息架构、路由、页面结构、组件、状态机、交互细节、快捷键、响应式与可访问性。
> 基准：Octop 的 Web 控制台（`dashboard/src`，约 19.7 万行）已验证了大量交互；本文保留其精华、修掉其结构性问题，并补齐它缺的部分（命令面板、URL 视图状态、通知中心、统一壳）。
>
> Octop 外壳与 16 个页面的逐按钮/配置对照见 [`22-Octop交互逐按钮分析.md`](22-Octop交互逐按钮分析.md)；专家抽屉与连接器/知识库的逐字段规格见 [`23-专家编辑抽屉规格.md`](23-专家编辑抽屉规格.md)、[`24-连接器与知识库交互规格.md`](24-连接器与知识库交互规格.md)；可点击原型见 [`prototype/index.html`](../prototype/index.html)。

## 1. 设计原则

| # | 原则 | 具体含义 | 反例（Octop 的问题） |
|---|---|---|---|
| 1 | **对话为中心** | 打开即对话；其他页面都是"配置对话"或"观察对话" | 导航 19 个入口平铺，对话只是其一 |
| 2 | **一层壳** | 每个页面只有一个页面头（标题+操作+Tab） | Chat 在移动端有全局 Header + 自带 toolbar 两层 |
| 3 | **状态可见** | 流式/排队/审批/重连/压缩都有明确视觉 | 重连静默、自动批准静默 |
| 4 | **可撤回** | 停止、撤回插话、撤销自动批准、删除进回收站 | 自动批准无撤回 |
| 5 | **URL 即视图** | 面板、Tab、筛选、模型都进 URL | 大量视图状态只在 localStorage |
| 6 | **键盘优先** | ⌘K 命令面板 + 全站快捷键 | 仅输入框内有快捷键 |
| 7 | **渐进披露** | 首屏只给常用；高级项收进"更多" | 一次给 8 个 chip，挤压输入区 |
| 8 | **一致的异步态** | loading/empty/error/forbidden 四态统一组件 | 5 套加载态并存 |

## 2. 信息架构

### 2.1 全局布局（桌面 ≥1280）

```
┌────┬──────────────────┬───────────────────────────────────────────┬──────────────────┐
│ 导 │  上下文面板       │  主内容                                    │  Dock（可选）     │
│ 航 │  (280–320px)     │                                           │  (400–560px)     │
│ 64 │                  │  ┌─────────────────────────────────────┐  │                  │
│ px │  会话列表         │  │ 页面头：标题 / 面包屑 / 操作 / Tab    │  │  文件            │
│    │  专家列表         │  ├─────────────────────────────────────┤  │  运行轨迹        │
│    │  知识库树         │  │                                     │  │  浏览器          │
│    │  任务列表         │  │  内容（滚动区）                       │  │  引用            │
│    │  …               │  │                                     │  │  工具 UI         │
│    │                  │  ├─────────────────────────────────────┤  │                  │
│    │                  │  │  底部操作区（composer / 主按钮）       │  │                  │
│    │                  │  └─────────────────────────────────────┘  │                  │
└────┴──────────────────┴───────────────────────────────────────────┴──────────────────┘
```

- 导航 rail 可展开为 220px（图标+文字），状态持久化。
- 上下文面板随路由变化：`/chat` 是会话列表，`/agents` 是专家列表，`/knowledge` 是知识库树……
- Dock 是可选的第三栏，只在对话/工作台出现；宽度可拖拽，URL 记录 `?dock=files&panel=right`。
- 三栏都可独立折叠；折叠后留 4px 边缘热区（hover 出现把手）。

### 2.2 主导航（8 + 3）

| 序 | 图标 | 名称 | 路由 | 说明 | 权限点 |
|---|---|---|---|---|---|
| 1 | 💬 | 对话 | `/chat` | 人主动发起的会话，按专家分组 | `chat:use` |
| 2 | 📥 | **任务** | `/tasks` | **注意力收件箱 / 进行中 / 已排队 / 已完成**；Tab：来源、定时、工作流 | `task:use` |
| 3 | 🤖 | 专家 | `/agents` | 我的专家 / 团队 / 模板库 | `agent:read` |
| 4 | 📚 | 知识 | `/knowledge` | 知识库与文档 | `kb:read` |
| 5 | 🔌 | 连接 | `/connections` | 连接器 / MCP / 渠道 / **来源** | `connection:read` |
| 6 | 🧩 | 扩展 | `/extensions` | 技能 / 插件 / 技能包 | `extension:read` |
| 7 | 🖥 | 工作台 | `/workbench` | 浏览器 / 终端（全屏，保活） | `device:use` |
| 8 | 📊 | 用量 | `/usage` | token / 成本 / 配额 / 每工单成本 | `usage:read` |
| — | ⚙️ | 设置 | `/settings` | 个人设置 | 登录即可 |
| — | 🛡 | 管理 | `/admin` | 成员/模型/存储/安全/审计/备份 | `admin:*` |

底部区：设置、管理、头像（账号菜单：语言/主题、API Key、退出）。

> 与 Octop 的差异：Octop 19 个入口分 4 组；PolyOpus 用 **8 个对象类型**做一级。`任务` 是新增的一级入口——它是"Agent 在替你干活"的主界面，与"你自己聊天"的 `对话` 并列。原 `自动化` 并入 `任务` 的 Tab。
>
> **已定稿（2026-11）**：采用本节 **8 + 3**；原型已从 19 项切回 8 项，原 19 项中的设置/控制/管理子页通过「连接 / 扩展 / 工作台 / 管理」四个 Hub 进入。差距记录见 [`25-原型交互差距审计.md`](25-原型交互差距审计.md)。
>
> **单层导航（2026-11）**：全局只保留一级侧栏。设置、管理、连接、扩展、知识库、工作台、用量不再叠第二层侧栏，统一改为页内 Tab（`外观/通知/快捷键/账号`、`概览/用户/模型/...`、`连接器/通道/云端协同/ACP` 等）；只有对话会话列表、任务筛选这类"上下文面板"保留第二栏。
>
> **封版设计（2026-11）**：需求追踪、API/错误码、按钮状态、数据模型、模块接口分别见 [`28`](28-需求追踪矩阵.md)、[`29`](29-API与错误码总表.md)、[`30`](30-按钮与页面状态总表.md)、[`31`](31-全量数据模型与DDL.md)、[`32`](32-模块接口与状态机.md)。

## 3. 全局框架

### 3.1 设计令牌

```css
/* 颜色（语义化，不直接用色值） */
--bg-canvas / --bg-surface / --bg-elevated / --bg-hover / --bg-active
--fg-primary / --fg-secondary / --fg-muted / --fg-inverse
--border-subtle / --border-default / --border-strong
--accent / --accent-hover / --accent-fg
--success / --warning / --danger / --info   /* 各带 -bg 变体 */
--speaker-1 … --speaker-6                    /* 团队多说话人 */

/* 间距 4 的倍数 */
--space-1:4 --space-2:8 --space-3:12 --space-4:16 --space-5:20 --space-6:24 --space-8:32

/* 圆角/阴影/动效 */
--radius-sm:6 --radius-md:10 --radius-lg:14 --radius-full:999
--shadow-1 / --shadow-2 / --shadow-pop
--ease-out:cubic-bezier(.2,.8,.2,1)  --dur-fast:120ms --dur-base:200ms
```

- 主题：`light | dark | system`；强调色可选 6 种（不改语义色）。
- 字体：UI 用系统无衬线；代码用等宽（`ui-monospace`）；中文回退 `PingFang SC, Microsoft YaHei`。
- 字号：12/13/14/16/20/24/32（1.25 比例）；行高 1.5。
- 所有颜色必须走令牌，禁止页面内硬编码（Octop 的内联 style 是反面教材）。

### 3.2 页面壳（`PageShell`）

所有非全屏页统一结构：

```
┌─────────────────────────────────────────────────────────┐
│ 面包屑（可选）                    [次要操作] [主操作]     │  ← 48px
│ 标题 + 描述（可选）                                       │
├─────────────────────────────────────────────────────────┤
│ Tab（可选，URL 驱动）                                     │  ← 40px
├─────────────────────────────────────────────────────────┤
│                                                         │
│ 内容区（唯一滚动容器）                                    │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

- 全屏页（Chat / Workbench / Desktop）不使用 PageShell，自绘头部，但**必须**保留"返回/折叠"入口。
- 移动端：Tab 变成横向可滚动段，标题行压缩到 44px。

### 3.3 命令面板（⌘K / Ctrl+K）

统一入口，分组结果：

```
┌──────────────────────────────────────────────┐
│ 🔍 搜索或输入命令…                            │
├──────────────────────────────────────────────┤
│ 跳转   对话 › 最近的 5 个会话                  │
│        专家 › …                              │
│ 操作   新建对话 / 新建专家 / 新建知识库        │
│ 设置   外观 / 快捷键 / API Key                │
│ 帮助   文档 / 快捷键表 / 诊断                 │
└──────────────────────────────────────────────┘
```

- 模糊匹配 + 最近使用加权；↑↓ 选择，Enter 执行，Esc 关闭。
- 支持 `>` 前缀只搜命令，`@` 只搜专家，`#` 只搜会话。

### 3.4 全局快捷键

| 快捷键 | 动作 | 作用域 |
|---|---|---|
| `⌘K` / `Ctrl+K` | 命令面板 | 全局 |
| `⌘N` | 新建对话 | 全局 |
| `⌘⇧N` | 新建专家 | 全局 |
| `⌘/` | 快捷键帮助 | 全局 |

### 4.1 布局

```
┌──────────────┬──────────────────────────────────────────────┬─────────────────┐
│ 会话列表      │  ┌────────────────────────────────────────┐  │  Dock           │
│              │  │ [头像] 专家名 · 模型chip · 模式chip  ⋯  │  │ ┌─────────────┐ │
│ 🔍 搜索       │  ├────────────────────────────────────────┤  │ │文件│轨迹│浏览器│ │
│ ＋ 新对话     │  │                                        │  │ ├─────────────┤ │
│              │  │  消息流（虚拟滚动）                     │  │ │             │ │

│              │  │                                        │  │ │             │ │
│              │  ├────────────────────────────────────────┤  │ │             │ │
│              │  │ [队列: 2 条消息 ↑ ⌫]                   │  │ │             │ │
│              │  │ ┌────────────────────────────────────┐ │  │ │             │ │
│              │  │ │ 输入框…                            │ │  │ │             │ │
│              │  │ │ [Ask|Plan|Act] [模型] [知识] [工具]│ │  │ │             │ │
│              │  │ │                        [🎤] [发送/停止]│ │  │ │             │ │
│              │  │ └────────────────────────────────────┘ │  │ │             │ │
│              │  └────────────────────────────────────────┘  │ │             │ │
└──────────────┴──────────────────────────────────────────────┴─────────────────┘
```

### 4.2 会话列表（左栏）

| 元素 | 行为 |
|---|---|
| 搜索 | 本地即时过滤标题；回车走服务端全文搜索 |
| 新建 | `⌘N`；如果当前有草稿，先确认 |
| 分组 | 置顶 → 今天 → 昨天 → 本周 → 更早；按 `last_active` |
| 项 | 标题、专家头像（团队带徽章）、未读点、时间、状态图标（运行中=转圈，待审批=⚠） |
| 悬停操作 | 重命名 / 置顶 / 分叉 / 归档 / 删除 |
| 右键菜单 | 同上 + 复制链接 |
| 删除 | 进回收站（30 天），toast 可撤销 |
| 拖拽 | 拖到"置顶"区即置顶 |
| 空态 | "还没有对话" + 3 个示例任务卡（来自专家 manifest 的 `task_examples`） |

### 4.3 消息区

**分组规则**：同一轮内的 user → assistant 为一段；assistant 的"过程块"（思考、工具、计划）折叠在正文上方，形成一张"回合卡"。

**回合卡结构**

```
┌──────────────────────────────────────────────────────────┐
│ [头像] 专家名 · 2 分 13 秒 · 4.2k tokens · ¥0.03     ⋯   │
│                                                          │
│  ▸ 过程（3 步，可展开）                                    │
│    ✓ 读取 src/app.py            0.3s                     │
│    ✓ 知识库检索 "部署流程"       0.8s  [3 条引用]          │
│    ✗ 运行测试                  失败   [重试]              │
│                                                          │
│  正文（Markdown，支持代码/表格/公式/Mermaid）              │
│  …                                                       │
│                                                          │
│  [复制] [重新生成] [继续] [引用]                          │
└──────────────────────────────────────────────────────────┘
```

- 流式时：正文末尾显示闪烁光标；上方显示"正在思考 · 12s"；工具项显示 spinner。
- 长回答：超过 8 行折叠"展开全部"。
- 代码块：行号、语言标签、复制、下载、在新面板打开。
- 引用：正文中的 `[1]` 可点击，滚动到引用条；引用条点击打开 Dock 的"引用"页签，定位到原文片段。
- 多说话人（团队）：按 `speaker` 换头像、名字与左侧色条（`--speaker-N`）。

**滚动行为**：`follow`（默认，自动贴底）与 `free`（用户上滚后暂停跟随）两态；出现"↓ 新消息"悬浮按钮；发送时强制 follow；加载历史时保持锚点不跳动。

### 4.4 Composer（输入区）

| 区域 | 内容 |
|---|---|
| 附件条 | 缩略图 + 文件名 + 进度 + 移除；支持粘贴/拖拽/文件夹 |
| 输入 | 多行自适应（1–10 行）；`/` 命令菜单；`@` 文件/专家/知识库菜单；`#` 引用当前会话消息 |
| 操作行左 | 模式（Ask/Plan/Act）、模型、知识库、工具开关、语音 |
| 操作行右 | 字数/预估 token、发送 / 停止 |
| 提示 | 模式说明一行（如 "Plan：先出计划，确认后执行"） |

**四种运行态**

| 状态 | 输入框 | 主按钮 | 辅助 |
|---|---|---|---|
| 空闲 | 可编辑 | 发送（↑） | — |
| 生成中 | 可编辑（Enter 入队） | 停止（■） | "插话"按钮（↑ Steer） |
| 待审批 | 只读 + 提示"请先处理审批" | 禁用 | 审批卡高亮 |
| 待回答 | 可编辑 | 发送（作为回答） | "这是对提问的回复"提示 |

**模式（Ask / Plan / Act）**

| 模式 | 行为 | 适用 |
|---|---|---|
| Ask | 只读：不执行写操作与外部副作用工具 | 咨询、查资料 |
| Plan | 先生成计划（结构化步骤）→ 用户确认 → 切 Act 执行 | 多步任务 |
| Act | 全能力，高危工具走审批 | 日常 |

Plan 模式产出 `PlanReadyCard`：步骤列表 + "执行计划" / "修改" / "取消"。执行时步骤状态实时更新（`plan.updated` 事件）。

### 4.4.1 任务卡（懒 Ticket）

**触发**（任一）：写工具 / `risk>=medium` / 需要审批 / 设置预算 / 异步或长任务 / IM、cron、webhook、团队入口。
只读问答不出现任务卡。

```
┌──────────────────────────────────────────────────────────┐
│ ⚑ 这一步需要创建任务                                      │
│ 原因：调用 write_file（写入工作区）                        │
│ scope：fs:workspace  ·  预算：50k tokens / ¥0.20           │
│ 执行器：内置 · 预计 1–3 分钟                               │
│ [开始任务]  [取消]  [为什么需要任务？]                     │
└──────────────────────────────────────────────────────────┘
```

**状态**

| 状态 | 展示 | 主按钮 | 次按钮 |
|---|---|---|---|
| `suggested` | 原因 + scope + 预算 | 开始任务 | 取消 |
| `creating` | 骨架 + “正在创建…” | 禁用 | — |
| `active` | `#tk_…` + 进度 + 预算条 | 查看任务 | 停止 |
| `waiting_approval` | “等待你批准：write_file” | 批准 | 拒绝 / 本会话允许 |
| `budget_warning` | “预算已用 80%” | 追加预算 | 停止 |
| `failed` | 错误码 + 一句原因 | 重试 | 查看轨迹 |
| `completed` | 结论 + 产物数 | 查看报告 | — |
| `cancelled` | “已取消，未执行工具” | 重新发起 | — |

**文案规则**

- 第一行说“要做什么”，第二行说“为什么需要你确认”，不出现 Mandate/Assignment 等术语。
- 取消必须明确“不会执行任何工具”。
- 审批/预算/失败都在同一张卡更新，不跳页；详情页只做补充。

### 4.5 审批交互（HITL）

```
┌────────────────────────────────────────────────────────────┐
│ ⚠ 需要你的确认                                      ⏱ 28:14 │
│                                                            │
│ 工具：shell.exec                                            │
│ 命令：rm -rf ./dist && npm run build                        │
│ 影响：删除目录并重新构建（工作区内）                          │
│                                                            │
│ [查看完整参数 ▾]                                            │
│                                                            │
│ [拒绝]  [仅本次允许]  [本会话允许此工具 ▾]  [全部允许]        │
└────────────────────────────────────────────────────────────┘
```

- **必须显式**：不做"策略命中就静默自动批准"；自动批准也要显示一条 `自动批准（会话策略）` 的灰色卡片，可点"撤销并改为询问"。
- 倒计时：超时前 1 分钟变黄；超时后卡片变灰显示"已超时拒绝"，并提供"仍要执行"。
- 多动作审批：一张卡内列出 N 个动作，可逐项选择。
- 决策后：卡片收起为一行结果（批准/拒绝 + 操作者 + 时间），可展开。
- 多端：Web 批准后，IM 侧同步编辑原消息为"已批准"。

### 4.6 插话（Steer）与消息队列

- 生成中按 Enter → 进入**队列**（不是插话），显示在输入框上方："2 条待发送"。
- 队列 chip：`[消息预览 ×] [↑ 立即插话]`；"立即插话"把该项转为 steer，在安全边界注入。
- steer 已入队：显示"已插话，将在当前步骤后生效"；可撤回（未消费前）。
- 服务端权威：本地乐观行显示 `pending`，收到 `steer.ack` 后落定；被拒显示原因（payload 过大/正在审批）。
- 生成结束后：队列自动依次发送（可在设置关闭）。

### 4.7 上下文与用量

- Composer 上方常驻一行：`上下文 62% · 12.4k/20k`（点击展开构成）。
- 展开面板：系统提示 / 工具定义 / 技能 / 记忆 / 知识 / 历史 六段堆叠条 + 每段 token 与占比。
- 超过 75% 出现提示："接近上限，将自动压缩历史"；压缩后显示"已压缩 18k→9k"。
- 回合卡底部：耗时 / 输入 / 缓存命中 / 输出 / 成本。

### 4.8 空态与欢迎页

- 无会话：专家头像 + 欢迎语 + 4 个快捷提示卡（来自 manifest `quick_prompts`）+ "从模板创建专家"。
- 模型未配置：明确引导到 `/admin/models`，并提供"使用内置演示模型"（如果可用）。
- 专家未运行：显示状态与"启动"按钮。

### 4.9 Dock（右栏）

| Tab | 内容 | 触发 |
|---|---|---|
| 文件 | 工作区文件树 + 预览（图片/PDF/Office/代码/音视频） | 点击引用、工具产物 |
| 轨迹 | 时间轴（工具/模型/耗时/token）+ 过滤 + 导出 | `⌘⇧T` |
| 浏览器 | 实时画面 + 地址栏 + 接管 | 工具打开网页 |
| 引用 | 知识库命中片段 + 文档定位 | 点击 `[1]` |
| 工具 UI | 插件渲染的卡片 | 插件工具返回 |
| 终端 | 会话终端 | 工具执行 |

- 一个 callId 一个 Tab；最多 8 个，超出 LRU。
- 面板宽度可拖拽，双击把手复位；`⌘J` 折叠。
- 移动端：变为底部 Sheet，可上拉全屏。

### 4.10 流式渲染约定（前端实现）

| 事件 | UI 反应 | 批处理 |
|---|---|---|
| `message.delta` | 追加文本 | 每 50ms 或 64 token 合并一帧 |
| `reasoning.delta` | 思考折叠区追加 | 同上，默认折叠 |
| `tool.started` | 工具卡出现（spinner） | 立即 |
| `tool.delta` | 工具卡进度 | 100ms |
| `tool.completed` | 卡片完成，渲染结果/媒体/UI | 立即 |
| `approval.requested` | 插入审批卡，锁定输入 | 立即 |
| `plan.updated` | 更新计划卡 | 立即 |
| `context.updated` | 更新环 | 1s |
| `turn.finished` | 封口、显示耗时/用量 | 立即 |

**性能约束**：单条消息流式时，只重渲染"当前回合"组件；消息列表按回合 memo；虚拟列表阈值 30 条；首屏渲染预算 ≤ 300ms。

### 4.11 断线与恢复

- 连接中：顶部细条 "正在连接…"（可点开详情）。
- 断线：细条变黄 "连接已断开，正在重试（3/10）"，输入仍可写（发送进本地队列）。
- 恢复：按 `last_seq` 拉事件补齐，消息不重复不丢；显示"已恢复"toast。
- 服务端 turn 仍在跑：`turn_status: active` → 直接订阅，不重发。
- 服务端已结束：拉历史补齐，显示"本轮已结束"。

## 5. 页面规格

> 每页给出：目标 / 结构 / 关键交互 / 四态。省略通用样式。

### 5.1 登录 `/login`

- 结构：左品牌区（价值主张 + 3 张截图轮播），右表单卡（320px）。
- 交互：用户名密码 → 登录；"使用 Passkey"；SSO 按钮（按后端启用的 provider 动态渲染）；忘记密码（若启用邮件）。
- 细节：登录失败计数提示（剩余次数），锁定倒计时；验证码仅在失败 3 次后出现（渐进）。
- 态：加载骨架、错误内联、SSO 跳转中遮罩。

### 5.2 首次向导 `/setup`

5 步，左侧步骤条 + 右侧表单：

1. **管理员**：用户名/密码（强度条）/显示名。
2. **数据库**：SQLite（默认，显示路径）或 PostgreSQL（表单 + "测试连接"）。
3. **模型**：预设供应商卡（OpenAI/Anthropic/DeepSeek/通义/Ollama…）→ 填 Key → "测试"（真实 1-token 调用）→ 选默认模型。
4. **偏好**：语言、时区、主题、是否匿名统计。
5. **完成**：摘要 + "进入控制台"。

- 可"跳过并稍后配置"（`setup` 完成但 `model_configured=false`，进入后引导）。
- 幂等：刷新不丢进度（服务端存 wizard session）。
- 安全：向导 token 短 TTL；完成后中间件立即锁定 `/setup`。

### 5.3 专家列表 `/agents`

- Tab：**我的**（卡片/表格切换）/ **团队** / **模板库**。
- 卡片：头像、名称、描述、模型 chip、状态点、未读、⋯ 菜单（聊天/编辑/复制/分享/删除）。
- 工具栏：搜索、筛选（状态/模型/标签）、排序（最近/名称/创建）、"新建专家"。
- 新建：三步入导（选模板或空白 → 名称/头像/模型 → 能力勾选）。
- 模板库：分类（办公/研发/运营/生活…）+ 搜索 + 预览抽屉（提示词摘要、快捷提示、所需工具）+ "使用此模板"。
- 态：骨架卡、空态（引导创建/浏览模板）、错误重试。

### 5.4 专家详情 `/agents/:id`

Tab（URL 驱动）：

| Tab | 内容 |
|---|---|
| 概览 | 状态、模型、最近会话、用量、快捷入口 |
| 提示词 | SOUL/AGENTS 文件编辑器（Markdown + 变量提示）、版本差异 |
| 能力 | 工具开关（分组 + 搜索 + 风险标记）、技能、插件、MCP、子智能体 |
| 知识 | 绑定知识库、检索参数（topK/阈值）、"测试检索" |
| 记忆 | 长期记忆列表、画像、导入导出、清理 |
| 渠道 | 绑定 IM（飞书/企微/钉钉/Webhook），状态与测试 |
| 定时 | 该专家的定时任务列表 |
| 版本 | 版本列表、diff、发布、回滚 |

- 顶部常驻：头像/名称、"发布"（有未发布改动时高亮）、"开始聊天"。
- 编辑采用"草稿"语义：改动即时保存到草稿，需显式"发布"才影响新会话（进行中会话锁旧版本）。

### 5.5 知识库 `/knowledge`

- 左：知识库列表（搜索、新建、共享标记）。
- 右：文档表（文件名、类型、大小、状态、切片数、更新时间、操作）。
- 上传：拖拽区 + 文件选择 + "从 URL 导入" + 文件夹；显示队列与逐项进度。
- 文档行状态：排队/解析中/索引中/就绪/失败（可重试）/部分成功。
- 文档详情：切片列表（可编辑/删除单切片）、原文预览（高亮切片）、"重新索引"。
- 检索调试（Tab）：输入 query → 显示命中片段、分数、来源、耗时；用于调参与验收。
- 设置：切片策略、embedding 模型、检索模式（向量/关键词/混合）、阈值、共享范围。
- 态：空库引导、解析失败原因、维度不匹配的迁移提示。

### 5.6 来源与定时 `/tasks/sources`

- 四个 Tab：**来源 / 定时任务 / 工作流 / 触发规则**。
- **来源**：GitHub（仓库/事件类型/允许的人/机器人名单）、IM（平台/机器人/群）、邮件（IMAP/过滤）、Webhook（URL/密钥/事件映射）。每行显示：状态、读取位点（上次同步时间）、最近事件、暂停/恢复、测试。
- 定时任务表：名称、专家、触发（人类可读 + 下次运行）、动作、状态、最近结果、操作（运行/编辑/暂停/删除）。
- 新建抽屉：名称、选专家、触发（可视化 cron：每天/每周/每月/自定义 + 时区）、动作（通知/运行 Agent/运行工作流）、提示词/参数、目标会话（新会话/指定会话）、失败通知。
- 运行历史抽屉：时间、状态、耗时、输出摘要、错误、重试。
- 工作流：列表 + 画布编辑器（见 5.7）。
- 触发规则：Gate 的白名单/关键词/显式请求判定 + Assessment 的策略提示词。**默认档 `explicit_only`**（只响应 @、命令、指派、回复 bot）；支持"干跑"（只记录不执行），建议干跑 24h 再激活；`inferred` 需管理员显式开启并设日预算。

- **分组**：待我决定（attention）/ 进行中（assignment running）/ 已排队（ticket open, assignment pending）/ 已完成（ticket ended）。

- **实时**：`ticket.*` / `assignment.*` / `attention.*` 事件驱动，无需轮询。

### 5.15 注意力收件箱（全局）

- 顶栏铃铛 + 徽标（`⌘⇧A` 打开），与任务中心"待我决定"同源。
- 三类：**审批**（工具/写操作）、**提问**（Agent 需要信息）、**受阻**（预算/权限/依赖）。
- 每条：来源 + 工单号 + 一句话问题 + 影响面 + 快捷决策（允许 / 拒绝 / 回答 / 稍后）。
- 支持"同类批量允许"（带 scope 与时长），但**默认不静默自动批准**；自动批准必须留可见记录，可撤销。
- 超时策略：按 Policy 配置"保持 / 自动拒绝 / 升级给管理员"。
- 待决上限：每用户默认 20 条，超出时新任务进入"排队"，避免注意力被打爆。

| 阶段 | 状态 | 展示 |

## 6. 关键交互流程

### 6.1 首次使用（0→1）

```
访问 → /setup（5 步）→ 完成 → 自动登录 → /chat
  └─ 欢迎页：3 个示例（"总结这份文档" / "帮我写周报" / "创建一个代码助手"）
       └─ 点示例 → 若无专家，先引导创建（模板预选）
```

### 6.2 发一条消息（正常）

```
输入 → Enter
  ├─ 乐观插入用户气泡（status=sending）
  ├─ 建 turn → turn.queued → turn.started
  ├─ 首个 delta → 气泡转为"生成中"，显示停止按钮
  ├─ tool.started → 过程块出现
  ├─ approval.requested → 审批卡 + 输入锁定 + 浏览器通知
  ├─ 用户批准 → resume → 继续
  └─ turn.finished → 封口、耗时/用量、建议追问
```

### 6.3 断线重连

```
WS close（非主动）
  ├─ 显示"重连中"条
  ├─ 指数退避（0.5/1/2/4/8s，上限 10 次）
  ├─ 连上 → subscribe{after_seq}
  │    ├─ turn_status=active → 继续收流
  │    └─ turn_status=idle  → 拉历史补齐
  └─ 失败 10 次 → "连接失败 [重试] [查看诊断]"
```

### 6.4 团队协作

```
用户在房间发问
  ├─ 协调者回复"我来分派" + 计划卡
  ├─ 成员 A/B 气泡依次上墙（不同头像/色条，标"来自 A"）
  ├─ 成员工具调用以折叠块显示在各自气泡内
  ├─ 协调者汇总（带"【总结】"前缀）
  └─ 右侧成员条显示谁在运行/空闲
```

### 6.5 知识入库

```
上传 → 队列项（进度条）→ 解析（可看页数）→ 切片（可预览）→ 索引 → 就绪
  └─ 失败 → 红色状态 + 原因 + [重试] [查看日志]
```

### 6.6 审批（多端）

```
Web 弹出审批卡（同时 IM 收到卡片消息）
  ├─ Web 批准 → 事件 approval.resolved → IM 消息编辑为"已批准"
  └─ IM 回复"同意" → 同样 resolve → Web 卡片收起
```

### 6.7 事件驱动的一次工作（新增）

```
GitHub issue_comment（@bot 请修一下）
  → Source 收到 webhook（验签 + 202）
  → Trigger 落库（dedupe: comment_id）
  → event_thread = issue#412
  → Gate：actor 在白名单 + 显式请求 → pass
  → Assessment：accept / explicit / scope=[repo:acme/api]（1.2s）
  → Ticket opened（Mandate: policy v7）
  → Assignment → Executor（builtin 或 claude-code）
  → Report progress → 任务中心进度条
  ├─ 需要写 CI 配置 → Attention → 收件箱红点 → 人允许
  └─ 完成 → Report ready（PR #418）
  → Ticket ended
  → Channel：回到 issue 评论（GitHub 结构化回复）
  → 事件流：Web 任务详情 + 对话列表"任务"徽章
```

**人介入的四个入口**：注意力收件箱、任务卡片、工单详情、对话（接管后）。

**"停止"的语义**：只停止当前 Assignment，Ticket 进入 ended（`stopped_by_human`），Mandate 作废；之后该 Thread 上的人消息**不会再自动接单**（除非重新 Eval 并新建 Ticket）。

## 8. 前端架构

### 8.1 状态分域

```
stores/
  sessionStore     会话列表、当前会话、未读、置顶
  threadStore      消息、回合、历史分页、投影
  streamStore      连接状态、seq、当前流、批量渲染
  queueStore       待发送队列、steer 项
  uiStore          dock、面板宽度、折叠、主题、快捷键
  agentStore       专家列表、当前专家、模板
```

- 一律 `useSyncExternalStore` + selector 订阅（`useStore(store, selector, equality)`），禁止整树订阅。
- 服务端数据用查询缓存（TanStack Query）：`useThreads`, `useAgents`, `useKnowledge`；`staleTime` 30s，变更后精准失效。
- 本地草稿/偏好走统一 `storage` 模块（命名空间、版本迁移、TTL、内存 fallback）。

### 8.2 事件处理管线

```
WS frames → normalize(frame) → reducer(streamStore) → 50ms 批量 commit
                                   ├─ message.* → threadStore
                                   ├─ tool.*    → threadStore.toolCalls
                                   ├─ approval.*→ uiStore.approvals
                                   └─ usage.*   → uiStore.usage
```

- 单一 reducer，纯函数，可单测；帧的未知类型忽略并上报。
- 重放：给定 `turn_id` 可从服务端拉事件序列重建 UI（用于"重播这一轮"）。

### 8.3 API 客户端

- OpenAPI → `types.gen.ts`；手写薄封装（每域一个模块）。
- 统一拦截：认证、locale、trace id、错误映射、401 刷新一次、403 跳转。
- 流式：`fetch` + ReadableStream（SSE）与原生 WS 两种传输，接口一致。

### 8.4 性能预算

| 指标 | 预算 |
|---|---|
| 首屏 JS（gzip） | ≤ 220 KB（不含按需 chunk） |
| LCP | ≤ 2.0s（本地） |
| 流式帧到 paint | ≤ 80ms |
| 1000 条消息滚动 | ≥ 50fps |
| 路由切换 | ≤ 150ms（已预取） |

手段：路由级 code split、重组件懒加载（Monaco/pdf.js/xterm/Mermaid）、虚拟列表、图片懒加载、字体 `font-display: swap`。

## 10. 可访问性与国际化

**可访问性（WCAG 2.1 AA）**
- 所有交互元素可聚焦（禁止裸 `div onClick`）；`:focus-visible` 明显。
- icon-only 按钮必须有 `aria-label`。
- 对话框焦点陷阱 + 关闭后归还焦点。
- 流式状态用 `aria-live="polite"` 播报"正在生成/已完成"。
- 颜色对比 ≥ 4.5:1；不只用颜色表达状态（配图标/文本）。
- 键盘可达：Tab 顺序、方向键切 Tab、Esc 关闭、⌘K 全局。

**国际化**
- 语言：zh-CN / en-US（预留 ja/ko）。
- 文案单一真相：只允许 key，禁止内联兜底中文（Octop 的 788 处内联兜底是反面教材）。
- **key 树规范（N-05）**：`域.页面.控件[.状态]`，如 `chat.composer.send`、`tickets.row.stopConfirm`；zh/en 双树**行数与叶子集合必须一致**，CI 校验（借 Octop 的 key 一致性测试）。
- **回退策略**：缺 key → 回退 en 并 `console.warn` + 计数上报；禁止显示裸 key。
- **服务端显示名（N-05）**：工具/技能名由 `GET /tool-labels`、`GET /skill-labels` 下发（带 locale），前端合并进 i18n 后再渲染——避免工具名硬编码在两处。
- 命名空间拆分按路由懒加载，切语言不重载页面。
- 日期时间：服务端时区 + `Intl.DateTimeFormat`；相对时间（"3 分钟前"）本地化。
- 数字/货币：按 locale 格式化；成本显示保留 4 位小数或 `<0.01`；**大额 token 缩写**（`1.2M/3.4K`）+ tooltip 精确值。
- RTL 预留：布局用 logical properties（`margin-inline-start` 等）。
- **页面级验收（D-17）**：每页至少 1 条 i18n 验收（无裸 key/无内联中文）+ 3 条 a11y 验收（焦点/aria/对比度）。

## 12. Octop 交互资产清单（可直接借鉴）

Octop 的前端结构有问题，但**交互细节是踩坑换来的**。下面这些应当在 PolyOpus 里保留，重建成本极高：

| # | 资产 | Octop 做法 | PolyOpus 怎么用 |
|---|---|---|---|
| 1 | 50ms 批量 paint | `STREAM_PAINT_MS=50` + 不可变快照 + `useSyncExternalStore` | 原样保留；再加"结构化帧立即 paint"的分流 |
| 2 | 虚拟列表前插锚定 | `react-virtuoso` + `firstItemIndex` 从 1e6 倒扣 | 原样保留（这是加载历史不跳的关键） |
| 3 | follow/free 双态滚动 | 程序化滚动守卫 700ms、发送时 `useLayoutEffect` 同步 pin | 原样保留 |
| 4 | 在飞尾部缓存 | `inflightTranscriptCache`（sessionStorage，80k/条、1.5MB 上限）+ `mergeHistoryTail` | 原样保留，解决"刷新丢半条回答" |
| 5 | 工具 UI 插件协议 | `octop_ui{renderer,version}` + `data_ref:"artifact"` + blob-ESM 加载 + `patchResult` + 错误边界回落 | 保留并加 `api_version` |

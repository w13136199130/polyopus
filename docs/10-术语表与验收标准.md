# 10 · 术语表与模块验收标准（DoD）

> 解决两个协作问题：**叫法不统一**、**做完没有判定标准**。
> 用法：评审时对照本表；实现完成后逐条打勾。

---

## 1. 术语表（中英对照）

### 1.1 入口与工作（Intake）

| 术语 | 英文 | 定义 | 不要叫成 |
|---|---|---|---|
| 来源 | Source | 事件流的实现 + 一份配置（GitHub App、飞书机器人、IMAP 账号、Webhook） | 渠道、连接器 |
| 触发 | Trigger | 一条不可变的外部事件，带来源元数据 | 消息、事件（太泛） |
| 事件线程 | Event Thread | **同一业务对象**的 Trigger 序列：一个 PR / issue / 邮件串 / IM 话题 = 一个线程；评论面与 CI 是上下文，行内 review 只是 anchor | 消息线程、话题（太泛） |
| 研判 | Eval | Gate + Assessment 的合称 | 审核、路由 |
| 准入 | Gate | 确定性过滤：谁、从哪、是否明确请求 | 鉴权（那是 authn） |
| 评估 | Assessment | 模型判断：接不接、多大范围、明确还是推断 | 审核 |
| 决定 | Decision | Eval 的输出：accept/stop/ignore/unavailable | 结果 |
| 策略 | Policy | 版本化的接单规则 + 各来源准入表 | 配置、规则（太泛） |
| 授权 | Mandate | 不可变的授权凭证：策略版本、范围、强度、命中规则、发起人 | 权限（那是 RBAC） |
| 工单 | Ticket | 一个被授权的工作单元，可跨多轮、可恢复 | 任务、job（太泛） |
| 派工 | Assignment | 工单与某个 Executor 实例的绑定 | 运行、run |
| 订阅 | Subscription | 工单与事件线程的多对多关系（只给上下文，不给权限） | 关注 |
| 去向 | Disposition | 每条 Trigger 的处理结果记录 | 日志 |
| 待决 | Attention | 需要人回答的结构化事项（审批/提问/受阻） | 通知、告警 |
| 执行器 | Executor | 跑工单的端口；内置或外部（Codex/Claude Code/DSH） | 引擎、内核 |
| 内核 | Kernel | 我们自己写的 Agent 循环（prompt/模型/工具/审批/插话/预算/事件） | 模型、Agent |
| 报告 | Report | 执行器回报的结构化状态 | 结果、日志 |
| 巡检 | Watchdog | 独立定时任务，检查执行器是否卡住/跑偏 | 监控（那是 metrics） |

### 1.2 对话与执行

| 术语 | 英文 | 定义 |
|---|---|---|
| 对话 | Conversation / Thread | 人与 Agent 的一段聊天（原 `threads` 表） |
| 轮次 | Turn | 一次用户输入及其完整回复（含多步） |
| 运行 | Run | Turn 的一次执行尝试（重试即新 Run） |
| 步骤 | RunStep | 运行中的原子步骤（模型/工具/审批/压缩/委派） |
| 事件 | Event | append-only 的事实流（驱动 UI、审计、回放） |
| 消息 | Message | 事件的展示投影 |
| 插话 | Steer | 生成中追加的用户输入，在安全边界注入 |
| 审批 | Approval | 针对工具调用的 HITL 决策 |
| 压缩 | Compaction | 上下文超预算时的摘要化 |
| 引用图 | Chain of Recall | Trigger→Thread→Ticket→Assignment→Run 的稳定 ID 链 |

### 1.3 能力与数据

| 术语 | 英文 | 定义 |
|---|---|---|
| 工具 | Tool | 可被模型调用的函数，带 JSON Schema 与风险级别 |
| 技能 | Skill | 提示词包 + 脚本（`SKILL.md`） |
| 插件 | Plugin | 工具/技能/钩子/UI 的打包分发单元 |
| 连接器 | Connector | OAuth/MCP 形式的外部服务接入 |
| 知识库 | Knowledge Base | 文档 + 切片 + 向量 + 检索配置 |
| 记忆 | Memory | 跨会话的事实/偏好/情景/画像 |
| 记忆原子 | Memory Atom | 一条可检索的长期记忆（`fact/preference/episode/skill`），带来源、置信与有效期 |
| 工作上下文 | Working Context | 单次模型调用的 prompt 内容（system + 工具 + 历史 + 输入） |
| 压缩 | Compaction | 上下文超预算时把整段对话摘要化，保留决策/未决/引用 |
| 工具结果清除 | Tool-result Clearing | 把旧的、可重取的工具结果替换为占位，保留调用记录 |
| 命名空间 | Namespace | 记忆隔离边界：`tenant_id:agent_id` |
| 资源 ACL | Resource ACL | 资源级授权（viewer/editor/owner） |
| 租户 | Tenant | 隔离边界；默认 `default` |

## 2. 模块验收标准（DoD）

> 每个模块"完成"必须同时满足：功能、边界、错误、可观测、测试、文档六项。下表是**模块特有**的判定条件，通用六项不重复。

### 2.1 platform

- [ ] 迁移在空库、旧库、SQLite、PG 四种组合上通过
- [ ] 队列并发领取 100 协程无重复、无丢失
- [ ] 配置损坏时拒绝启动并给出修复命令（不是静默默认）
- [ ] 事件写入 p95 ≤ 100 ms（本地）
- [ ] BlobStore 三实现通过同一套契约测试

### 2.2 identity

- [ ] 越权矩阵（5 角色 × 12 资源 × 6 动作）全绿
- [ ] refresh token 复用检测生效
- [ ] 改密/绑 MFA 后旧 token 立即失效
- [ ] API Key 作用域与速率限制可验证

### 2.3 agents

- [ ] 模板实例化后的文件树快照测试通过
- [ ] 发布/回滚状态机全绿；会话锁版本可验证
- [ ] 删除 Agent 后无残留（DB/workspace/索引/授权）
- [ ] spec schema 向后兼容（v1 快照回归）

### 2.4 conversations

- [ ] 状态迁移矩阵全覆盖（每个状态 × 每个事件）
- [ ] 在 model/tool step 处 kill -9 后可恢复或明确失败
- [ ] 同 thread 并发写 seq 连续无洞
- [ ] 投影删除后可从 events 完整重建
- [ ] 审批跨重启可恢复

### 2.5 intake

- [ ] 重放同一条 webhook 100 次 → 1 个 Ticket
- [ ] 每条 Trigger 都有 disposition（含 filtered）
- [ ] Gate 规则表驱动测试全绿；默认拒绝
- [ ] Mandate 校验 fail-closed；越权工具被拒并审计
- [ ] 人 stop 后该 Thread 不再自动接单
- [ ] Assessment 60 条样本 precision ≥ 0.9
- [ ] 崩溃恢复：assignment 中 kill，重启后 attempt+1 且不重复回复

### 2.6 kernel

- [ ] 8 类场景单测：纯文本/单工具/多工具/工具失败/审批中断/超步数/取消/压缩
- [ ] 内核测试不依赖 DB 与网络（FakeModel 即可跑）
- [ ] 取消传播到子进程（无孤儿）
- [ ] 上下文压缩后不丢 system 与最近 K 轮

### 2.7 capabilities

- [ ] ToolSpec schema 校验拒绝非法参数
- [ ] 策略规则每条至少 1 正 1 负
- [ ] 插件装载/卸载/热更新不重启
- [ ] MCP 断连降级为"该组工具不可用"，不阻塞整轮
- [ ] async 工具结果回到同一 turn；取消可传播

### 2.8 knowledge

- [ ] 黄金集 recall@5 ≥ 0.8；引用可定位到片段
- [ ] ACL 在检索 SQL 内过滤（B 用户检索不到 A 的 KB）
- [ ] 切片快照稳定（同文档同参数）
- [ ] 解析失败可重试且有可读原因

### 2.9 memory

- [ ] 每条记忆可追溯来源 turn
- [ ] 冲突不静默覆盖（保留双方 + requires_review）
- [ ] 单条/按来源/全量删除均可用
- [ ] 注入有预算上限，超限先裁剪相关性最低的

### 2.10 orchestration

- [ ] 派工幂等（dedupe_key）
- [ ] 成员忙时入队而非失败
- [ ] 停止协调者 ≠ 停止成员（语义明确）
- [ ] 工作流节点级重试与失败分支可验证

### 2.11 channels

- [ ] 平台 message_id 幂等
- [ ] 限流与退避可观测
- [ ] 群聊激活规则可配、可测
- [ ] 媒体下载后转 artifact 引用

### 2.12 control

- [ ] 浏览器 profile 隔离；CDP 仅本地 + token
- [ ] 终端默认禁用；启用后高危命令审批
- [ ] 所有输入注入有审计
- [ ] 会话超时与资源上限生效

### 2.13 billing / audit / admin

- [ ] 每次模型/工具调用都有 usage 记录（含 cost_micros）
- [ ] 三层配额（租户/用户/Agent）可阻断、可降级
- [ ] 审计可按 run/用户/资源检索并导出
- [ ] 管理概览含队列深度、错误率、p95

### 2.14 api

- [ ] 错误码与状态码一一对应（机器校验）
- [ ] OpenAPI 快照与前端生成类型一致
- [ ] 所有写操作支持 `Idempotency-Key`
- [ ] 列表统一 `{items, next_cursor}`

## 3. 评审时怎么用

1. **设计评审**：看 §2 的条目是否覆盖了本次改动；缺项就补设计。
2. **代码评审**：PR 描述里贴"本次涉及的 DoD 条目 + 验证方式"。
3. **发布评审**：里程碑内所有模块的 DoD 必须全勾；未勾的写清原因与补救计划。

> 不建议把 DoD 做成 100 项大表——**每模块 4–7 条**，够用且能被真正执行。

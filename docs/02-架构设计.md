# PolyOpus 架构设计（目标架构）

> **架构基线**：仓库最终树以 `33` 为准，边界决策以 `34` 为准；本文负责执行模型、数据模型与安全原则。
> 本文是 PolyOpus 的**目标架构**，不是 Octop 的复述。所有"Octop 现状"只作为对照与证据，用于说明为什么这样设计。
> 阅读顺序建议：先读 `01-功能全景.md` 了解要做什么，再读本文了解怎么搭骨架，最后读 `03-模块设计.md` 落地。

## 0. 一页纸结论

| 维度 | 决策 | 一句话理由 |
|---|---|---|
| 形态 | **模块化单体 + 可拆 Worker**，默认单进程单二进制 | 保留自托管"一条命令跑起来"的体验，但不把状态锁死在进程内 |
| 语言 | 后端 Python 3.12+（FastAPI），前端 React 19 + TS | 与 Octop 同栈，生态/招人/复用成本最低；Agent 生态（MCP、LangChain 生态、文档解析）在 Python 侧最全 |
| 数据 | PostgreSQL 为首选，SQLite 为单机默认 | 一套 schema 两种方言；队列/事件/租约都落在库里，不引入必选中间件 |
| 执行 | **持久化 Turn/Run/Step 状态机**（durable execution） | 崩溃可恢复、可多副本、可审计；这是与 Octop 最大的架构差异 |
| 入口 | **Source → Trigger → Eval → Ticket → Assignment** | 统一多来源事件、幂等、可审计；工作授权（Mandate）与上下文分离 |
| 会话 | **事件溯源（append-only events）为唯一事实源**，messages 为投影 | 消灭 Octop "checkpoint + jsonl + threads + trajectory" 四套存储并存 |
| 多租户 | 第一天就带 `tenant_id`（默认 `default`） | 后补租户列是灾难级改造；默认单租户不增加使用复杂度 |
| 扩展 | 工具/技能/插件/MCP 统一为 **Capability** 抽象 + 策略引擎 | Octop 的工具开关、HITL、命令护栏、技能禁用四套机制各自为政 |
| 前端 | 领域化状态（session / stream / queue / artifacts 分离）+ 生成式 API 客户端 | Octop 的 chatStore 单文件 3.8k 行，已到维护极限 |
| 部署 | 单机 / Docker Compose / K8s（可选 Redis） | 从个人 NAS 到企业内网一套代码 |

**与 Octop 的定位差异**：Octop 是"功能极全的家庭/小团队助手平台"；PolyOpus 是"可演进的 Agent 工作台内核 + 参考实现"。前者追求覆盖面，后者追求**可恢复、可观测、可扩展、可多租户**，功能面按里程碑逐步补齐。

## 1. 目标、约束与非功能需求

### 1.1 目标

1. **一个进程能跑**：`poly serve` 起 API + Web + Worker + Scheduler，数据落 `~/.polyopus/`。
2. **一条水平线能扩**：API 无状态可多副本；Worker 可独立扩容；会话不绑进程。
3. **一次对话可恢复**：进程被杀、机器重启、网络断开后，进行中的 turn 要么继续，要么给出明确失败与已产生内容，不出现"半截消息 + 幽灵状态"。
4. **一切可审计**：每次模型调用、工具调用、审批、委派都有 run/step 记录与 trace。
5. **能力可插拔**：新增模型供应商、工具、IM 平台、知识后端不改核心。
6. **默认安全**：最小权限、工具审批、路径越权防护、密钥加密、租户隔离默认开启。

### 1.2 非目标（首版明确不做）

- 多地域联邦与跨集群调度（Octop 的 Bridge 先做到"实例互联"级别即可）。
- 内置模型推理/训练。
- 移动端原生 App（先 PWA）。
- 插件市场托管与计费分成。
- 100% 兼容 Octop 的数据模型与 API（只保证**功能对齐**，不保证 wire 兼容）。

### 1.3 非功能需求（可验收）

| 编号 | 指标 | 目标值 | 验证方式 |
|---|---|---|---|

### 2.1 逻辑分层（C4-L1/L2）

```
┌──────────────────────────────────────────────────────────────────────────┐
│ Surfaces                                                                  │
│  Web Console (React SPA)   CLI (Click/Typer)   IM Adapters   HTTP/WS API   │
└───────────────┬──────────────────────────────────────────────────────────┘
                │  (JSON / SSE / WebSocket / 平台回调)
┌───────────────▼──────────────────────────────────────────────────────────┐
│ Interface Layer (api/)                                                    │
│  routers · ws hub · sse · deps(auth) · error mapping · openapi · rate limit│
└───────────────┬──────────────────────────────────────────────────────────┘
                │  只做协议转换，不放业务规则
┌───────────────▼──────────────────────────────────────────────────────────┐
│ Application Layer (domains/*/service.py)                                  │
│  Identity │ Agents │ Conversations │ Capabilities │ Knowledge │ Memory    │
│  Orchestration │ Channels │ Billing │ Audit                                │
│  —— 事务边界、用例编排、领域事件发布                                        │
└───────────────┬──────────────────────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────────────────────┐
│ Domain + Kernel                                                           │
│  kernel/: agent loop · model gateway · tool executor · prompt · context    │
│  domains/*/model.py, policy.py, repo interfaces                            │
└───────────────┬──────────────────────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────────────────────┐

│  db · migrations · queue · event bus · storage · secrets · telemetry · i18n│
└──────────────────────────────────────────────────────────────────────────┘
```

**依赖规则（硬约束，CI 强制）**

| 层 | 可以 import | 禁止 import |
|---|---|---|
| `kernel/` | `platform/`、stdlib、三方 SDK | `domains/`、`api/`、`cli/` |
| `domains/x/` | `kernel/`、`platform/`、同层 domain 的 **public 接口** | 其他 domain 的 `repo`/内部模块、`api/`、`cli/` |
| `api/` | `domains/*/service`、`kernel` 的类型、`platform/` | SQL、领域规则、`cli/` |
| `workers/` | `domains/*/service`、`kernel` | `api/` |
| `cli/` | `domains/*/service`、`platform/` | `api/`（`serve` 命令除外，走 launcher） |

> 实现手段：`import-linter` 或自写 `ruff` 规则 + CI 检查；比 Octop 只写在 AGENTS.md 里的约定更可靠。

### 2.2 进程形态

| 模式 | 命令 | 组成 | 适用 |
|---|---|---|---|
| **all-in-one**（默认） | `poly serve` | API + Web + Worker + Scheduler（同进程，多 asyncio 任务） | 个人 / NAS / 小团队 |
| **split** | `poly api` + `poly worker --concurrency 4` + `poly scheduler` | 通过 DB 队列通信 | 团队 / 需要独立扩容 |
| **HA** | N×api + M×worker + 1×scheduler(leader election) + Postgres + Redis(可选) | Redis 用于 WS 扇出与缓存；队列仍可用 PG | 企业 |

**关键点：模式切换不改代码，只改 `POLY_ROLE` 与 `POLY_QUEUE_DRIVER`。** 这是对 Octop "单进程、无队列、进程内状态" 的直接修正。

```python
# platform/runtime/roles.py
class Role(StrEnum):
    ALL = "all"; API = "api"; WORKER = "worker"; SCHEDULER = "scheduler"

def enabled_components(role: Role) -> set[Component]:
    return {
        Role.ALL:       {API, WORKER, SCHEDULER, WS_HUB},
        Role.API:       {API, WS_HUB},
        Role.WORKER:    {WORKER},
        Role.SCHEDULER: {SCHEDULER},
    }[role]
```

## 3. 核心执行模型（最重要的一章）

### 3.1 对象模型

```
Tenant 1─* User 1─* Agent 1─* Thread 1─* Turn 1─* Run 1─* RunStep
                                     │        └─* Event
                                     ├─* Message（投影）
                                     └─* Artifact
Run 1─* Approval
Run 1─* ToolInvocation
```

| 对象 | 语义 | 关键字段 |
|---|---|---|
| **Agent** | 配置实体（人格/模型/工具绑定），不是进程 | `agent_id, tenant_id, owner_id, kind(expert\|team), config_version` |
| **AgentVersion** | 不可变配置快照，可发布/回滚 | `version, spec_json, published_at` |
| **Thread** | 一段对话容器，绑定 agent，跨渠道 | `thread_id, agent_id, origin(web\|im\|cron\|api), session_key` |
| **Turn** | 用户的一次输入及其完整回复 | `turn_id, thread_id, seq, status, input_message_id` |
| **Run** | Turn 的一次执行尝试（重试即新 Run） | `run_id, turn_id, attempt, status, lease_owner, lease_until` |
| **RunStep** | 执行中的原子步骤 | `run_id, idx, kind(model\|tool\|approval\|compact\|delegate), status, input_ref, output_ref, idem_key` |
| **Event** | append-only 事实流，驱动 UI/审计/回放 | `thread_id, seq, type, payload_json` |
| **Message** | 面向展示的投影（user/assistant/tool/system） | `message_id, thread_id, turn_id, role, content_json, status` |

> **为什么不用 LangGraph checkpoint 当事实源**：checkpoint 是运行时内部结构，版本升级即变；它无法承载审批、插话、委派、用量等产品事件。Octop 因此被迫同时维护 checkpoint + jsonl + threads + trajectory 四份数据，且修复历史需要 `history_backfill.py` 这类补丁。PolyOpus 让**事件是事实，checkpoint 只是缓存**。

### 3.2 Turn 状态机

```
                 ┌──────────── cancel ────────────┐
                 ▼                                │
 queued ──► running ──► awaiting_approval ──► running
                 │  └──► awaiting_input ────────┘
                 │  └──► awaiting_tool(内部，不暴露)
                 ├──► completed
                 ├──► failed
                 └──► cancelled
```

- `queued`：已落库、已分配 turn_id，等待 worker 领取（可跨进程）。
- `running`：持有 run lease；心跳每 5 s 续租。
- `awaiting_approval` / `awaiting_input`：**不占 worker**，释放 lease，事件驱动恢复（审批来自 Web/IM/API）。
- 终态写入 `turn.finished` 事件 + 更新 `threads.last_active`。

**并发规则**：同一 thread 同一时刻只允许一个活跃 turn（`threads.active_turn_id` 唯一约束 + 悲观锁）。用户中途再发消息 → 走 **steer（插入当前 turn）** 或 **follow_up（排队下一 turn）**，与 Octop 的语义一致但持久化。

### 3.3 执行循环（伪代码）

```python
async def execute_turn(ctx: TurnContext) -> None:
    run = await runs.claim(turn_id=ctx.turn_id, worker=ctx.worker_id)  # SKIP LOCKED + lease
    try:
        while (step := await plan_next_step(run)) is not None:
            async with runs.checkpoint(run, step.idx):        # 幂等：已完成则跳过
                match step.kind:
                    case "model":   await run_model_step(ctx, step)    # 流式写 event
                    case "tool":    await run_tool_step(ctx, step)     # 审批→执行→审计
                    case "approval": await park_for_approval(ctx, step); return
                    case "compact": await compact_context(ctx, step)
                    case "delegate": await dispatch_to_peer(ctx, step)
            if await steer.has_pending(ctx.turn_id):
                await steer.drain_at_safe_boundary(ctx)          # 注入为用户消息
        await finish_turn(ctx, status="completed")
    except CancelledError:
        await finish_turn(ctx, status="cancelled")
    except Exception as exc:
        await finish_turn(ctx, status="failed", error=exc)
    finally:
        await runs.release(run)
```

**幂等与恢复语义（必须写进文档，避免"以为 exactly-once"）**

| 步骤 | 语义 | 恢复策略 |
|---|---|---|
| 模型调用 | at-least-once | 未完成则重跑该 step；已产生的 delta 事件保留，UI 以 `step.restarted` 事件重置该段 |
| 工具调用 | 由工具声明 `idempotent` | 幂等工具可直接重放；非幂等工具恢复时**不自动重放**，转 `awaiting_input` 让用户确认 |
| 审批 | exactly-once 决策 | `approvals` 行 + 唯一约束，重复提交返回同结果 |
| 委派 | at-least-once + 去重键 | 子任务带 `dedupe_key`，对端按 key 幂等 |

> 对比 Octop：团队在途任务用进程内 `TeamJobTracker`，重启即丢（其文档明确写为"非目标"）；HITL park 与 steer 队列同样在内存。这在单机小规模可用，但一旦需要"重启不丢活"就不成立。

### 3.4 事件契约

**唯一信封**（WS / SSE / 内部总线 / IM 投影共用一套类型；完整字段见 `11-事件Schema.md`）：

```json
{
  "v": 1,
  "event_id": "ev_01J9Z8Q3K7Y2N5M4P6R8S0T2V4",
  "stream_id": "conv:th_01J...",
  "seq": 10231,
  "type": "tool.completed",
  "ts": "2026-11-05T10:00:00.123Z",
  "tenant_id": "default",
  "actor": { "kind": "agent", "id": "ag_01J..." },
  "trace_id": "4bf92f...",
  "causation_id": "ev_01J...",
  "correlation_id": "tu_01J...",
  "refs": { "thread_id": "th_01J...", "turn_id": "tu_01J...", "run_id": "rn_01J..." },
  "payload": { "...": "..." },
  "meta": { "coalesced": false, "producer": "kernel" }
}
```

**事件类型表（首版 61 类，权威定义见 `11`）**

| 分组 | 类型 | 说明 |
|---|---|---|
| 生命周期 | `turn.queued` `turn.started` `turn.resumed` `turn.finished` | finished 带 status/usage/error |
| 文本流 | `message.started` `message.delta` `message.completed` | delta 带 `index`，支持多段/多说话人 |
| 推理 | `reasoning.delta` `reasoning.summary` | 不落 Message，仅事件与折叠 UI |
| 工具 | `tool.started` `tool.delta` `tool.completed` `tool.failed` | 带 `tool_call_id, name, args_digest` |
| 审批 | `approval.requested` `approval.resolved` | 结构化 decisions |
| 插话 | `steer.queued` `steer.drained` `steer.removed` `steer.rejected` | 客户端可撤回 |
| 上下文 | `context.updated` `context.compacted` | 供 Context Meter |
| 产物 | `artifact.created` `artifact.updated` | 文件/预览/插件卡片 |
| 计划 | `plan.updated` | 多步任务清单 |
| 错误 | `error` | 结构化 code + 可重试标记 |

**断线重连**：客户端持 `last_seq`，`GET /threads/{id}/events?after_seq=` 或 WS `subscribe{session_id, after_seq}`。服务端只保留最近 N 条在内存，历史从 `events` 表回放。

### 3.5 流式与背压

- 模型 delta → 聚合器（16–50 ms 或 64 token 批量）→ event bus → WS。
- 每连接有 `max_inflight_bytes`；超限降级为"每 250 ms 合并一帧"，并在 `message.delta` 上带 `coalesced: true`。
- UI 侧按 `requestAnimationFrame` 批量 render，禁止每 token setState。

### 3.6 Work Intake（工作入口层，2026-11 修订）

> 本节是 `07-SuperAgent评审与修订.md` 的落地摘要。原设计把 Web/IM/cron/webhook 当作"入口"，各自转成 Turn；修订后统一为 **Source → Trigger → Eval → Ticket → Assignment**，Turn 降级为 Executor 的内部实现。

```
Source(adapter, read_position, identity)
  → Trigger(immutable, dedupe_key)
  → event_thread(thread_key)
  → Gate(确定性) → Assessment(模型) → Decision
  → Ticket(Mandate: policy_version/scope/strength)
  → Assignment(executor_kind, lease)
  → Executor(TurnEngine | 外部 harness)
  → Report → Channel(回复) + events
```

**四条硬规则**

1. **幂等**：`(source_id, dedupe_key)` 唯一；同一 Trigger 接受两次只建一个 Ticket。
2. **授权与上下文分离**：Subscription 只把事件扇出给 Ticket 当上下文，**不授予权限**；权限只在 Mandate。
3. **Ticket 状态独立于 Executor**：Executor 只能 `report(dropped)`；结束/停止由人、完成或 Policy 失效决定。
4. **Eval 串行且批处理**：同一 `event_thread` 同时只跑一个 Eval，期间到达的 Trigger 合并进下一批；被过滤的 Trigger 也要写 `disposition`。

**两层判断**

| 层 | 实现 | 职责 | 失败处理 |
|---|---|---|---|
| Gate | 确定性代码（毫秒） | 来源/身份/白名单/bot/限流/显式请求 | 过滤并记 `trigger.filtered` |
| Assessment | 便宜模型 | 该不该接、scope 多大、explicit 还是 inferred | 超时/失败 → `unavailable`，Trigger 重新入队 |

**Mandate**（不可变）：`{policy_version, scope[], strength, matched_rules[], actor{source,id}}`。工具执行前校验 `tool.required_scope ⊆ mandate.scope`；不满足 → 拒绝并开 `attention`。Policy 变更只投递、不撤销；扩大范围必须开新 Ticket。

**成本**：`tickets.budget_json`（tokens / cost / wall-clock / tool calls）；超限 → `report(blocked)` → Attention。`strength=inferred` 默认零主动预算，只做只读。

**Watchdog**：独立调度（不在 API/Worker 进程内），每 5 分钟巡检所有 running Assignment 的心跳与最近报告；`stalled`（心跳超时）与 `drifting`（便宜模型判定偏离目标）各发 `watchdog.alert`，并可在任务中心一键停。

**统一执行基底与懒 Ticket（2026-11 定稿）**

对照 Octop b4：它没有 Ticket/Mandate，所有入口（Web/IM/cron/团队/桥接）最终都落到
`session_key → thread → turn` 这一条执行基底；cron 用 `cron_runs.lease_token` 做持久化，团队任务用进程内 tracker。
PolyOpus 保留 Ticket，但**不把 Ticket 当成第二条执行路径**：

1. **执行基底只有一条**：所有入口都落 `thread + turn`；Ticket 是工作授权/预算/审计的**信封**，不是执行器。
2. **同步只读对话不建 Ticket**：无工具、无预算、无审批、无异步的普通问答，`turn.ticket_id = null`。
3. **懒创建 Ticket**：出现以下任一条件时，在**执行前**创建 Ticket 并回填 `turn.ticket_id`：
   - 调用 `risk >= medium` 的工具，或任何写操作；
   - 需要审批 / 需要预算；
   - 异步工具、长任务、跨 turn continuation；
   - 来自 IM / cron / webhook / 团队的自动任务（这些入口直接创建 Ticket）。
4. **Mandate 来源**：Web 对话用“会话策略 + 用户显式请求”生成；自动入口用 Policy/Assessment 生成。
5. **无 Ticket 的 turn 只能只读**：只允许 `risk=low` 且 `side_effects=false` 的工具；否则拒绝并要求升级为 Ticket。
6. **Ticket 结束不影响 thread**：Ticket 是工作单元，thread 是对话容器；一个 thread 可顺序承载多个 Ticket。

> 完整概念、DDL、状态机、事件与 UI 见 `07`；懒创建规则同步到 `28 CHAT-015`、`32 §6`、`ADR-012`。

## 4. 数据模型

### 4.1 约定

- 主键：`id BIGINT` 自增（内部），业务 ID：`xxx_id TEXT UNIQUE`（ULID，对外与跨表引用）。沿用 Octop 的这条经验，它是对的。
- 所有业务表带 `tenant_id TEXT NOT NULL DEFAULT 'default'` + 组合索引首列。
- 时间统一 `ts BIGINT`（epoch ms），避免时区问题；展示层按 `settings.timezone`。
- 软删除：`deleted_at BIGINT NULL`；审计表只追加。
- JSON 列统一 `*_json TEXT`（SQLite）/`JSONB`（PG），由 repo 层做序列化。

### 4.3 关键 DDL（SQLite 方言，PG 由迁移器生成）

```sql
CREATE TABLE turns (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  turn_id       TEXT NOT NULL UNIQUE,

CREATE TABLE runs (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  run_id        TEXT NOT NULL UNIQUE,
  turn_id       TEXT NOT NULL REFERENCES turns(turn_id) ON DELETE CASCADE,
  attempt       INTEGER NOT NULL DEFAULT 1,
  status        TEXT NOT NULL,
  lease_owner   TEXT,
  lease_until   INTEGER,
  heartbeat_at  INTEGER,
  last_step_idx INTEGER NOT NULL DEFAULT -1,

  finished_at   INTEGER,

CREATE TABLE events (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  tenant_id   TEXT NOT NULL DEFAULT 'default',
  thread_id   TEXT NOT NULL,
  seq         INTEGER NOT NULL,
  turn_id     TEXT,
  run_id      TEXT,
  type        TEXT NOT NULL,
  payload_json TEXT NOT NULL,
  ts          INTEGER NOT NULL,
  UNIQUE (thread_id, seq)
);
CREATE INDEX idx_events_thread_seq ON events(thread_id, seq);

CREATE TABLE approvals (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  approval_id   TEXT NOT NULL UNIQUE,
  turn_id       TEXT NOT NULL,
  run_id        TEXT NOT NULL,
  step_idx      INTEGER NOT NULL,
  request_json  TEXT NOT NULL,       -- 展示用的结构化审批单
  decisions_json TEXT,               -- 用户决策（可多次）
  status        TEXT NOT NULL,       -- pending/approved/denied/expired

  created_at    INTEGER NOT NULL,
  resolved_at   INTEGER,
  UNIQUE (run_id, step_idx)
);
```

### 4.4 投影与保留策略

- `messages` 由 `message.started/delta/completed` 聚合写入；`events` 是事实，`messages` 可重建（提供 `poly repair projections`）。
- 事件保留：默认 90 天热存 + 归档到对象存储（JSONL）；消息永久。
- 大对象（附件、截图、PDF 预览）走 `artifacts` + 对象存储/本地 CAS，DB 只存元数据与 hash。**不要**像 Octop 那样把附件塞进 agent workspace 的 `inbound/`，否则"删除会话"与"清理存储"永远对不上账。

## 5. 内核（Kernel）设计

### 5.1 模型网关

```python
class ModelGateway(Protocol):
    async def stream(self, req: ModelRequest) -> AsyncIterator[ModelDelta]: ...
    async def complete(self, req: ModelRequest) -> ModelResponse: ...
    def capabilities(self, model: str) -> ModelCaps: ...

@dataclass(frozen=True)
class ModelRequest:
    model: str
    messages: list[ChatMessage]
    tools: list[ToolSpec]
    temperature: float
    max_output_tokens: int
    response_format: Literal["text", "json_object", "json_schema"] | None
    reasoning: ReasoningConfig | None
    tenant_id: str
    trace: TraceContext
```

职责：供应商适配（OpenAI 兼容 / Anthropic / Gemini / Ollama / 自建）、能力矩阵、流式归一化（文本/推理/工具调用统一成 `ModelDelta`）、重试与退避、fallback 链、限流、用量与成本核算、prompt cache 命中统计。

**路由规则**（可配置，按租户/Agent/任务类型）：
1. 显式指定模型 → 用之；
2. `task_class`（chat / summarize / extract / embed / judge / vision）→ 路由表；
3. 失败（超时/5xx/429）→ fallback 链下一个；
4. 预算耗尽 → 降级到便宜模型或拒绝并给明确错误码 `QUOTA_EXCEEDED`。

**能力矩阵**：`ModelCaps{max_input_tokens, max_output_tokens, supports_tools, supports_vision, supports_responses_api, cache_style(anthropic|openai|none)}`；上下文预算表按 `max_input_tokens` 分档缩放（`13 §3.2`）。

**健康路由（2026-11，借 Octop `providers/health.py`）**：网关内维护进程内健康状态机——`healthy / open(冷却 60s) / half_open(试探一次)`；调用失败按类型分类（网络/限流/鉴权/内容）驱动状态迁移；AUTO 路由先 `reserve_healthy()` 预留健康模型。健康只影响运行时，不写库。

**预置模型同步**：启动时合并预置 `models` 行；用户改过的（`updated_by` 非空）不覆盖；已失效的默认模型自动替换为路由表下一个健康项。

**计费**：ModelGateway（chat）/ embedding / 评估三个入口统一读 `model_prices`（当前 version）计 `cost_micros`；价格 upsert 自动升 version，历史账单保留当时的 `price_version`。

> Octop 的模型解析散落在 `GlobalProcessor._resolve_harness_model_route` 与 `AgentManager` 里，且用量只记 token 不记成本。PolyOpus 把它收敛为单一网关 + `usage_records`（含 `cost_micros`、`currency`、`price_version`）。

### 5.2 工具执行器与策略

```python
@dataclass(frozen=True)
class ToolSpec:
    name: str
    description: str
    input_schema: dict[str, Any]
    source: Literal["builtin", "mcp", "plugin", "openapi", "skill"]
    risk: Literal["low", "medium", "high", "critical"]
    side_effects: bool
    idempotent: bool
    timeout_s: float = 60
    scopes: tuple[str, ...] = ()          # 需要的权限点
    renderer: str | None = None           # 前端卡片渲染器
    output_schema: dict | None = None
```

执行管线：

```
模型请求工具
  → 参数校验（JSON Schema）
  → 策略评估 policy.evaluate(subject, agent, tool, args)
      ├─ deny  → 返回结构化拒绝给模型（不是抛异常）
      ├─ ask   → 落 approvals + 事件 + 暂停 run
      └─ allow → 继续
  → 脱敏/限流/预算检查
  → 沙箱执行（超时、取消、输出截断、二进制走 artifact）
  → 审计 + usage + 事件
```

**策略引擎**用声明式规则（YAML/JSON），支持 `when` 表达式（agent.kind、tool.risk、args 前缀、时间、租户策略），返回 `allow/ask/deny + obligations`。默认策略：`risk>=high → ask`，`source=plugin 且未签名 → ask`，`critical → deny`。

**执行期二次校验（硬约束）**：模型可见的工具列表只是提示，不是安全边界。`ToolRuntime.invoke()` 必须重新求值 policy，防止 prompt 注入、历史调用或插件直接构造的 `ToolCall` 绕过。

**策略发布（硬约束）**：策略以 `policy_bundles` 为单位发布，状态 `draft → active → rolled_back`；每租户同时只有一个 active。发布前必须 dry-run（看会拦多少），支持灰度租户与一键回滚；策略加载失败时使用 last-known-good，没有 LKG 时只拒绝写工具，读工具降级放行并告警。

### 5.3 提示词组装与上下文预算

> 预算数值、压缩触发与保留清单、工具结果清除、引用图见 `13-记忆与上下文设计.md` §3。

顺序（稳定前缀在前，利于 prompt cache）：

```
[系统身份] SOUL/IDENTITY  →  [运行准则] AGENTS  →  [技能索引] skills index
→ [记忆快照] MEMORY/USER  →  [知识片段] retrieval（按 token 预算）
→ [会话摘要] rolling summary  →  [最近 N 轮原文]  →  [当前输入 + 附件引用]
```

- 预算：`context_window - max_output - reserve`；超限先压缩"最近 N 轮"为摘要，再裁剪知识片段（按相关性），最后才裁剪记忆。
- 压缩产出 `context.compacted` 事件，UI 显示"已压缩 X→Y tokens"。
- 所有注入片段带来源与 id，便于引用与审计（"为什么模型这么说"）。

### 5.4 中途插话（Steer）

与 Octop 语义对齐但持久化：

- `steer_items(turn_id, item_id, kind(text|image|file), payload, status(queued|drained|removed), created_at)`
- 只在**安全边界**注入：工具批次完成后、模型开始输出新内容前、turn 自然结束前。
- 审批挂起期间新 steer 拒绝（`reason=awaiting_approval`），恢复后继续排空。
- 队列上限：深度 10 / 总字节 256 KB，超限拒绝并提示。

### 5.5 审批（HITL）

- 审批单结构：`{approval_id, title, summary, actions:[{tool, args_preview, risk, scope}], allowed_decisions:[approve, approve_for_session, deny], expires_at}`
- 决策粒度：单次 / 本会话（thread 级 bypass，写 `thread_policies`，有 TTL 与审计）/ 永久（仅管理员，需二次确认）。
- 多端同步：Web/IM/API 任一处决策，其余端收到 `approval.resolved` 并收起卡片。
- 超时策略：默认 30 min 自动 deny + 明确提示（可配置为"保持挂起"）。

## 6. 多智能体编排

### 6.1 三种协作形态

| 形态 | 触发 | 执行 | 适用 |
|---|---|---|---|
| **委派 Delegation** | Agent A 调 `delegate(agent_b, task)` | B 在独立 thread 执行，结果回 A | 一次性子任务 |
| **团队 Team** | 用户对 team agent 说话 | 协调者拆解 → 并行/串行派给成员 → 汇总 | 多角色协作 |
| **工作流 Workflow** | 用户/定时/事件触发 | DAG 节点（LLM/工具/审批/子流程） | 确定性流程 |

### 6.2 持久化邮箱（替代 Octop 的进程内 InboxManager）

```sql
CREATE TABLE delegations (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  delegation_id TEXT NOT NULL UNIQUE,
  tenant_id     TEXT NOT NULL,
  parent_run_id TEXT NOT NULL,
  from_agent_id TEXT NOT NULL,
  to_agent_id   TEXT NOT NULL,
  room_thread_id TEXT,                 -- 团队房间
  child_thread_id TEXT,                -- 成员侧会话
  dedupe_key    TEXT NOT NULL,
  status        TEXT NOT NULL,         -- queued/running/done/failed/cancelled
  payload_json  TEXT NOT NULL,
  result_json   TEXT,
  lease_owner   TEXT,
  lease_until   INTEGER,
  attempts      INTEGER NOT NULL DEFAULT 0,
  created_at    INTEGER NOT NULL,
  UNIQUE (dedupe_key)
);
```

- 领取用 `SELECT ... WHERE status='queued' ORDER BY created_at LIMIT 1 FOR UPDATE SKIP LOCKED`（PG）/ 事务 + `BEGIN IMMEDIATE`（SQLite）。
- 同 callee 串行（可选），不同 callee 并行；失败重试 3 次后 `failed` 并回叫父 run。
- 重启后继续；`attempts` 超限进死信，UI 可见并可手动重试。

### 6.3 团队房间

- `room_thread_id` = 协调者的 thread；成员 checkpoint = `{room}~{member}`。
- 事件带 `speaker_agent_id`，前端按说话人渲染气泡（Octop 已有此设计，值得保留）。
- 协调者只做调度（轻量工具集），成员保留完整工具；派工消息由协调者**改写**后下发，避免原样转发导致指令歧义。

## 7. 扩展机制

### 7.1 Capability 统一模型

Octop 有：内置工具、插件工具、MCP 工具、技能（SKILL.md）、连接器（OAuth+MCP）、ACP runner。PolyOpus 统一为：

| 类型 | 提供物 | 注册方式 | 生命周期 |
|---|---|---|---|
| Builtin Tool | 函数 | 代码注册 | 随版本 |
| MCP Tool | JSON Schema | `mcp_servers` 行 + 发现缓存 | 连接级 |
| Plugin | 工具/技能/钩子/UI | `plugin.yaml` + `setup(ctx)` | 安装级 |
| Skill | 提示词包 + 脚本 | `SKILL.md` 目录 | Agent 级 |
| OpenAPI Tool | HTTP 端点 → 工具 | spec 导入 | 连接级 |

**统一到 `tools` 视图**：`agent 可用工具 = builtin(未禁用) ∪ plugins(启用) ∪ mcp(已连接且已选) ∪ openapi(已绑定)`，再经策略收缩。

### 7.1.1 技能渐进披露（v1.0 硬约束）

> 对照 Octop 后补：技能不能整包塞进 system prompt，否则上下文被技能正文吃满。

1. `SKILL.md` frontmatter 必填 `name / description / when_to_use`，可选 `allowed-tools / version / dependencies`。
2. system prompt **只放索引**：`name + 一句 description + when_to_use`；正文不进稳定前缀。
3. 正文按需读：内置 `skill.read(slug)` 工具，返回正文；单次 ≤32KB，带 `content_hash`。
4. **每轮 allowlist**：turn 配置可传 `skills=[...]`；索引与执行都按它过滤。
5. **禁用必须双向生效**：从索引移除，同时 `skill.read` 返回 `SKILL_DISABLED`；不能只改 prompt。
6. 技能包带 `version + dependencies`；安装校验路径穿越、文件数、总大小；依赖缺失时拒绝启用。

### 7.2 插件格式（比 Octop 更强的地方）

```yaml
# plugin.yaml
id: weather
version: 0.2.2
api_version: 1                 # 插件 API 版本，主版本不匹配拒绝加载
kind: tool                     # tool | skill | hook | channel | renderer
entry: main.py
permissions: [http:outbound, fs:workspace]   # 新增：声明式权限
ui:
  entry: ui/dist/index.js
  manifest: ui/dist/manifest.json
```

改进点：
1. **`api_version` + 兼容矩阵**（Octop 无，插件随核心升级即碎）。
2. **`permissions` 声明 + 运行时强制**（Octop 插件是任意 Python，等于给宿主开后门）。
3. **开发模式**：`poly plugin dev ./my-plugin` 起本地热重载 + 模拟工具调用面板。
4. **签名与来源**：安装时记录 sha256 与来源 URL；未签名插件默认 `risk=high`。
5. **UI 契约**：renderer 注册 + 版本化，宿主提供 `host.patchResult / host.openArtifact / host.i18n`。

## 8. 安全架构

### 8.1 威胁模型（STRIDE 摘要）

| 威胁 | 场景 | 控制 |
|---|---|---|
| 越权访问 | 用户 A 读 B 的 thread | 每次 repo 查询强制 `tenant_id + owner` 过滤；集成测试覆盖 |
| 路径穿越 | 工具读写 `../../etc/passwd` | workspace 路径 jail（resolve 后前缀校验），拒绝符号链接逃逸 |
| SSRF | 工具访问内网 metadata | 出站 allowlist + DNS/IP 校验 + 禁 169.254/10.x（可配） |
| 提示注入 | 网页内容指示模型删库 | 内容分区（untrusted 标记）、工具输出引用化、危险工具强制审批、系统提示优先级声明 |
| 密钥泄露 | 日志/事件里带 api_key | 结构化脱敏（regex + 已知 secret 值匹配）、日志白名单字段 |
| 供应链 | 恶意插件 | 权限声明、签名、默认禁用、审计 |
| 资源耗尽 | 大附件/超长上下文 | 上传限额、token 预算、每租户并发与速率限制 |
| 会话劫持 | XSS 偷 token | httpOnly cookie + CSRF token，或短期 access + refresh cookie；严格 CSP |

**提示注入三层防线（硬约束，`28 CAP-010`）**：

1. **入口**：IM/网页/webhook 外部内容统一标记 `untrusted`，包在专用分隔符内，不得拼进 system prompt 或作为指令解释。
2. **工具输出**：大内容（>2k token）写 artifact，上下文只保留摘要 + 引用 id；工具/网页输出永不包含“执行指令”语义的直通。
3. **记忆/知识**：写入白名单 + 置信阈值 + 来源标记（`13 §4.6`）；检索片段带 `source=untrusted|trusted`，模型可见来源。
4. **兜底**：无论提示如何声称“已批准”，工具执行仍以策略引擎判定为准（`ADR-011` 执行期二次校验）。

### 8.2 认证与授权

- **认证**：密码（argon2id）+ TOTP + WebAuthn；OIDC/OAuth（飞书/钉钉/企微）；LDAP 可选；API Key（作用域 + 过期 + 速率）。
- **SSO allowlist（硬约束）**：首登必须通过 `allowed_email_domains / allowed_groups`；`auto_provision` 默认关闭；首登角色固定，`role_sync=none|login` 必须显式配置；不匹配返回 `SSO_NOT_ALLOWED`，不建号。
- **Token 传输（硬约束）**：只允许 `Authorization: Bearer` 或 httpOnly+Secure cookie；`?access_token=` 返回 `TOKEN_IN_QUERY`；登出撤销 refresh family，密码修改撤销全部。
- **授权**：RBAC（系统角色）+ 资源 ACL（`owner / team / tenant / public`）+ 租户边界。权限点形如 `agent:write`、`kb:read`、`tool:approve`。
- **ACL 两层（硬约束）**：
  1. **能力层**：RBAC 决定“能不能做这个动作”（`kb:write`）。
  2. **可见层**：资源自身的 `visibility` + `resource_group_grants` 决定“能不能看到/用这个资源”。
  两层的交集才是最终允许；不能用一个替代另一个。
- **ACL 优先级**：`tenant 边界 > admin/owner > 显式 grant > visibility 默认`。默认 `private`；**无 grant 不等于公开**（这是 Octop 的 fail-open，不能复刻）。跨租户共享 v1 不允许。
- **资源类型**：`skill_package / knowledge_base / connector / model / storage_backend / plugin / expert / agent`；grant 只影响读/用，写仍要求 owner/admin。
- **实现**：列表查询用统一 SQL 片段（repo 层），单资源用 `ACL.allows()`（service 层）；前端 `can()` 只做展示。
- **grant 运维（硬约束）**：`effect` 默认 `allow`（v1 预留 `deny`）；支持 `expires_at` 临时授权；grant 变更必须失效权限缓存并写审计；提供批量授权与“为什么看不到”诊断。资源 key 用稳定 ID，不用路径。
- **来源身份（硬约束）**：外部 IM/webhook 消息必须带 `source_actor`，**不得继承 Agent owner**；`source_actors` 存外部 ID/显示名/human|bot/关联本地用户，`triggers/channel_messages.actor_id` 引用它；线程、用量、记忆按 actor 归属。
- **会话**：access JWT 15 min + refresh token 14 天（轮换 + 复用检测）；登出撤销 refresh family；密码修改撤销全部。
- **step-up（硬约束）**：重置密码、关闭 MFA、创建/撤销 API Key、修改安全策略，要求 5 分钟内重新认证（password/TOTP/passkey），并写审计。仅靠 access token 不够。
- **last-admin（硬约束）**：不能禁用/删除/降级最后一个 admin；对 admin 目标的敏感操作需二次确认 + 审计。
- **租户过滤**：repo 基类强制注入 `tenant_id`；CI 检查无 tenant 条件的查询（禁止 service 自觉）。

### 8.3 执行沙箱

| 能力 | 默认 | 可选 |
|---|---|---|
| Shell | 禁用；启用则走容器（推荐）或本地受限 subprocess（allowlist + 无 shell 解释） | Docker / Firecracker |
| 文件 | workspace jail | 挂载只读目录 |
| 浏览器 | 独立 profile 目录，CDP 端口仅本地 | 容器化 Chromium |
| 网络 | 出站 allowlist（可关） | 全放行（个人模式） |
| 插件 | 子进程 + 只读挂载 + 网络代理；默认禁用 | 容器 / Wasm |

> **插件隔离的现实约束**：Python 进程内无法可靠沙箱化。首版不承诺"in-process 安全"，插件一律子进程运行，
> 只给 workspace 只读挂载与受控网络；`permissions` 声明由宿主在调用前强制，而不是插件自觉。

## 9. 可观测性与评测

- **Tracing**：OTel；span 层级 `turn → run → step(model|tool) → http`；属性含 `tenant, agent, thread, run, model, tokens, cost`。
- **Metrics**（Prometheus）：`turn_total{status}`、`turn_duration_seconds`、`ttft_seconds`、`model_tokens_total{model,direction}`、`tool_calls_total{tool,status}`、`queue_depth`、`worker_lease_expired_total`、`approval_wait_seconds`。
- **Logs**：JSON 行，字段固定（`ts, level, trace_id, tenant, agent, thread, run, event, msg`），默认不含 prompt 全文（可开 DEBUG 且脱敏）。
- **回放**：给定 `run_id` 可重放事件序列到 UI（"重播这一轮"），用于排障与演示。
- **评测**：`tests/eval/` 下按能力域维护黄金集（工具选择、引用准确性、拒答率、注入抵抗），CI 上跑离线评测，回归即阻断。

## 10. 性能与容量

| 关注点 | 策略 |
|---|---|
| WS 扇出 | 单机内存 hub；多副本用 Redis pub/sub（可选），按 `thread_id` 分片 |
| 事件写放大 | 批量 insert（每 50 ms 或 100 条），单事务；seq 由 DB 分配 |
| 历史加载 | `messages` 投影 + `(thread_id, seq)` 索引；首屏只取最近 50 条 + 向前分页 |
| 大文件 | 直传对象存储（预签名 URL），后端只登记元数据 |
| 向量检索 | pgvector（HNSW）或 sqlite-vec；按 KB 分区，查询带 ACL 过滤 |
| 冷启动 | 延迟加载 provider SDK；插件按需 import |
| 内存 | 流式处理，不把整段对话拼在内存；附件不读入内存（流式转发） |

## 11. 部署与升级

### 11.1 单机

```
poly init            # 建库、管理员、密钥
poly serve           # 127.0.0.1:8787
poly service install # systemd/launchd/windows service
```

数据目录 `~/.polyopus/`：`poly.db`、`secrets/`、`workspaces/`、`artifacts/`、`logs/`、`plugins/`、`config.toml`。

### 11.2 Docker / Compose

`poly`（app）+ `postgres`（可选）+ `redis`（可选）+ `minio`（可选）。默认 SQLite + 本地卷。

### 11.3 升级

- 迁移版本化（`NNN_*.sql` + `NNN_*.pg.sql`），启动时自动迁移，失败即拒绝启动并给出回滚命令。
- 兼容窗口：API 与插件 `api_version` 各保留 N-1 兼容。
- 备份：`poly backup` 导出一致性快照（DB + 密钥 + 配置），`poly restore` 校验后恢复。

## 12. 架构决策记录（ADR）

| # | 决策 | 备选 | 取舍 |
|---|---|---|---|
| 001 | 持久化 Turn/Run/Step，不用纯内存执行 | 纯 asyncio 任务（Octop 现状） | 多写约 2k 行，换来崩溃恢复与水平扩展 |
| 002 | 事件溯源为事实源 | checkpoint 为事实源（Octop） | 需要投影与回放工具，但消灭多存储不一致 |
| 003 | 自研薄内核（~5k 行）而非绑定 LangGraph | 直接用 octop-harness / LangGraph | 失去现成图能力，换来可控的恢复语义与可测性；复杂流程由 workflow 模块补 |
| 004 | 默认单进程，队列抽象可换 | 直接上 Redis/Celery | 零依赖启动，需要时再拆 |
| 005 | 插件跑在宿主进程但声明权限 | 一律子进程隔离 | 首版性能与开发体验优先，高危插件走子进程（后续） |
| 006 | 前端 SPA + 生成式客户端 | SSR / BFF | 部署简单；SEO 无需求 |
| 007 | 多租户列从第一天存在 | 后续加 | 迁移成本极高，先行成本极低 |
| 008 | 引入 Work Intake 层（Source/Trigger/Eval/Ticket/Assignment） | 消息直接进 Turn | 多一层抽象，换来多来源统一、幂等、授权与审计 |
| 009 | Executor 做成端口，内置 kernel 只是默认实现 | 内核与产品强耦合 | 可接外部 harness；避免被单一运行时绑架 |
| 010 | 授权与上下文分离（Mandate vs Subscription） | 订阅即授权 | 主动性场景下必须能回答"谁允许的、能做多大" |
| 011 | **Intake 立即实施**（2026-11-05 决策） | 放到 v1.0 之后 | 越晚补，channels/cron/webhook 越要返工；M0 建表 + M1 最小摄取 |
| 012 | **内核自研 + Executor 端口**，外部执行器后接 | 直接用 Codex/Claude Code 当内核 | 通用场景与审批/插话/预算只有自研内核能做；专用编码活 v1.5 外包 |
| 013 | **默认接单档 `explicit_only`**（2026-11-05 决策） | allowed_list / all_candidates | 先建立信任；`inferred` 需管理员按来源开启并设日预算 |
| 014 | **事件线程按业务对象归一**（PR/issue/邮件串/IM 话题） | 按消息面（评论/CI 分开） | 避免同一 PR 多 Worker、上下文割裂与重复工单；review 用 anchor |
| 015 | **Source 归属租户级** | 实例级/全局级 | 一个 App 服务多租户时按 installation 区分；凭证进 secrets |
| 016 | **外部执行器以 Mandate 为准** | 以执行器自身权限模型为准 | 只交已授权子集；超范围即拒绝并开 Attention |

## 13. 与 Octop 的架构对照（速查）

| 维度 | Octop | PolyOpus | 迁移影响 |
|---|---|---|---|
| 进程 | 单进程，状态在内存 | 单进程默认 + 可拆 worker | 需要队列与租约 |
| 会话真相 | checkpoint + jsonl + threads + trajectory | events（+messages 投影） | 需要回放/重建工具 |
| 执行恢复 | 无（重启丢在途） | Run/Step 断点续跑 | worker 必须幂等 |
| 多智能体 | 进程内 Inbox + TeamJobTracker | 持久化 delegations 邮箱 | 团队可靠性提升 |
| 工具治理 | 开关 + HITL + YAML 护栏 | 统一 ToolSpec + 策略引擎 | 规则需迁移 |
| 记忆 | octop-memory 库 | 自有 memory 域（可换后端） | 数据迁移脚本 |
| 知识 | 固定切片 + 每 KB SQLite 向量 | 结构感知切片 + 混合检索 + 重排 | 需重建索引 |
| 扩展 | 插件 + MCP + 技能 | Capability 统一 + 插件权限 | 插件需改 manifest |
| 多租户 | 单实例多用户 | tenant_id 全表 | 新能力 |
| 前端状态 | 单 store 3.8k 行 | 分域 store + 生成客户端 | 重写 |

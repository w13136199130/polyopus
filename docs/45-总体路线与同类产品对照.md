# 45 · 总体路线与同类产品对照

> 回答三个问题：**市场上有哪些路线、各走成了什么样；PolyOpus 走哪条；接下来 12 周具体怎么走。**
> 竞品只做"模式级"对照（架构形态/取舍），不比版本细节；Octop 用本地源码证据。

---

## 0. 一句话

五条主流路线里，PolyOpus 走的是**"Octop 的产品面 × Temporal 的持久执行 × 契约先行的平台工程"**——
这是**起步最慢、天花板最高**的一条；对 4 人团队的正确打开方式不是水平铺开，而是
**walking skeleton + 两条垂直切片**（先打穿"对话+审批"，再打穿"工单+webhook"）。

---

## 1. 市场五条路线对照

| 路线 | 代表 | 核心打法 | 走成了什么 | 学什么 | 避什么 |
|---|---|---|---|---|---|
| **A 组装优先** | **Octop** | 拿现成引擎（octop-harness+deepagents+octop-memory）拼产品面：渠道/专家/UI/插件 | 上线最快、体验最全；但四套会话真相、上帝对象、无租户，官方 backlog 自认还需 24–32 人周才能企业化 | 交互资产（50ms paint/审批恢复/工具 UI 协议）、记忆引擎参数、渠道接入 | 引擎黑盒化后的 monkeypatch 与版本考古；状态进进程 |
| **B 工作流优先** | Dify / FastGPT / Coze | 可视化编排 + RAG 管线 + 应用市场，SaaS 优先 | 非开发者可用、增长快；但 Agent 自主性浅（流程是画出来的，不是长出来的），复杂循环后补 | 知识管线产品化（我们的 KB 调试面板/评测即学它）；模板/市场运营 | 把"自主 Agent"降级为节点连线——我们有 Ticket/Intake，不退回画布 |
| **C 引擎/框架优先** | LangGraph（+平台）、CrewAI、AG2 | 卖发动机：checkpoint/interrupt/多角色编排，生态优先 | 开发者心智强；产品面（租户/审计/渠道）留给上层 | interrupt 式 HITL、checkpoint 思想（我们已吸收进 Turn/Run/Step）；**harness 正在商品化 → 执行器必须可替换（ADR-014 舱 2）** | 用框架状态当真相（双真相病）；跟着快 API 演进重写 |
| **D 单场景纵深** | OpenHands、Claude Code、Codex | 一个场景（编码）打穿：沙箱运行时 + 事件流 + 工具链 | 单点极强、开发者爱；平台能力（多租户/入口/审计）基本没有 | **事件流架构**（与我们同构，验证了方向）；沙箱激进默认 | 场景绑定过深——我们做平台，编码只是可选执行器 |
| **E 持久执行优先** | Temporal、Restate | durable execution：一切是可重放的事件，worker 无状态 | 企业可靠性金标准；但无 Agent 语义，门槛高 | **我们的精神同源**：Turn/Run/Step+租约+S1 重放=轻量 Temporal；housekeeping/租约/死信的运维纪律 | 为可靠性引入全套 Temporal 依赖——DB 租约已够 T1/T2 |

**关键市场事实**：harness 正在商品化（Claude Code/Codex/DSH 都能被调用）——**这验证了我们的执行器端口设计**：差异化不在循环，在入口/授权/审计/注意力（`01` 结论 12 早已写下，路线未变）。

## 2. PolyOpus 的路线定位

```
路线 = A 的产品面 + E 的持久执行 + 平台工程纪律（契约/门禁/ADR）
        └─ 内核自研（ADR-014，带两条 buy 逃生舱）
        └─ 执行器端口（内置 TurnEngine | harness | Codex/Claude Code）
        └─ 不做 B 的画布（v1.5 DAG 已冻结为"不做节点编排优先"）
```

三条已定、不再重开的战略决策：

1. **自研薄内核 + 逃生舱**（ADR-014，翻转触发器已预注册）；
2. **v1.0 范围冻结**（团队/渠道/控制面/云主机 → v1.1，只建表不启用）；
3. **契约先行**（188 ops/61 事件生成 + coverage_check 硬门禁）。

## 3. 接下来 12 周的执行路线（对齐 `06`，强调垂直切片）

> 原则：**每个里程碑交付一条能演示的闭环，而不是一层能编译的横板。**

| 周 | 交付（垂直切片） | 出口判据（不过不进下一段） |
|---|---|---|
| W1–2 **M0 骨架**（25 张卡见 `47`） | 仓库/CI/config doctor/迁移器（先 12 表）/事件存储/最小租约/恢复演示 | `kill -9` 后 turn 恢复演示；空库/旧库/双跑矩阵绿 |
| W3–6 **切片①：对话+审批闭环** | identity 最小集 → threads/turns → SSE/WS → 内核 12 步跑通 → 审批卡（前端只做这一屏） | 同一句"读文件改一行"：流式可见、审批可暂停、重启可续、轨迹可回放 |
| W7–10 **切片②：工单+webhook 闭环** | Intake(Source/Gate/Eval) → Ticket/Mandate → Assignment → Report → 通知；任务中心一屏 | 重放 10 条 webhook 只建 1 工单；预算超限进 Attention；Watchdog 一键停 |
| W11–12 **加固** | 记忆三层(候选+晋升)、KB SQLite 路径+黄金集、用量计费、S4/S5 spike 收口 | 探针/黄金集达标；`coverage_check` G-4 从 WARN 升阻断，首批 ≥40 用例落地 |

M2 之后（能力/知识深化、管理端补全、v1.1 域）按 `06` 原计划，不在此展开。

## 4. 里程碑门与止损

| 门 | 判据 | 不过怎么办 |
|---|---|---|
| G-M0 | 恢复演示 + 迁移矩阵 | 阻塞一切；不允许"先写业务再补地基" |
| G-M1 | 切片①四件事（流式/审批/重启续/回放） | 内核问题 → 触发 ADR-014 舱 2；前端问题 → 收窄到服务端渲染事件流 |
| G-M2 | 幂等 10 连发 + 预算 + Watchdog | Intake 语义问题回 `09` 复核，不带病进 M3 |
| G-QA | 探针 ≥95% / recall@5 ≥0.8 / G-4 升阻断 | 舱 1 换压缩内脏；KB 不达标不上线（`06` 已写明） |

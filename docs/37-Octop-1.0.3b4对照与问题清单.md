# 37 · Octop 1.0.3b4 对照与问题清单

> 口径：本次对照的是 `E:\space\my_space\project\Octop`，版本 **1.0.3b4（2026-11-06）**；
> 此前的 `01/35/36` 基于 `E:\space\work_space\agnet\lsh-agent` 的 **1.0.3b2**。
> 结论：b4 在 b2 上增加了 **1 个新域（云主机）+ 多实例共享 + 若干交互细节**，PolyOpus 的基线需要更新。

## 0. 结论先行

| 判断 | 说明 |
|---|---|
| 基线已过时 | PolyOpus 的能力盘点锚定 b2；b3/b4 新增能力没有进入 `01/28/29/30` |
| 最大新缺口 | **云主机（腾讯云 CVM）**：12 个端点 + 一个工作台 Tab + 授权/监控/启停/AI 运维面板，PolyOpus 完全没有 |

| 第三缺口 | **资源分组可见性**：Octop 已覆盖 6 类资源；PolyOpus 有 `groups` 表但没有 `resource_group_grants` 或对应 API |

## 3. 交互对比与问题

### 3.1 工作台：2 Tab → 3 Tab

Octop b4：

- `/workbench` 下三个路径：`/workbench/terminal`、`/workbench/browser`、`/workbench/cloud`。
- 默认 Tab 按权限选择：有 browser 权限默认 browser，否则 terminal。
- 云服务器页包含：授权空态、地域筛选、实例表、指标热力图、集群趋势、节点详情抽屉、启停/重启确认、AI 运维面板。
- 授权交互不是填 AK/SK：**一键授权 → 浏览器登录 → 复制验证码 → 回填**，或从本机 `tccli` 导入。

PolyOpus 现状：

- `30 §14A.2` 只有“Tab 终端/浏览器”，没有 cloud。
- `04` 路由只有 `/workbench`、`/workbench/browser/:id`、`/workbench/terminal/:id`。
- 原型 `prototype/app.js` 的工作台也只有 `terminal/browser`。

**问题**：如果目标是“对齐 Octop b4”，工作台的页面结构、权限默认值、空态、危险操作确认都缺一整块；如果目标是不做云主机，必须在 `01/28` 明确写“非目标”，否则会被误认为漏项。

### 3.2 通知：后台提醒 → 系统通知

Octop b4 把“后台标签页的定时提醒”从页面内提醒改为**系统通知**。PolyOpus 只有 Attention/收件箱，用于审批/提问/受阻，没有“定时任务完成/失败”的轻量通知。

**问题**：`30` 没有通知中心/浏览器通知的权限、降级（未授权通知权限时回落到站内）、点击跳转与去重规格。

### 3.3 聊天列表：隐藏专家

Octop b3 支持在聊天列表隐藏任意专家（不影响专家本身）。PolyOpus `30` 的对话侧栏只有搜索/新建/更多，没有“隐藏/恢复”与“隐藏后如何找回”。

### 3.4 技能包：文件树编辑 / 共享 / 头像

Octop b3/b1 支持技能包文件树编辑、共享、头像、复制策略。PolyOpus `30 §8` 只有安装/更新/启停/来源/版本，没有文件树编辑器与共享范围。

### 3.5 用量：大额 token 缩写

Octop b4 对超大 token 用量做缩写（如 1.2M）。PolyOpus `30 §9` 未定义格式，容易在表格里撑破列。

### 3.6 连接器：类别筛选

PolyOpus `CONN-001` 已有按类别/搜索筛选，和 b4 对齐。✅

### 3.7 专家市场 vs 模板库

Octop b3 把内置专家并入“专家市场”，安装包不再自带市场目录。PolyOpus `04` 是“专家列表 Tab：我的/团队/模板库”，市场在 v2。**这是范围决策，不是 bug**；但 `01` 的“模板库”与 b4 的“市场”语义要对齐，避免 UI 文案两套。

## 5. Octop b4 仍然不能照抄的地方

b4 修了一些 b2 的问题（共享连接器编辑权、聊天历史错序、记忆分批、MFA 旧库补齐、记住登录续期），但以下结构性问题仍在：

| 问题 | b4 证据 | PolyOpus 应坚持 |
|---|---|---|
| 无租户 | 全仓 `tenant_id` 只出现在 agent/connector 字段，不是隔离边界 | 全表 `tenant_id` + repo 强制过滤 |
| IM 身份塌缩 | `message_keys.py:92-107` 仍把所有 IM 消息归 `agent_owner_id` | `source_actor` 归属，不继承 owner |
| 固定切片 | `chunk.py:6` 仍是 800/120 字符 | 结构感知 300–800 token |
| 暴力检索 | `index.py:108` 仍是 in-process cosine 全表扫描 | pgvector/BM25 + RRF |
| 检索失败静默 | 仍以空上下文降级 | 结构化错误 + 事件 |
| 插件任意代码 | 仍无 permissions 声明/沙箱 | 子进程 + 权限 + 签名 |
| 工具治理多套并行 | catalog/plugin/skill/security/MCP 仍分散 | 单一策略引擎 + 执行期校验 |
| 工具调用审计不完整 | 审计仍以管理动作为主 | 每次 tool call 落 `tool_calls` + 事件 |

## 0. 范围裁定（唯一口径）

### 0.1 v0.5 的一句话

**在 Web / webhook / schedule 三类入口下，Agent 能"不用显式 @"接活：Assessment 研判 → Ticket 自动执行 → Report → 回到原来源线程；失败/超预算进 Attention；重启不丢。**

这是对 `06`/`45` 中「接入 GitHub/飞书后…」的**修订**：按 `28 §1.2` 与 `46 P1-5`，v1 的来源封顶为 Web / webhook / schedule，GitHub、邮件、IM 全部 **v1.1**。v0.5 不接外部渠道，出口演示用 webhook + schedule 完成。

### 0.2 为什么前端底座进 v0.5

| 事实 | 影响 |
|---|---|
| 当前生产前端是 `src/polyopus/web/index.html` 单文件（23.5KB，原生 JS） | 只能支撑 v0.1 的"一屏"演示 |
| `docs/33 §5` 的目标是 React + TS + Vite + TanStack Query + 8+3 壳 | 后续任务中心/审批/来源配置都依赖这一层 |
| v0.5 目标用户是 3–10 人小团队 | 单文件无法承载多页面、URL 状态、权限与四态 |
| `generated/ts` 已有 API/事件类型 | 前端可一次接对契约，避免手写漂移 |

**裁定**：v0.5 包含前端底座，但只迁 **Chat / Tasks / Usage** 三个已有后端的页面；其余 8+3 路由先占位（`ComingSoon`），完整页面留给 v1.0。前端底座不是"重写全部界面"，是"把后续 UI 的地基一次打好"。

### 0.4 已具备（v0.5 不重做）

- **入口**：`POST /webhooks/{source_id}`、HMAC 验签、`(source_id,dedupe_key)` 幂等、Source 配置、disposition 审计（S2-01/02、INTAKE-001/002/003）。
- **工单**：Ticket + Mandate + `timeline_events` + `tickets.stop` + Watchdog + 预算闸门（S2-03..06）。

- **注意力**：approval 卡、批准/拒绝/过期、任务中心收件箱（S1-05、S2-05）。
- **执行**：turn worker、策略引擎、fs.read/fs.write、审批恢复、跨进程重启（V01-01..04）。

### 0.5 前端底座技术决定（2026-11，V05-01 前置）

| # | 决定 | 理由 | 落点 |

| F4 | **样式/组件**：CSS Modules + prototype tokens；Dialog/Drawer/Menu/Tooltip 用 Radix primitives；只做明/暗 | 不引 Tailwind；a11y 不自造 | V05-06 |

| F10 | **测试**：Playwright 用临时 DB + `POLY_ADMIN_PASSWORD` 起 `poly serve`；CI 顺序 `contracts.generate → build → test → e2e`；禁止只查 HTML 字符串 | 现有 `test_screen.py` 只查字符串 | V05-01/03 |

## 4. 任务卡

### A 线 · 前端底座

#### V05-01 · 前端工程底座与 AppShell（2d）
- 产出：`web/`（Vite + React 19 + TS 5 + TanStack Query v5 + React Router v7）、`vite.config.ts`（proxy `/api`、`/healthz` → 8000）、`tsconfig.json`、`src/app/{App,router,providers}.tsx`、`layouts/{AppShell,Sidebar}.tsx`、`pnpm-lock.yaml`；`src/polyopus/web/` 作为构建产物入库。
- 做法：8+3 路由先全量注册，只有 `/chat`、`/tasks`、`/usage` 指向真实页，其余 `ComingSoon`（标 `v1.0`）；登录页 + 路由守卫；`poly serve` 挂静态目录 + SPA fallback；token 从 `prototype/index.html` 抽到 `styles/tokens.css`；`scripts/check.py` 增加 `web-build`；CI 加 Node 22 + corepack pnpm + 缓存。
- 验收：
  - `corepack enable && pnpm --dir web install`（lockfile 生效）
  - `pnpm --dir web build` 产出 `src/polyopus/web/index.html` + assets；`git diff --exit-code src/polyopus/web` 为空（dist 同步）
  - `uv run python scripts/check.py --skip test --skip coverage` 含 `web-build` 且通过
  - `uv run poly serve --port 8000` 后 `GET /` 与 `GET /tasks` 均 200（SPA fallback），`GET /api/v1/healthz` 不被 fallback 吞掉
  - dev 下 `GET /api/v1/threads` 经 Vite proxy 返回 200；SSE 首字逐个到达（不整段缓冲）
  - 构建拆 `vendor-react`/`vendor-query`/`vendor-ui`；prod drop console；旧 hash chunk 404 触发一次软刷新
  - `pnpm --dir web test` 通过；侧栏 8+3 计数与路由表一致
- 风险：SPA fallback 与 API 路由冲突 → 只对非 `/api`、非 `/healthz` 的 GET 回 `index.html`；Vite proxy 缓冲 SSE → 见 §0.5 的实测与回退方案。

#### V05-02 · API 客户端 + 类型 + SSE（1d）
- 产出：`web/src/lib/api/{client,generated,endpoints}.ts`、`lib/stream/sse.ts`、`lib/auth`。
- 做法：`client.ts` 统一 fetch（`credentials: "include"`，cookie-first，不读 localStorage token）、`X-Trace-Id`、错误信封映射（`AUTH_FAILED`/`TOKEN_IN_QUERY`/`VALIDATION_FAILED`）；401 单飞（`poly:unauthorized` 只跳一次登录，带 `returnTo`）；`generated.ts` 直接 re-export `generated/ts/src/*.gen.ts`；SSE 封装只做 SSE（无 WS），支持 `after_seq` 续读、断线退避、重复 seq 去重、切线程 abort；store 依赖 `StreamTransport` 接口（SSE 现在/WS 以后）；未知事件/缺字段宽容解析。
- 验收：
  - `pnpm --dir web test -- api`（401 跳登录、403/409/422 映射、traceId 透出）
  - 用真服务器跑 `useStream`，断线后从 `last_seq` 续读不重复
  - 浏览器 `document.cookie` 看不到 token；localStorage 无 accessToken
  - 组件不直接 `new EventSource`（lint 规则或 grep 门禁）
- 风险：`generated/ts` 未随契约更新 → CI 先跑 `python -m contracts.generate` 再 build；refresh 未实现 → 401 走登录，不假装自动续期。

#### V05-03 · Chat 页迁移（1.5d）
- 产出：`routes/chat/ChatPage.tsx`、`features/chat/{components,hooks,api}`：会话列表、消息流、composer、审批卡。
- 做法：URL 带 `threadId`；流式 delta 按 seq 去重；审批卡走 Attention API；四态组件统一。**本卡只迁后端已有能力**：发送/流式/审批；停止 turn、重新生成、附件、编辑重发不在 v0.5（后端无对应端点）。
- 验收：
  - Playwright：登录 → 新建会话 → 发消息 → 看到 ≥2 个 delta → 审批卡批准 → 完成
  - `pnpm --dir web e2e -- chat`
  - 刷新后 `?threadId=` 可恢复同一会话
- 风险：旧 `index.html` 的 SSE 逻辑直接搬 → 必须走 `lib/stream`，不复制；把"停止/重试"当已有能力 → 本卡明确不做。

#### V05-04 · Tasks 页迁移（1.5d）
- 产出：`routes/tasks/TasksPage.tsx`、`features/tasks/*`：收件箱、四桶（attention/running/queued/done）、停止、详情浮层（scope/budget/report）。
- 做法：轮询 `GET /tickets` + `GET /tickets/{id}`；四桶计数优先用 `GET /tickets/counts`（V05-22），未合并时由列表客户端聚合；详情展示 timeline（V05-22）+ scope/budget/report；停止二次确认；标题 XSS 转义；空态给"创建演示 webhook"。
- 验收：
  - Playwright：seed 2 个 ticket → 四桶计数正确 → 停止后 bucket=done
  - `pnpm --dir web e2e -- tasks`
- 风险：自动执行未上线时页面只有 queued → V05-07 合并后补 running 态 e2e；V05-22 延后时 timeline 隐藏、counts 用列表聚合。

#### V05-05 · Usage 页迁移（1d）
- 产出：`routes/usage/UsagePage.tsx`、`features/usage/*`：summary（day/week/month × model）、CSV 导出。
- 做法：切窗口/筛选走 URL search params；导出与当前筛选一致；per-ticket 成本先显示 `—`（V05-18 接）。
- 验收：
  - 切窗口不串数据；导出内容与当前筛选一致
  - `pnpm --dir web e2e -- usage`
- 风险：`costMicros=0` 时显示 `unpriced`，不显示 ¥0 误导；把 per-ticket 成本当已有 → 本卡只占位。

#### V05-06 · UI kit / 四态 / 主题（1d）
- 产出：`components/ui/{Button,Dialog,Drawer,Table,Empty,ErrorState,Forbidden,Loading}.tsx`、`styles/tokens.css`、明暗主题；Dialog/Drawer/Menu/Tooltip 基于 Radix primitives。
- 做法：token 取自 prototype（颜色/间距/圆角/字号）；组件无业务；`components/ui` 不 import `features`；v0.5 只做明/暗，原型的 9 套配色留到 v1.0。
- 验收：
  - `pnpm --dir web test -- ui`；每个组件有 a11y（focus ring/aria/焦点陷阱）
  - 明暗切换持久化；1280/1024 不溢出（Playwright 截图）
- 风险：一次性做全套组件 → 只做本迭代三页用到的 12 个；主题蔓延 → 只留明/暗。

#### V05-23 · 流式恢复与刷新合并（1d）
- 依赖：V05-02、V05-03。
- 产出：`features/chat/inflight-cache.ts`、`merge-history.ts`、`useStream` 的 watchdog/seal prior。
- 做法：sessionStorage tail cache（200ms 防抖、单条 ≤80k、总 ≤1.5M、pagehide flush）；刷新后 history + 本地尾按最后 user message id 合并，取"更富"一侧；45s 无帧或 20s 无 ping 判 stale，最多 8 次重连；新 assistant 气泡开始时 seal 上一个 streaming；活动流存活时不做全量历史替换。
- 验收：
  - `pnpm --dir web test -- stream-recovery`（cache 命中/不命中、重复 seq、跳号、seal prior）
  - Playwright：流式中刷新 → 文本不丢不重；断网 5s 恢复；两个气泡不同时 streaming
- 风险：缓存把上一轮拼接进来 → 必须匹配最后 user message id；缓存无上限 → 按 80k/1.5M 截断。

### B 线 · 工单闭环

#### V05-07 · 工单自动执行（2d）
- 产出：`workers/ticket_loop.py`（或并入 `worker_loop` 的第二队列）、`tickets.claim_next/run_claimed`；迁移补 `assignments.attempt` + `UNIQUE(ticket_id, attempt)`。
- 做法：`tickets.state='open' AND bucket='queued'` 即工单队列；CAS 领取 + 租约；调用 `run_assignment` → Report → bucket；`UNIQUE(ticket_id, attempt)` 防双跑；`serve` 内嵌 + `poly worker` 均可跑。
- 验收：
  - `uv run pytest tests/e2e/test_ticket_auto.py -q`：webhook 进来后**不调用任何内部函数**，状态自动 `queued→running→done`
  - 10 个 webhook 并发 → 10 ticket 各执行一次；双 worker 零重复
  - 执行中 kill 进程 → 重启后 ticket 不丢（queued 重领或 running 标 recovered）
- 风险：工单与对话 worker 抢 SQLite 写锁 → 复用 `busy_timeout=5000`，单写者串行。

#### V05-08 · 出站回复（2d）
- 产出：`domains/outbound/{service,port}.py`、`source.config.callback_url`、`outbox` 发送、`POST /sources/{id}/test-reply`。
- 做法：Report ready/blocked/failed → 构造 Outbound（title/summary/link）→ 写 outbox → 异步 POST callback，HMAC 签名、幂等键 `(ticket_id, report_id)`、退避 3 次、死信。
- 验收：
  - `uv run pytest tests/e2e/test_outbound.py -q`：本地 callback 接收器收到 1 条；重试不重复
  - callback 500 → 重试 → 死信；`outbox` 状态可查
  - 回复内容不含密钥/绝对路径
- 风险：回调不可达阻塞执行 → outbox 异步，绝不阻塞 turn。

#### V05-09 · 失败/预算/停止 → Attention（1d）
- 产出：`Report.state in (failed,blocked)` → Attention(kind=blocked/failed)；`tickets.stop` 只停 Assignment。
- 做法：结构化 payload（reason/next_action）；预算超限沿用 S2-05；停止后不再接新事件。
- 验收：
  - `uv run pytest tests/e2e/test_ticket_attention.py -q`
  - 预算 1 token → blocked + Attention；人 stop → assignment ended/ticket ended
- 风险：自由文本推断 attention → 只认 Report/approval 结构化字段（`46 P0-1`）。

#### V05-10 · 订阅扇出（1.5d）
- 产出：`subscriptions`（ticket_id, event_thread_key）、`intake.fan_out`。
- 做法：Ticket 打开后订阅其 thread；同 thread 后续 Trigger 直达 Ticket，不再过 Gate/Assessment；无 open ticket 才走新单。
- 验收：
  - `uv run pytest tests/integration/test_subscriptions.py -q`
  - 同一 webhook thread 连发 5 条 → 1 ticket + 4 条 fan_out，不新建 ticket
- 风险：订阅泄漏导致永远不再建单 → ticket ended 时释放订阅。

#### V05-11 · 人工消息恢复 Ticket（1d）
- 产出：ticket 线程上的人类 turn → 唤醒/续跑 assignment（同 Mandate）。
- 做法：`S8`：人消息优先于自动任务；若 ticket ended 但同 thread 新消息 → 新 ticket（不复活旧单）。
- 验收：
  - `uv run pytest tests/e2e/test_ticket_human_resume.py -q`
  - 暂停的 ticket 收到人消息 → 恢复；已 ended 的 → 新单
- 风险：与订阅扇出循环 → 人类消息标记 `actor_kind=user`，不再触发扇出。

| 定时任务漂移 | 重复/漏跑 | DB 时间 + 单写者；错过只补最近一次 |
| 范围回涨 | 有人加 GitHub/飞书/通知 | 新卡必须过 §0 裁定，否则进 v1.0/v1.1 |

## 0. 范围裁定（唯一口径）

### 0.1 v0.5 的一句话

**在 Web / webhook / schedule 三类入口下，Agent 能"不用显式 @"接活：Assessment 研判 → Ticket 自动执行 → Report → 回到原来源线程；失败/超预算进 Attention；重启不丢。**

这是对 `06`/`45` 中「接入 GitHub/飞书后…」的**修订**：按 `28 §1.2` 与 `46 P1-5`，v1 的来源封顶为 Web / webhook / schedule，GitHub、邮件、IM 全部 **v1.1**。v0.5 不接外部渠道，出口演示用 webhook + schedule 完成。

### 0.2 为什么前端底座进 v0.5

| 事实 | 影响 |
|---|---|
| 当前生产前端是 `src/polyopus/web/index.html` 单文件（23.5KB，原生 JS） | 只能支撑 v0.1 的"一屏"演示 |
| `docs/33 §5` 的目标是 React + TS + Vite + TanStack Query + 8+3 壳 | 后续任务中心/审批/来源配置都依赖这一层 |
| v0.5 目标用户是 3–10 人小团队 | 单文件无法承载多页面、URL 状态、权限与四态 |
| `generated/ts` 已有 API/事件类型 | 前端可一次接对契约，避免手写漂移 |

**裁定**：v0.5 包含前端底座，但只迁 **Chat / Tasks / Usage** 三个已有后端的页面；其余 8+3 路由先占位（`ComingSoon`），完整页面留给 v1.0。前端底座不是"重写全部界面"，是"把后续 UI 的地基一次打好"。

### 0.3 不做（明确移出 v0.5）

| 项 | 去向 | 依据 |
|---|---|---|
| GitHub / 邮件 / 飞书 / 企微 / 钉钉 Source | v1.1 | `28 §1.2`、`46 P1-5` |
| 通知中心（站内 badge/浏览器通知） | v1.0 | `28 §2.11` |
| 插件 v1 / MCP / 专家 / 连接器 / 知识库 UI | v1.0 | `28 §1.1`、`01` v0.5 行 |
| 多租户 / RBAC / 控制面 / 云主机 | v1.0–v1.1 | `28 §1.2` |
| 工作流 DAG / 团队派工 / 桌面端 | v1.5+ | `28 §1.2` |
| DSH/Harness 执行器 | v1.5 前 | `46 P2-7` |

### 0.4 已具备（v0.5 不重做）

- **入口**：`POST /webhooks/{source_id}`、HMAC 验签、`(source_id,dedupe_key)` 幂等、Source 配置、disposition 审计（S2-01/02、INTAKE-001/002/003）。
- **工单**：Ticket + Mandate + `timeline_events` + `tickets.stop` + Watchdog + 预算闸门（S2-03..06）。
- **Assignment/Report**：`tickets.assign/run_assignment` 服务与 Report 行（仅测试驱动，**无生产触发**）。
- **注意力**：approval 卡、批准/拒绝/过期、任务中心收件箱（S1-05、S2-05）。
- **执行**：turn worker、策略引擎、fs.read/fs.write、审批恢复、跨进程重启（V01-01..04）。
- **账与知识**：usage ledger/summary/export、memory、KB + 黄金集（W11）。
- **前端**：登录/对话流式/审批卡/任务中心/演示触发器（单文件）。

## 4. 任务卡

### A 线 · 前端底座

#### V05-01 · 前端工程底座与 AppShell（2d）
- 产出：`web/`（Vite + React + TS + TanStack Query + Router）、`vite.config.ts`、`tsconfig.json`、`src/app/{App,router,providers}.tsx`、`layouts/{AppShell,Sidebar}.tsx`；`src/polyopus/web/` 改为构建产物。
- 做法：8+3 路由先全量注册，只有 `/chat`、`/tasks`、`/usage` 指向真实页，其余 `ComingSoon`；登录页 + 路由守卫；`poly serve` 挂静态目录 + SPA fallback；设计 token 从 `prototype/index.html` 抽到 `styles/tokens.css`。
- 验收：
  - `corepack enable && pnpm --dir web install`
  - `pnpm --dir web build` 产出 `src/polyopus/web/index.html` + assets
  - `uv run poly serve --port 8000` 后 `GET /` 与 `GET /tasks` 均 200（SPA fallback）
  - `pnpm --dir web test` 通过；侧栏 8+3 计数与路由表一致
- 风险：SPA fallback 与 API 路由冲突 → 只对非 `/api`、非 `/healthz` 的 GET 回 `index.html`。

#### V05-02 · API 客户端 + 类型 + SSE（1d）
- 产出：`web/src/lib/api/{client,generated,endpoints}.ts`、`lib/stream/sse.ts`、`lib/auth`。
- 做法：`client.ts` 统一 fetch、Bearer/cookie、`X-Trace-Id`、错误信封映射（`AUTH_FAILED`/`TOKEN_IN_QUERY`/`VALIDATION_FAILED`）；`generated.ts` 直接 re-export `generated/ts/src/*.gen.ts`；SSE 封装支持 `after_seq` 续读、断线重连、重复 seq 去重。
- 验收：
  - `pnpm --dir web test -- api`（401 跳登录、409 冲突、错误码映射）
  - 用真服务器跑 `useStream`，断线后从 `last_seq` 续读不重复
  - 组件不直接 `new EventSource`（lint 规则或 grep 门禁）
- 风险：`generated/ts` 未随契约更新 → CI 先跑 `python -m contracts.generate` 再 build。

#### V05-03 · Chat 页迁移（1.5d）
- 产出：`routes/chat/ChatPage.tsx`、`features/chat/{components,hooks,api}`：会话列表、消息流、composer、审批卡、停止/重试。
- 做法：URL 带 `threadId`；流式 delta 按 seq 去重；审批卡走 Attention API；四态组件统一。
- 验收：
  - Playwright：登录 → 新建会话 → 发消息 → 看到 ≥2 个 delta → 审批卡批准 → 完成
  - `pnpm --dir web e2e -- chat`
  - 刷新后 `?threadId=` 可恢复同一会话
- 风险：旧 `index.html` 的 SSE 逻辑直接搬 → 必须走 `lib/stream`，不复制。

#### V05-04 · Tasks 页迁移（1.5d）
- 产出：`routes/tasks/TasksPage.tsx`、`features/tasks/*`：收件箱、四桶（attention/running/queued/done）、停止、详情浮层（scope/budget/report/timeline）。
- 做法：轮询 `GET /tickets` + `GET /tickets/{id}`；停止二次确认；标题 XSS 转义；空态给"创建演示 webhook"。
- 验收：
  - Playwright：seed 2 个 ticket → 四桶计数正确 → 停止后 bucket=done
  - `pnpm --dir web e2e -- tasks`
- 风险：自动执行未上线时页面只有 queued → V05-07 合并后补 running 态 e2e。

#### V05-05 · Usage 页迁移（1d）
- 产出：`routes/usage/UsagePage.tsx`、`features/usage/*`：summary（day/week/month × model）、CSV 导出、按工单成本占位。
- 验收：
  - 切窗口不串数据；导出内容与当前筛选一致
  - `pnpm --dir web e2e -- usage`
- 风险：`costMicros=0` 时显示 `unpriced`，不显示 ¥0 误导。

#### V05-06 · UI kit / 四态 / 主题（1d）
- 产出：`components/ui/{Button,Dialog,Drawer,Table,Empty,ErrorState,Forbidden,Loading}.tsx`、`styles/tokens.css`、明暗主题。
- 做法：token 取自 prototype（颜色/间距/圆角/字号）；组件无业务；`components/ui` 不 import `features`。
- 验收：
  - `pnpm --dir web test -- ui`；每个组件有 a11y（focus ring/aria）
  - 明暗切换持久化；1280/1024 不溢出（Playwright 截图）
- 风险：一次性做全套组件 → 只做本迭代三页用到的 8 个。

### B 线 · 工单闭环

#### V05-07 · 工单自动执行（2d）
- 产出：`workers/ticket_loop.py`（或并入 `worker_loop` 的第二队列）、`tickets.claim_next/run_claimed`；迁移补 `assignments.attempt` + `UNIQUE(ticket_id, attempt)`。
- 做法：`tickets.state='open' AND bucket='queued'` 即工单队列；CAS 领取 + 租约；调用 `run_assignment` → Report → bucket；`UNIQUE(ticket_id, attempt)` 防双跑；`serve` 内嵌 + `poly worker` 均可跑。
- 验收：
  - `uv run pytest tests/e2e/test_ticket_auto.py -q`：webhook 进来后**不调用任何内部函数**，状态自动 `queued→running→done`
  - 10 个 webhook 并发 → 10 ticket 各执行一次；双 worker 零重复
  - 执行中 kill 进程 → 重启后 ticket 不丢（queued 重领或 running 标 recovered）
- 风险：工单与对话 worker 抢 SQLite 写锁 → 复用 `busy_timeout=5000`，单写者串行。

#### V05-08 · 出站回复（2d）
- 产出：`domains/outbound/{service,port}.py`、`source.config.callback_url`、`outbox` 发送、`POST /sources/{id}/test-reply`。
- 做法：Report ready/blocked/failed → 构造 Outbound（title/summary/link）→ 写 outbox → 异步 POST callback，HMAC 签名、幂等键 `(ticket_id, report_id)`、退避 3 次、死信。
- 验收：
  - `uv run pytest tests/e2e/test_outbound.py -q`：本地 callback 接收器收到 1 条；重试不重复
  - callback 500 → 重试 → 死信；`outbox` 状态可查
  - 回复内容不含密钥/绝对路径
- 风险：回调不可达阻塞执行 → outbox 异步，绝不阻塞 turn。

#### V05-09 · 失败/预算/停止 → Attention（1d）
- 产出：`Report.state in (failed,blocked)` → Attention(kind=blocked/failed)；`tickets.stop` 只停 Assignment。
- 做法：结构化 payload（reason/next_action）；预算超限沿用 S2-05；停止后不再接新事件。
- 验收：
  - `uv run pytest tests/e2e/test_ticket_attention.py -q`
  - 预算 1 token → blocked + Attention；人 stop → assignment ended/ticket ended
- 风险：自由文本推断 attention → 只认 Report/approval 结构化字段（`46 P0-1`）。

#### V05-10 · 订阅扇出（1.5d）
- 产出：`subscriptions`（ticket_id, event_thread_key）、`intake.fan_out`。
- 做法：Ticket 打开后订阅其 thread；同 thread 后续 Trigger 直达 Ticket，不再过 Gate/Assessment；无 open ticket 才走新单。
- 验收：
  - `uv run pytest tests/integration/test_subscriptions.py -q`
  - 同一 webhook thread 连发 5 条 → 1 ticket + 4 条 fan_out，不新建 ticket
- 风险：订阅泄漏导致永远不再建单 → ticket ended 时释放订阅。

#### V05-11 · 人工消息恢复 Ticket（1d）
- 产出：ticket 线程上的人类 turn → 唤醒/续跑 assignment（同 Mandate）。
- 做法：`S8`：人消息优先于自动任务；若 ticket ended 但同 thread 新消息 → 新 ticket（不复活旧单）。
- 验收：
  - `uv run pytest tests/e2e/test_ticket_human_resume.py -q`
  - 暂停的 ticket 收到人消息 → 恢复；已 ended 的 → 新单
- 风险：与订阅扇出循环 → 人类消息标记 `actor_kind=user`，不再触发扇出。

### C 线 · 准入与定时

#### V05-12 · Policy 版本化（1.5d）
- 产出：`policy_bundles`/`policy_rules` 版本、`policy_version` 写入 Ticket/Mandate。
- 做法：发布新版本不撤销在途 Mandate；扩大 scope 必须新 Ticket；支持 dry-run 与 LKG 回滚。
- 验收：
  - `uv run pytest tests/integration/test_policy_version.py -q`
  - 改策略后旧 Mandate 仍按旧版本执行；越 scope 被拒
- 风险：版本只在内存 → 必须落表并随 Ticket 快照。

#### V05-13 · Assessment 模型研判（2d）
- 产出：`domains/intake/assessment.py`、`evals` 表写入、`poly eval --dry-run`。
- 做法：便宜模型（deepseek-flash）`temperature=0`、结构化 JSON、超时 8s、失败 `unavailable` 重排；后处理不信任模型（scope 解析/⊆Policy/低置信 ignore/重复检测）；线程快照 5 分钟缓存。
- 验收：
  - `uv run pytest tests/integration/test_assessment.py -q`
  - 60 条标注样本：**accept precision ≥ 0.9**，误接率 ≤ 0.1（宁漏不乱）
  - `uv run poly eval --dry-run --source <id>`：24h 触发全部产出 disposition，不建单
- 风险：模型乱接 → 默认 `explicit_only`；precision 不达标只开干跑，不进自动接单。

#### V05-14 · Schedule Source（2d）
- 产出：`cron_jobs`、`kind=schedule` Source、`workers/scheduler.py`。
- 做法：cron/once/interval；时区显式；错过只补最近一次；重启从 `next_run_at` 继续；运行历史落 `cron_runs`。
- 验收：
  - `uv run pytest tests/integration/test_schedule.py -q`（时区/错过/重启/双跑）
  - 每 5 分钟任务跑 3 次，工单 3 张；停机 2 小时后只补 1 次
- 风险：Windows 定时精度 → 用 DB 时间 + 轮询，不用系统 cron。

#### V05-15 · 回复塑形（1d）
- 产出：`outbound/shaper.py`：webhook structured / web full / 未来 IM ≤100 词。
- 做法：同一 Report 按 `source.reply_style` 渲染；截断保留关键结论与链接；禁止把内部 trace 输出。
- 验收：
  - `uv run pytest tests/integration/test_reply_shape.py -q`
  - 同一 ticket 两种 style 输出不同且都含 ticket 链接
- 风险：渠道未接 → 只做 webhook/web 两种，IM 留接口。

#### V05-16 · 审批策略增强（1d）
- 产出：按 source/risk 的 auto-approve 规则、批量确认、过期自动 deny。
- 做法：策略仍走 `PolicyEngine`；auto-approve 只对显式白名单工具；批量只对同类 action。
- 验收：
  - `uv run pytest tests/e2e/test_approval_policy.py -q`
  - 白名单工具不弹卡；越权工具仍 ask；批量批准只处理选中项
- 风险：自动批准扩大攻击面 → 默认关闭，source 级显式开启。

### D 线 · 能力与账

#### V05-17 · 异步工具（2d）
- 产出：`ToolSpec.execution=sync|async`、`start()` 立即返回、`tool.result` 事件、取消。
- 做法：长任务写 `tool_calls`/`artifacts`，结果回到同一 turn；超时/取消可观测；不阻塞 worker 领取下一 turn。
- 验收：
  - `uv run pytest tests/integration/test_async_tools.py -q`
  - 10s 工具执行中，worker 仍能处理另一 turn；结果回原 turn
- 风险：异步结果与 turn 生命周期错配 → 结果事件必须带 `turn_id`，turn 结束后只落轨迹不续跑。

#### V05-18 · 成本与预算（1.5d）
- 产出：`model_prices` 种子（deepseek-flash）、per-ticket cost 汇总、source/day 预算。
- 做法：`usage_ledger.price_version` 已有；补价表与 `tickets.cost_micros` 回填；预算三层（ticket/source/day）。
- 验收：
  - `uv run pytest tests/integration/test_cost.py -q`
  - 20 个 turn 后 ticket cost > 0（不再 `unpriced`）；超预算 → blocked + Attention
- 风险：价格硬编码 → 只走版本化表，历史账不重算。

#### V05-19 · 审计与回放（1d）
- 产出：`audit_log` 写入 gate/assessment/reply/stop；`GET /admin/audit`（只读）+ 导出。
- 做法：不可修改、按人/事件/结果查询；ticket 时间线可回放；敏感字段脱敏。
- 验收：
  - `uv run pytest tests/integration/test_audit.py -q`
  - 每条 filtered/assessment/reply/stop 都能按 ticket 查到；导出 CSV 行数一致

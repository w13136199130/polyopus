# 16 · 稳定性与长期演进

> 目标：让产品"能长期跑、能定位问题、能安全升级、能局部改造"。
> 分四块：**运行稳定（SLO/降级/隔离）→ 行为稳定（Agent 不跑飞）→ 数据稳定（不丢/可恢复）→ 演进稳定（可替换/可升级）**。

---

## 1. SLO 与错误预算

| SLI | 目标 | 计算 | 告警 |
|---|---|---|---|
| HTTP 可用性 | 99.9% | 非 5xx / 总请求 | 5min > 1% |
| turn 成功率 | 99% | completed / (completed+failed) | 15min < 97% |
| 首 token p95 | ≤ 1.5s | turn.started→首个 delta | 10min > 3s |
| 工单完成 p95 | ≤ 30min（按类目） | ticket.opened→ended | 按类目分桶 |
| 队列排队 p95 | ≤ 2s | queued→running | > 30s |
| 事件写入 p95 | ≤ 100ms | append 耗时 | > 500ms |
| 审批等待 p95 | ≤ 1 工作日 | attention.requested→resolved | 仅统计 |
| 租约过期率 | < 0.1% | expired / claims | > 1% |
| 工单自动完成率 | ≥ 60% | 无人工介入 ended / 全部 ended | 7d < 50% |
| 人工干预密度 | ≤ 0.5 次/工单 | attention 数 / Ticket 数 | 7d > 1.0 |
| 注意力首响 p95 | ≤ 4h（工作时段） | attention.requested → 首次人工动作 | > 8h |

**错误预算策略**：月度预算耗尽 → 冻结新功能发布，只修稳定性（与发布流程联动）。

## 2. 故障域与降级矩阵

| 故障 | 影响 | 降级 | 用户可见 |
|---|---|---|---|
| LLM provider 超时/429 | 无法生成 | 重试→fallback→降级模型；全失败给 `MODEL_UNAVAILABLE` | 错误气泡 + 重试 |
| 向量库/检索超时 | 知识不可用 | 跳过知识，继续回答（标注"未使用知识库"） | 提示条 |
| MCP 服务不可达 | 该组工具不可用 | 标记工具不可用，不阻塞整轮 | 工具灰显 |
| 执行器崩溃 | 工单暂停 | 租约过期→重派（attempt+1） | 任务卡"重试中" |
| 队列积压 | 延迟上升 | 拒绝新 turn（429）/降级为排队 | 排队位置 |
| WebSocket 断 | 无实时 | 前端重连 + 补事件；降级为轮询 | 断线条 |
| 对象存储不可用 | 附件/产物 | 读走缓存；写失败重试 + 明确错误 | 上传失败 |
| 插件加载失败 | 该插件不可用 | 隔离该插件，其余正常 | 插件页报错 |
| 数据库只读/锁 | 全局 | 只读模式：可看不可写；写操作 503 | 全局横幅 |
| 磁盘满 | 写入失败 | 拒绝写入 + 告警；清理临时文件 | `STORAGE_FULL` |

**原则**：**降级要"部分可用"，不能"全有或全无"**；每次降级都发事件/指标，便于事后统计。

## 3. 幂等、重试、超时

| 操作 | 幂等键 | 重试 | 超时 | 备注 |
|---|---|---|---|---|
| 提交 turn | `client_msg_id` | 不自动重试（防重复） | 连接 10s | 失败由用户重发 |
| 工具调用 | `(run_id, step_idx, attempt)` | 仅 `idempotent=true` | 工具声明（默认 60s） | 非幂等不重放 |
| 审批 | `approval_id` | 是 | 30min 过期 | 重复提交返回同结果 |
| 派工 | `(ticket_id, attempt)` | 租约过期重派 | 心跳 15s / 租约 60s | attempt > 3 进死信 |
| 渠道回复 | `idem_key = hash(ticket+report)` | 是 | 30s | 平台侧去重 |
| Webhook 接收 | `(source, dedupe_key)` | 平台重投由幂等吸收 | 5s 内 202 | 先落库再处理 |
| 记忆写入 | `(namespace, content_hash)` | 是 | 30s | 去重后合并 |
| 备份 | `backup_id` | 是 | 按大小 | 失败清理临时文件 |

**重试预算**：每个请求最多 3 次、总时长 ≤ 30s；退避 0.5/1/2s + jitter；尊重 `Retry-After`。
**熔断**：同一 provider 连续 10 次失败 → 熔断 60s；半开探测 1 次。

## 4. 隔离

| 维度 | 隔离方式 | 验证 |
|---|---|---|
| 租户 | 所有查询强制 `tenant_id`；可选 PG RLS | 跨租户用例全空 |
| Agent | workspace 路径 jail；记忆 namespace | 路径穿越测试 |
| 执行器 | 每 Ticket 一个 workdir；进程/容器隔离 | 逃逸测试 |
| 插件 | 权限声明 + 高危子进程；UI 沙箱 iframe | 越权调用测试 |
| 渠道 | 每来源独立凭证；回复 scope 校验 | 越权回复测试 |
| 工具 | 网络 allowlist、文件 allowlist、超时 | SSRF/路径测试 |
| 模型 | 每租户配额；prompt 注入内容标记 | 注入用例集 |

**原则**：**隔离靠代码强制（repo/路径/策略），不靠"约定"**；每个隔离点都有负向测试。

## 5. 背压与容量

| 入口 | 限制 | 超限行为 |
|---|---|---|
| API | 每用户 60 req/min；每租户 600 | 429 + `Retry-After` |
| WS | 每连接 1MB/s；慢消费者降级合并帧 | 合并/断开 |
| 队列 | 深度阈值告警；> 2× 基线拒绝新 turn | 429 / 排队 |
| 上传 | 单文件 ≤ 100MB（可配）；并发 3 | 413 |
| 工具输出 | 32KB 内联；超出 artifact | 截断 + 引用 |
| 事件 | payload 32KB | 拆分/引用 |
| 执行器 | 每租户并发 N（默认 5） | 排队 |
| effect 队列 | 按 kind 配额：assessment 4 / delivery 4 / relay·notice·reply 1 / launch 按空闲 slot | 排队；人的消息唤醒优先 |
| 记忆 | 每 agent 5k atoms | 拒绝写入 + 提示清理 |

**容量模型（初版）**：1 租户 ≈ 50 并发 turn ≈ 5 执行器；PG 连接 20；向量 100 万 chunk/实例；事件 100 万/月（约 2GB）。超过 → 拆 worker / 分区 / 独立向量库。

## 6. 数据可靠性

| 项 | 做法 |
|---|---|
| 事件 | append-only；写入成功才推送；`(stream, seq)` 唯一 |
| 备份 | 一致性快照（DB + 密钥 + 配置）；默认每日；保留 7 份；manifest 记录包含项、sha256 校验和、schema 版本 |
| 恢复 | **每季度演练一次并留记录**（恢复到隔离环境 + 抽查数据 + 校验事件连续性，演练入 `audit_log`）；RTO ≤ 30min；恢复前强制：校验和比对 + `_schema_version` 兼容检查 + 二次确认 |
| 迁移 | 启动时自动迁移；失败拒绝启动并给回滚命令；迁移前自动备份 |
| 删除 | 软删 + 30 天回收站；租户删除走异步任务 + 审计 |
| 重建 | 投影可从 events 重建；提供 `poly repair projections` |
| 保留 | 事件 90 天热 + 归档；工单永久；trigger.raw 30 天 |

## 7. Agent 行为稳定性（关键）

Agent 的"不稳定"通常不是服务挂了，而是**跑飞、循环、乱调工具、忘事**。六道闸：

| 闸 | 机制 | 默认 |
|---|---|---|
| 步数上限 | `max_steps` | 30 |
| 预算上限 | tokens/cost/wall-clock/tool calls | 按 Agent/Ticket |
| 循环检测 | 相同工具+参数连续 3 次 → 中断并提示 | 开 |
| 工具白名单 | 只允许 Agent 绑定的工具 | 开 |
| 审批闸 | 高危写操作必须人批 | 开 |
| Watchdog | 心跳 + 漂移检测 | 5min |

**评测闸**（防"改提示词把能力改坏"；Runner 与数据集见 `19`）：

- 离线黄金集：工具选择、检索引用、拒答、注入抵抗、多步任务；
- 每次 prompt/模型/工具变更跑；关键指标下降 > 3% 阻断合并；
- 线上影子：新版本对 5% 流量只记录不执行，对比决策差异。

**可解释**：每个 turn 的决策都有事件（工具、审批、压缩、委派），支持回放到 UI。

## 8. 升级与兼容

| 对象 | 策略 |
|---|---|
| HTTP API | `/api/v1`；破坏性变更开 v2；v1 至少保留 6 个月 |
| 事件 | 信封 `v` + 只加字段；破坏性变更新 type 或 `v=2`，双发一个版本周期 |
| 插件 | `api_version` 主版本不兼容拒绝加载；次版本向下兼容 |
| 数据库 | 单向迁移 + 迁移前备份；不写 down migration（回滚靠备份） |
| 配置 | 新键有默认值；旧键保留并告警 |
| SDK/契约 | `contracts.generate --check` 进 CI；生成物不同步即失败 |
| 依赖 | 锁定版本；升级走 PR + 全量回归；许可证扫描 |

**废弃流程**：标记 `deprecated_at` → 文档公告 → 运行时告警（响应头/日志）→ 至少 2 个版本后移除。

## 9. 可改造性（Architecture Fitness）

### 9A. Housekeeping 矩阵（后台整理任务总表，N-06）

> 所有周期任务一处登记：频率/并发/失败处理/可观测。新增任务必须进此表，否则不实现。
> 统一约束：单实例并发 1（DB 租约防重）；失败重试 ≤3 次指数退避；每次运行记一条指标与 debug 日志。

| 任务 | 频率 | 做什么 | 失败处理 | 指标 |
|---|---|---|---|---|
| outbox 投递 | 1s 扫描 | pending 事件按 topic 投递 | 重试 3 次 → `failed` + 告警 | `outbox_lag_seconds` |
| 事件归档 | 1h | 超过 90 天的事件写对象存储 JSONL 后删除 | 跳过该分区，下轮再试 | `events_archived_total` |
| notifications TTL | 1h | 已读/过期通知清理 | 单条失败跳过 | `notifications_pruned_total` |
| grant 过期 | 5min | `expires_at` 到期的授权失效 + 缓存失效 | 幂等重跑 | `grants_expired_total` |
| idempotency_keys | 1h | 超 24h 的键清理 | 同上 | `idem_pruned_total` |
| oauth_states | 10min | 超 24h 的 state 清理 | 同上 | `oauth_pruned_total` |
| memory GC | 1d | 拒绝候选 30d / 退休 atom 90d / 孤儿 raw 180d | 分批 ≤500 行 | `memory_gc_rows` |
| memory 抽取 | 空闲 300s / 6h | 会话抽取 → 候选 → 晋升 | lease 防重；失败保 raw | `memory_extracted_total` |
| KB 启动恢复 | 启动时 | processing → pending 重入队 | 逐文档 | `kb_resumed_total` |
| KB 死信 | 30min | 失败超 3 次的摄取任务标 dead | 保留行供人工 | `kb_dlq_total` |
| instances 心跳 | 60s | 超 60s 无心跳标离线 | 幂等 | `instances_offline_total` |
| watchdog 巡检 | 5min | running assignment 心跳/漂移检查 | 告警 `watchdog.alert` | `assignments_stalled_total` |
| delegation 租约 | 30s | 租约过期的 running 派工重派 | attempts 上限 3 → dead | `delegations_requeued_total` |
| cron 补跑 | 每次触发 | 错过只补最近一次 | 记 `skipped` | `cron_misfired_total` |
| 备份自动 | 按设置(默认 24h) | 一致性快照 + 校验和 | 失败告警保留上次 | `backup_last_success_age` |
| 评测集回归 | 入库时/每日 | KB 黄金集 recall/faithfulness | 阈值未达阻断发布 | `kb_eval_score` |

### 9B. 适应度函数

用 CI 强制的"适应度函数"，而不是靠自觉：

| 函数 | 规则 | 工具 |
|---|---|---|
| 模块边界 | `kernel` 不 import `domains`；`domains` 不 import `api` | import-linter |
| 文件规模 | 单文件 ≤ 600 行（生成物除外） | 脚本 |
| 依赖方向 | 只允许 inward | import-linter |
| 契约同步 | `contracts.generate --check` | 已有 |
| 事件兼容 | 已发布必填字段不得删 | schema diff |
| 迁移幂等 | 同一迁移跑两次结果一致 | 测试 |
| 许可证 | 禁止 GPL/AGPL/SSPL 进入核心 | 依赖扫描 |
| 复杂度 | 圈复杂度 ≤ 15 | ruff/radon |

**可替换点（演进缝）**：

```
ModelGateway      → 换模型厂商
Executor          → 换内置/Codex/Claude Code/DSH
MemoryProvider    → 换自研/mem0/Zep
SourceAdapter     → 加来源
ChannelAdapter    → 加渠道
BlobStore         → 本地/S3/COS
EventBus          → 进程内/Redis/NATS
ContextAssembler  → 换压缩策略
```

每个缝都有接口 + 契约测试 + 至少一个替代实现（哪怕是假的），否则"可替换"只是口号。

## 10. 发布流程

```
PR → CI（lint/type/test/contracts/eval）→ staging 部署 → 冒烟
  → 10% 租户灰度（feature flag）→ 观察 24h（错误率/时延/成本）
  → 50% → 100% → 标记稳定
```

- **回滚**：镜像回滚 ≤ 5min；DB 迁移失败用备份恢复；插件回滚保留旧版本目录。
- **Feature flag**：新功能默认关；按租户/用户开；flag 有 owner 与过期时间。
- **事故**：P0 15min 内响应；24h 内出 postmortem（时间线/根因/改进项/负责人）。

## 11. 演进路线与改造点

| 阶段 | 可能的重构 | 如何保证不痛 |
|---|---|---|
| v0.5 → v1.0 | 单进程 → 拆 worker | 队列/租约已抽象；配置切 role |
| v1.0 → v1.5 | 自研记忆 → 接 Zep | MemoryProvider 端口 + 双写迁移 |
| v1.0 → v1.5 | 内置执行器 → 外部 Codex | Executor 端口 + Report 契约 |
| v1.5 → v2.0 | 单租户 → 多租户强化 | `tenant_id` 已在所有表；RLS 可选 |
| 任意 | 换模型/换向量库 | Gateway/Provider 抽象 + 契约测试 |

**改造原则**：先加端口与影子实现 → 双写/对比 → 切读 → 删除旧路径。禁止"大爆炸式重写"。

## 12. 风险登记册（增补）

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| Agent 跑飞/循环 | 高 | 中高 | 六道闸 + 评测 |
| 上下文压缩丢关键信息 | 中 | 高 | 探针校验 + 可回滚 |
| 记忆污染 | 中 | 高 | 写入白名单 + 来源分级 |
| 插件越权 | 中 | 高 | 权限声明 + 沙箱 + 审计 |
| 队列积压雪崩 | 中 | 高 | 背压 + 限流 + 降级 |
| 迁移失败 | 低 | 高 | 备份 + 启动校验 + 回滚 |
| 依赖许可污染 | 中 | 中 | CI 扫描 + NOTICE |
| 供应商 API 变更 | 高 | 中 | Gateway 适配 + 录制回放测试 |

# 21 · 数据存储、展示与切换

> 回答：**数据存在哪？怎么给用户看？能不能换存储？换的时候数据怎么办？**
> 一句话：**元数据在控制面数据库，文件在工作区，产物在对象存储，密钥加密在库；向量与投影是派生数据，可重建；切换靠"导出→迁移→校验→切入口"，不做热切。**

---

## 1. 结论先行

| 问题 | 答案 |
|---|---|
| 存在哪 | 四层：控制面 DB、Agent 工作区、对象存储（artifacts）、密钥/日志 |
| 谁是真相 | 事件（会话/工单）、Agent spec（DB+文件）、源文档、记忆原子、产物 blob |
| 谁是派生 | messages 投影、知识切片/向量、记忆 embedding、统计 |
| 怎么展示 | 每个数据类型都有对应页面 + "存储位置"信息 + 管理台数据地图 |
| 能换吗 | 能：存储后端（按 Agent）、DB 引擎（离线迁移）、向量（重建）、记忆（Provider）、实例（导出导入） |
| 能热切吗 | **不能**（v1 明确不做双写热切）；用维护模式 + 迁移 + 校验 + 切入口 |

## 2. 数据分层

```
┌──────────────────────────────────────────────────────────────┐
│ 控制面 DB（OLTP）                                             │
│  users/agents/versions/bindings/tickets/assignments/events    │
│  messages(投影)/memory_atoms/knowledge_chunks(向量)/usage     │
├──────────────────────────────────────────────────────────────┤
│ Agent 工作区（文件）                                           │
│  SOUL.md / AGENTS.md / skills/ / references/ / notes/         │
├──────────────────────────────────────────────────────────────┤
│ 对象存储（不可变 blob，内容寻址）                               │
│  artifacts/<sha256>  附件、截图、导出、报告、大工具结果          │
├──────────────────────────────────────────────────────────────┤
│ 密钥与运维                                                     │
│  secrets（加密列）/ master.key / logs / traces / backups       │
└──────────────────────────────────────────────────────────────┘
```

### 2.1 权威 vs 派生

| 数据 | 权威 | 派生/可重建 | 说明 |
|---|---|---|---|
| 会话/工单 | `events`（append-only） | `messages` 投影 | 投影坏了可从事件重建 |
| Agent 配置 | DB `agent_versions` + 工作区文件 | — | 文件是提示词/技能的真相 |
| 知识 | 源文档（blob）+ `kb_documents` | `kb_chunks` + 向量 | 换模型只需重建向量 |
| 记忆 | `memory_atoms` | embedding | 换 embedding 模型重算 |
| 产物 | blob（sha256） | 缩略图/预览 | 预览失败不影响原文件 |
| 用量/审计 | `usage_records`/`audit_log` | 聚合报表 | 报表可重算 |

> 原则：**能重建的绝不备份两份；不能重建的必须有备份。**

## 3. 默认部署下的磁盘布局

```
~/.polyopus/
├─ config.toml               # 进程配置（DB/存储/日志）
├─ poly.db                   # SQLite 控制面（Postgres 模式下不存在）
├─ secrets/
│  └─ master.key             # 32B，0600；也可用环境变量注入
├─ workspaces/
│  └─ <agent_id>/            # SOUL/AGENTS/skills/notes
├─ artifacts/
│  └─ ab/cd/abcdef...        # 内容寻址（sha256 前 2/2 位分片）
├─ logs/
│  └─ poly.log
├─ backups/
│  └─ poly-2026-11-05.tar.gz
└─ plugins/
   └─ <id>/<version>/
```

**Postgres 模式**：`poly.db` 换成 DSN；`workspaces/artifacts` 仍可本地或远程。

## 4. 数据模型 → 介质映射

| 数据 | 表/路径 | 默认介质 | 可选介质 |
|---|---|---|---|
| 用户/角色/租户 | `users`,`roles`,`memberships` | 控制面 DB | — |
| Agent 元数据 | `agents`,`agent_versions`,`agent_bindings` | 控制面 DB | — |
| Agent 提示词/技能 | `workspaces/<id>/` | 本地 FS | S3/COS、Docker、PG（受限） |
| 会话事件 | `events` | 控制面 DB | — |
| 消息投影 | `messages` | 控制面 DB | — |
| 工单/派工 | `tickets`,`assignments`,`reports` | 控制面 DB | — |
| 记忆 | `memory_atoms`,`memory_profiles` | 控制面 DB（pgvector/sqlite-vec） | 外部 MemoryProvider |
| 知识文档 | `kb_documents` + blob | 控制面 DB + 对象存储 | — |
| 知识切片/向量 | `kb_chunks` | 控制面 DB（pgvector/sqlite-vec） | 外部向量库 |
| 附件/产物 | `artifacts` 表 + blob | 对象存储 | 本地 CAS |
| 密钥 | `secrets`（密文列） | 控制面 DB | — |
| 用量/审计 | `usage_records`,`audit_log` | 控制面 DB | 归档到对象存储 |
| 日志/Trace | 文件 + OTel | 本地文件 | OTLP/Langfuse |
| 备份 | `backups/*.tar.gz` | 本地 | 对象存储 |

## 5. 怎么展示

### 5.1 用户视角：每个数据都有"家"

| 数据 | 页面 | 展示方式 | 可做的操作 |
|---|---|---|---|
| 会话 | `/chat` | 消息流、产物卡 | 查看/导出/删除 |
| 专家配置 | `/agents/:id` | 提示词、技能、工具、知识绑定 | 编辑/发布/版本 |
| 工作区文件 | 专家详情 → 工作区 / 对话 Dock | 文件树 + 预览/编辑 | 上传/重命名/删除 |
| 知识 | `/knowledge/:kbId` | 文档表 + 切片 + 检索调试 | 上传/重索引/删除 |
| 记忆 | 专家 → 记忆 Tab | 原子列表/画像/来源 | 查看/纠错/删除/导出 |
| 工单 | `/tasks/:id` | 时间轴/报告/产物 | 停止/重派/导出 |
| 用量 | `/usage` | 趋势/按模型/按工单 | 导出 |
| 存储 | `/admin/storage` | 后端列表、用量、连通性 | 新增/测试/迁移 |
| 备份 | `/admin/backup` | 备份列表、恢复 | 创建/恢复/下载 |

### 5.2 "这条数据存在哪"——可解释性

每个资源详情页都有 **存储信息** 区块（可折叠）：

```
存储位置
  数据库     PostgreSQL @ db.internal:5432 / polyopus
  工作区     s3://acme-workspaces/agents/ag_01J... （远端）
  产物       本地 CAS：~/.polyopus/artifacts/ab/cd/...
  最后同步   2026-11-05 13:20
```

- 普通用户只看"本地/云端"与"是否已同步"。
- 管理员可看真实路径/桶名 + "在存储中打开"（本地文件管理器/S3 控制台链接）。

### 5.3 管理台"数据地图"

`/admin/storage` 增加一屏：按租户/类型统计行数、字节数、增长率、异常（孤儿 blob、缺失文件、投影滞后），并提供"校验/重建/迁移"入口。

## 6. 能不能切换

### 6.1 五种"切换"，分别怎么做

| 切换 | 粒度 | 是否支持 | 方式 | 停机 |
|---|---|---|---|---|
| 存储后端（本地 ↔ S3） | 按 Agent / 全局 | ✅ | 改 spec + `poly storage migrate` 复制并改写引用 | 短暂只读 |
| DB 引擎（SQLite ↔ PG） | 实例 | ✅ | `poly db migrate`（dump/restore + 校验） | 维护模式 |
| 向量后端（sqlite-vec ↔ pgvector） | 实例 | ✅ | 重建索引 | 后台，可读 |
| 记忆 Provider（Pg ↔ mem0/Zep） | 按 Agent | ✅ | 导出/导入 + 双读校验 | 无（双写期除外） |
| 实例（导出/导入） | 租户/用户 | ✅ | `poly export` / `poly import` | 无 |

### 6.2 存储后端切换（最常用）

```bash
# 1) 新增后端并测试
poly storage add --name cos-prod --kind s3 --endpoint ... --bucket ...

# 2) 预检：文件数、总大小、冲突
poly storage plan --agent ag_123 --to cos-prod

# 3) 复制（幂等，可断点续传）
poly storage migrate --agent ag_123 --to cos-prod --concurrency 8

# 4) 校验：sha256 manifest 对比
poly storage verify --agent ag_123 --to cos-prod

# 5) 切换（写 config，重建 runtime）
poly storage use --agent ag_123 --backend cos-prod
```

- 迁移期间该 Agent 进入只读（避免边写边迁）。
- 旧后端保留 7 天，回滚只需切回。
- 远端路径规则：`s3://bucket/tenants/<tenant>/agents/<agent_id>/...`。

### 6.3 DB 引擎切换

```
1. 进入维护模式（API 只读，worker 停止领取）
2. 备份 SQLite/源 PG
3. 导出（逻辑 dump 或 pg_dump）
4. 导入目标（建 schema → 迁移 → 导入）
5. 校验（表计数、事件连续性、抽样）
6. 改 config.toml → 重启
7. 观察 24h，旧库保留 7 天
```

**不支持热切**：双写会带来一致性、序列、锁的复杂度；v1 明确用维护窗口（通常 < 30 分钟）。

> 参考 Octop 的教训：它只在 setup 阶段支持热切库，且 history_v2 与 PG 互斥。我们不做这种半吊子能力。

### 6.4 记忆 Provider 切换

- `MemoryProvider` 端口 + `export/import`。
- 切换期：**双读单写**（写新 Provider，读新旧合并去重），观察 1 周后切读、停旧。
- 失败回滚：把 `provider` 配置切回，数据仍在旧库。

### 6.5 不能"切换"的东西

- **租户归属**：`tenant_id` 不可变；跨租户转移 = 导出/导入。
- **事件历史**：不可改；只能追加。
- **工件哈希**：内容寻址，改内容即新 blob。

## 7. 一致性与事务边界

| 操作 | 事务范围 | 失败处理 |
|---|---|---|
| 写事件 + 更新投影 | 同一 DB 事务 | 回滚，不产生半截消息 |
| 写 artifact 元数据 + blob | 先写 blob（幂等），再写元数据 | 孤儿 blob 由 GC 清理 |
| 写工作区文件 + DB 引用 | 先写文件，再写引用（或反之 + 补偿） | 校验任务修复 |
| 工单状态 + 事件 | 同一事务 | 回滚 |
| 记忆写入 + 事件 | 同一事务 | 回滚 |

**跨介质没有分布式事务**：用"先写不可变、后写引用、后台对账"的模式；每天跑 `poly doctor --storage` 找孤儿/缺失。

---

## 8. 多租户

- 所有表带 `tenant_id`；查询强制过滤。
- 对象存储路径前缀 `tenants/<tenant>/...`；签名 URL 带租户校验。
- 大租户可选 **schema-per-tenant**（PG）或独立实例（T3）。
- 删除租户：异步任务删 DB 行 + workspace + artifacts + 向量 + 审计留存。

## 9. 备份、恢复、导出

| 能力 | 内容 | 命令 |
|---|---|---|
| 全量备份 | DB + secrets + config + workspace 清单（artifacts 可选） | `poly backup create` |
| 恢复 | 校验版本 → 恢复 DB → 校验事件连续性 → 重启 | `poly backup restore` |
| 租户导出 | DB 行（JSONL）+ workspace + artifacts 清单 | `poly export --tenant` |
| 用户导出 | 该用户的消息/记忆/工单/文件 | `poly export --user` |
| 产物单独备份 | 对象存储版本化/跨区复制 | 由存储层负责 |

- 备份默认每日 04:00，保留 7 份；恢复演练每季度。
- `artifacts` 很大时默认不打包，依赖对象存储的版本化；需要时 `--include-artifacts`。

## 10. 容量、清理与生命周期

| 数据 | 策略 |
|---|---|
| 事件 | 90 天热 + 归档（Parquet/JSONL 到对象存储） |
| 消息投影 | 永久（随租户删除） |
| 日志 | 14 天，压缩 |
| 临时文件 | 24h 清理 |
| 孤儿 blob | 每周 GC（无引用且 >7 天） |
| 备份 | 7 份滚动 |
| 记忆 | 每 Agent 5k atoms 上限；TTL 见 `13` |

## 11. 常见问题

**Q：我用 Postgres，还需要本地磁盘吗？**
需要：至少放 `secrets/master.key`、日志、临时文件；workspace/artifacts 可全远端。

**Q：能不能只用 S3，不要本地目录？**
可以（`workspace.backend=s3` + `artifact_store=s3`），但 `master.key` 必须在本地或 KMS。

**Q：切换存储会丢数据吗？**
按 §6.2 的 plan→migrate→verify→use，且旧后端保留 7 天，不会。

**Q：能不能把某个 Agent 的数据搬到另一个实例？**
用 `poly export --agent` / `poly import`；ID 会重映射，`legacy_map` 保留。

**Q：向量能不能换库？**
能，重建索引即可；切片文本是权威，向量是派生。

**Q：用户能看到自己的数据存在哪吗？**
能看"本地/云端 + 是否同步"；管理员能看真实路径。

**Q：多租户会不会互相看到文件？**
路径前缀 + 签名 URL 校验 + DB 行级过滤；越权用例见 `20`。

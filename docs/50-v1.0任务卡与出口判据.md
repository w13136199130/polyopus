## 1. 卡片约定

- 估时 0.5d / 1d / 1.5d / 2d；超过 2d 必须拆卡。
- 一张卡 = 一个 PR；PR 标题带卡号。
- 验收必须是命令，不是描述；命令写进卡片，CI 里同名目标必须存在。
- 每张卡至少 1 条**越权/负向**测试（涉及身份/资源/配额的卡尤其如此）。
- 新增 API 必须进 OpenAPI + `implemented.json` + 前端类型；新增事件必须进 `schemas/events`。
- 前端卡必须同时更新 `web/` 源码与 `src/polyopus/web` 构建产物。

## 4. 卡片详情

### A 线 · 生产基线

#### V1-01 · 多租户上下文与隔离（2d）
- 产出：`platform/tenant.py`（`TenantContext`）、所有 domain service 的 tenant 参数、跨租户 404 规则、迁移补 `tenant_id` 索引。
- 做法：API 依赖解析 session → tenant；service 层禁止无 tenant 查询；跨租户一律 `404 NOT_FOUND`（不泄露存在性）；后台 worker 从 row 取 tenant，不读全局。
- 验收：
  - `uv run pytest tests/security/test_tenant_isolation.py -q`：两租户 × 6 资源 × 读/写/删全拒
  - `uv run pytest` 全量绿；v0.5 的 e2e 不回归
  - `uv run python tools/export_implemented.py --check`
- 风险：漏一个查询就泄露 → 用 `tenant_id` 必填的 repository/helper；静态检查 + 夜跑矩阵。

#### V1-02 · RBAC / 权限点 / 路由守卫（2d）
- 产出：`roles`/`user_roles`/`permissions`、`admin|member|auditor` 三角色、`require(permission)` 依赖、前端路由/按钮同源权限表。
- 做法：权限点 `resource:action`；后端先鉴权再查资源；前端用 `/auth/me` 返回权限集隐藏入口，但**不以隐藏代鉴权**；auditor 只读审计/用量。
- 验收：
  - `uv run pytest tests/security/test_rbac.py -q`：角色 × 资源 × 动作矩阵；最后 admin 不可降级/删除
  - `pnpm --dir web test -- rbac`：侧栏/按钮与权限一致
  - `uv run pytest tests/e2e/test_settings.py -q`
- 风险：权限点膨胀 → 只登记本卡消费的点；新增资源必须加一行矩阵。

#### V1-03 · 认证加固（2d）
- 产出：refresh token rotation/family revocation、`/auth/refresh`、API Key（哈希存储、scope/expiry）、MFA（TOTP + 恢复码）、step-up（5 分钟）。
- 做法：短 access + 单次 refresh；重放旧 refresh 撤销 family；API Key 只显示一次；MFA 关闭/重置/创建 Key 需 `REAUTH_REQUIRED`；`?access_token=` 一律 `TOKEN_IN_QUERY`。
- 验收：
  - `uv run pytest tests/security/test_auth_hardening.py -q`：refresh 重放、family 撤销、Key 越权、step-up 超时、token-in-query
  - `pnpm --dir web test` 绿；登录/刷新/401 跳转不回归
- 风险：把 refresh 存 localStorage → 只允许 httpOnly cookie；文档与代码同查。

#### V1-04 · 用户 / 邀请 / 角色管理（2d）
- 产出：`/admin/users`、`/invites*`、角色分配、最后一个 admin 保护、操作审计；管理页真页。
- 做法：邀请过期/已用/撤销分别错误码；禁用用户撤销 session；角色变更写 audit；删除/降级 admin 二次确认。
- 验收：
  - `uv run pytest tests/e2e/test_admin_users.py -q`
  - `pnpm --dir web e2e -- settings`：邀请→接受→分配角色→禁用
  - `uv run pytest tests/security/test_rbac.py -q`
- 风险：邀请链接泄露 → 一次性 token + TTL + 接受时校验邮箱。

#### V1-05 · 三层配额与超限行为（1.5d）
- 产出：`quota_limits`、租户/用户/模型三层限额、402 `QUOTA_EXCEEDED`、超限 Attention。
- 做法：请求前预检 + 使用后记账；限额可配 0=不限；返回 `details{scope,limit,used}`；不静默降级。
- 验收：
  - `uv run pytest tests/integration/test_quota.py -q`：每层独立触发；0 不限制；并发不超卖
  - `GET /usage/summary` 与 quota used 一致
- 风险：并发读写超卖 → CAS 或单写者事务。

#### V1-06 · 审计合规（1.5d）
- 产出：审计保留策略、按用户/租户导出（JSONL+artifacts）、租户删除异步清理、审计匿名化。
- 做法：沿用 V05-19 `audit_log`；导出走 `data_jobs`；删除先软删再清业务/事件/对象；审计只追加。
- 验收：
  - `uv run pytest tests/integration/test_audit_export.py -q`：CSV/JSONL 行数一致；删除后审计匿名
  - `GET /admin/audit` 与导出过滤一致
- 风险：删除破坏审计 → 先导出、再匿名化、最后物理删除。

#### V1-07 · 备份恢复与演练（2d）
- 产出：`poly backup` / `poly restore`、SQLite 一致性快照（backup API）、artifact/workspace 打包、恢复演练脚本。
- 做法：WAL checkpoint 后快照；备份含 schema version；恢复先校验 checksum/版本；RTO 记录。
- 验收：
  - `uv run pytest tests/integration/test_backup_restore.py -q`：备份→删库→恢复→事件 seq 连续、ticket/report 一致
  - `uv run python scripts/restore_drill.py`：RTO ≤ 30 min（本机）
- 风险：热备不一致 → 只用 SQLite backup API，不 cp 文件。

#### V1-08 · 可观测（2d）
- 产出：`/metrics`（Prometheus）、5 个 SLO、告警规则、trace 采样（错误/审批/deny/慢请求 100%）、看板 JSON。
- 做法：指标命名 `poly_<domain>_<unit>`；SLO 用 burn-rate；禁止高基数标签（ticket_id 不进 label）。
- 验收：
  - `uv run pytest tests/integration/test_observability.py -q`：指标出现、标签集稳定、采样决策
  - `curl /metrics` 含 turn/tool/queue/usage 四组
- 风险：指标爆炸 → 白名单标签；trace 采样别把 PII 写进 span。

#### V1-09 · Watchdog v1（1.5d）
- 产出：stalled/drifting 检测、`watchdog.alert`、一键 stop/requeue、5 分钟告警。
- 做法：心跳阈值 + 便宜模型/规则判偏离；动作需审计；同一 Assignment 去重。
- 验收：
  - `uv run pytest tests/integration/test_watchdog.py -q`：注入卡死 5 分钟内告警；requeue 上限
- 风险：误杀正常长任务 → 阈值按 executor/工具类型可配。

#### V1-10 · 站内通知（1d）
- 产出：`notifications` 表 + 未读聚合 + `/notifications*` + 顶栏入口；IM 推送留 v1.1。
- 做法：attention/ticket/usage 事件触发；未读计数；已读幂等；可跳转资源。
- 验收：
  - `uv run pytest tests/integration/test_notifications.py -q`
  - `pnpm --dir web test` + 通知入口 e2e
- 风险：通知风暴 → 聚合窗口 + 每类去重。

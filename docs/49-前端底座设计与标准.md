## 0. 结论摘要

**技术栈**：React 19 + Vite 7 + TS 5 + TanStack Query v5 + React Router v7（library mode）
+ CSS Modules + Radix primitives；不引 Next/SSR/Tailwind/Redux；v0.5 不引 Zustand。

**架构三句话**：

1. **服务端状态归 TanStack Query，活动流归 stream store，视图状态归 URL**；三者不互相镜像。
2. **events 是真相**：`message.delta` 只进活动流；`message.completed`/`turn.finished` 后以 messages 投影为准。
3. **契约先行的边界是"已实现端点白名单"**：`generated/ts` 是类型源，不是实现承诺。

**三条铁律**：

- 不直接 `new EventSource`：用 fetch-based SSE（能读 401、能 abort、能带 trace header）。
- 不把 token 放 localStorage：cookie-first，SSE 也靠 cookie。
- 不手改 `src/polyopus/web/`：它是 `web/` 的构建产物，CI 做 drift check。

## 1. 设计原则

| # | 原则 | 具体含义 | 反例 |
|---|---|---|---|
| 1 | **状态分层** | 服务端快照/活动流/视图状态各有唯一归属 | tickets 同时存 Query 和 Zustand |
| 2 | **URL 即视图** | 选中项、筛选、Tab、窗口都进 query string | 全塞 localStorage，刷新丢 |
| 3 | **流式单一真相** | 活动 turn 只在 stream store；结束即清 | delta 写进 Query 缓存再 refetch |
| 4 | **失败可见可恢复** | 401/403/409/422/5xx 有明确 UI 与重试 | 静默重连、空白页 |
| 5 | **契约先行** | 只 import `generated/ts`；只包已实现端点 | 手写类型、调用 188 个契约里的 404 |
| 6 | **小表面积** | v0.5 只做 3 个真页，其余占位 | 一次做 8+3 全页面 |
| 7 | **a11y 默认** | 焦点、键盘、aria、对比度是完成条件 | 自造 Dialog 焦点陷阱 |
| 8 | **性能预算** | 首包/路由包/流式渲染有数字门槛 | 每 delta 重渲染整列表 |
| 9 | **测试在接缝** | 测 parser/store/错误映射/E2E 主链 | 只断言 HTML 字符串 |
| 10 | **不预支库** | 没有需求不引依赖（Zustand/zod/Tailwind） | 先装一套全家桶 |

## 4. 状态与数据架构

### 4.1 三类状态

| 状态 | 归属 | 例子 | 生命周期 |
|---|---|---|---|
| 服务端快照 | TanStack Query | threads、messages、tickets、usage | 随查询/失效 |
| 活动流 | stream store（`useSyncExternalStore`） | 当前 turn 的 delta、seq、状态 | 一次 turn |
| 视图状态 | URL search params | `threadId`、`bucket`、`window` | 刷新可恢复 |
| 纯 UI | 组件本地 / ui store | 侧栏折叠、主题 | localStorage（仅主题/折叠） |

### 4.2 Query key 约定

```ts
["threads"]                    // 列表
["thread", id]                 // 单线程
["messages", threadId]         // 消息列表
["tickets"]                    // 工单列表
["ticket", id]                 // 详情
["usage", window, model]       // 用量
```

- `staleTime`：threads/tickets 3s，messages 0（以事件为准），usage 30s。
- 轮询：tickets 3s（与现有任务中心一致）；threads 10s。
- 失效：`turn.finished` → messages/threads；`ticket.*` → tickets/ticket；`usage.recorded` → usage。

### 4.3 活动流状态

```ts
type StreamStatus = "idle" | "optimistic" | "streaming" | "reconnecting" | "error";

type ActiveTurn = {
  threadId: string;
  turnId: string;
  messageId: string;
  seq: number;          // 已处理的最大事件 seq
  text: string;         // 当前 assistant 文本
  status: StreamStatus;
  error?: { code: string; message: string; traceId?: string };
  startedAt: number;
};
```

**事件 → 动作**：

| 事件 | 动作 |
|---|---|
| `turn.queued` | 确认 turnId，乐观消息替换真实 ID |
| `turn.started` | status=streaming |
| `message.started` | 新建 assistant 占位 |
| `message.delta` | text += delta；按 50ms 批量通知 |
| `message.completed` | 用 payload blocks 覆盖文本；写入 messages Query 缓存 |
| `approval.requested` | 立即 paint 审批卡（跳过批队列） |
| `tool.*` | 立即 paint 工具状态（跳过批队列） |
| `usage.recorded` | 失效 usage 查询 |
| `turn.finished` | status=idle；invalidate messages/threads；清活动流 |
| `error`/断线 | status=error/reconnecting；保留已生成文本 |

### 4.4 乐观发送与回滚

1. 本地插入 user 消息（`clientPendingId`），composer 清空。
2. `POST /turns` 202 → 用 `turnId` 替换 pending。
3. 2s 未 ack 或网络错 → 撤回本地消息 + 恢复输入框 + toast。
4. 审批/停止等动作同样乐观 + NACK 回滚。

### 4.5 刷新/断线恢复（吸取 Octop chatStore 的教训）

- **活动流 tail 缓存**：把"最后一条 localPending 用户消息起"的尾部消息写入 `sessionStorage`
  （key `poly:inflight:<threadId>`），200ms 防抖，单条文本 ≤80k、总缓存 ≤1.5M；
  页面 `pagehide`/`visibilitychange=hidden` 立即 flush。
- **历史 + 本地尾合并**：刷新后先拉 history；若缓存 tail 的最后一条 user message id 与 history 对上，
  取"更富"的一侧（assistant 文本优先，工具量只做 tie-break）；对不上则丢弃缓存，避免把上一轮拼接进来。
- **serverCaughtUp**：history 已包含缓存里的 user message 时，清缓存；未包含时保留，直到 `turn.finished`。
- **watchdog**：45s 无任何帧（或 20s 无 ping 但有活动流）判 stale，abort + 重连；最多 8 次，
  后台线程不反复重连；重连成功后从 `after_seq` 续读，不整段重拉。
- **seal prior streaming**：新的 assistant 气泡开始（审批恢复/最终轮）时，把上一个仍在 streaming 的气泡标 done，
  避免两个光标同时闪。
- **刷新保护**：活动流仍活着时，暂时不做过上拉刷新/全量替换，避免把屏幕上的 token 清掉。
- **缓存边界**：key 带 tenant/thread；logout 清空；不缓存敏感工具输出；turn 结束即清。

## 5. 流式协议（SSE）

### 5.1 为什么不用 EventSource

| 需求 | EventSource | fetch-based SSE |
|---|---|---|
| 读 401/403 状态 | 不能（只有 onerror） | 能 |
| 自定义 header（trace） | 不能 | 能 |
| 主动 abort/切线程 | 弱 | AbortController |
| cookie | 自动 | `credentials: "include"` |
| 重连策略 | 浏览器黑盒 | 自己控制 |

**决定**：`lib/stream/sse.ts` 用 `fetch` + `ReadableStream` 解析 `text/event-stream`，不直接用 EventSource。

### 5.2 客户端状态机

```
idle → optimistic → streaming → idle
          │             │
          │             ├─ 网络错 → reconnecting →(after_seq 回放)→ streaming
          │             │                └─ EVENT_GAP → snapshot(拉 messages)
          │             └─ error{retryable} → error → retry
          └─ 2s 无 ack → rollback
```

### 5.3 解析与去重

- 逐行解析 `id:`/`data:`/`: ping`；空行分帧。
- `seq <= cursor` 丢弃；`seq > cursor + 1` 记为 gap → 拉 messages 快照重建。
- 未知 `type` 忽略并计数（不抛错，避免新事件把旧前端打崩）。
- `turn.finished` 后关闭连接；同一 thread 切换时 abort 旧连接。

### 5.4 心跳与重连

- 后端每 15s 输出 `: ping`；FE 45s 无任何帧视为 stale，主动 abort + 重连。
- 重连退避 0.5/1/2/4s，上限 30s；手动"重试"立即重连。
- 后端响应头：`Cache-Control: no-cache`、`X-Accel-Buffering: no`。

### 5.5 渲染节流

- 文本 delta 50ms 批量 paint（per-message buffer）。
- `approval.*`/`tool.*`/错误帧立即 paint。
- 消息行 `memo`；只更新活动消息，不重渲染历史列表。

### 5.6 传输适配器（为 v1.0 的 WS 留口）

Octop 的聊天是 WebSocket（`/api/agents/{id}/chat/ws`），我们 v0.5 用 SSE。为避免以后重写 store，
stream store 只依赖一个窄接口：

```ts
interface StreamTransport {
  connect(input: { threadId: string; afterSeq: number }): void;
  close(): void;
  onFrame(cb: (frame: EventFrame) => void): () => void;
  onState(cb: (state: "open" | "stale" | "closed") => void): () => void;
}
```

v0.5 只实现 `SseTransport`；v1.0 若加 steer/team/WS，只换 transport，不动 store 与页面。

## 6. 认证与会话

| 项 | 决定 |
|---|---|
| 传输 | httpOnly cookie；`credentials: "include"`；不读 `accessToken` JSON |
| 属性 | `HttpOnly`、`SameSite=Lax`、`Path=/`；prod 加 `Secure` |
| 启动 | `GET /auth/me` 探活；401 → `/login?returnTo=...` |
| 过期 | 8h；无 refresh（v0.5）；401 时清会话、保留草稿、跳登录 |
| SSE | 靠 cookie；fetch SSE 自动带 |
| CSRF | SameSite=Lax + 后端 Origin 校验（POST/PUT/PATCH/DELETE）；v1.0 再加 token/CSP |
| 登出 | `POST /auth/logout` → 清 Query 缓存 + 跳登录 |

**401 中断正在流式**：abort SSE → 保存当前草稿/未发送文本到 sessionStorage → 跳登录 →
登录后 `returnTo` 回原页并恢复草稿。不能无限重连。

## 7. API 客户端与错误模型

### 7.1 分层

```
lib/api/client.ts      fetch 封装：credentials、trace、超时、错误信封
lib/api/generated.ts   re-export generated/ts/src/*.gen.ts（禁止手写同名类型）
lib/api/endpoints/     每个已实现端点一个薄函数（白名单）
lib/api/errors.ts      ApiError + 错误码 → UI 语义
```

### 7.2 已实现端点白名单

`generated/ts` 来自 188 个契约 op，但后端当前只有不到 20 个。**FE 只允许包已实现端点**：

- 新增 `tools/export_implemented.py`：内省 `create_app().routes` → `schemas/api/implemented.json`。
- CI 跑 `--check`；`lib/api/endpoints` 的每个路径必须在白名单里。
- 单测：每个 wrapper 对一个临时服务器做 200/4xx smoke；不在白名单直接失败。

### 7.3 错误映射

| HTTP | code | UI |
|---|---|---|
| 401 | `AUTH_FAILED`/`TOKEN_EXPIRED` | 跳登录（带 returnTo） |
| 403 | `FORBIDDEN` | Forbidden 页/按钮禁用说明 |
| 404 | `NOT_FOUND` | Empty/NotFound，不泄露存在性 |
| 409 | `CONFLICT`/`ATTENTION_ALREADY_RESOLVED` | toast + 刷新当前对象 |
| 422/400 | `VALIDATION_FAILED` | 字段级错误，不丢输入 |
| 429 | `RATE_LIMITED` | 倒计时/禁用提交 |
| 5xx | `INTERNAL_ERROR` | ErrorState + traceId + 重试 |

未知 code 一律显示通用错误 + `traceId`；不把后端 message 直接当 UI 文案。

## 10. 性能预算

| 指标 | 预算 | 测量 |

## 11. 测试策略与 CI

| 层 | 工具 | 覆盖 |
|---|---|---|
| 单元 | Vitest | SSE parser、seq/gap、错误映射、URL 编解码、store reducer |
| 组件 | Testing Library | 四态、审批卡、composer、任务桶 |
| E2E | Playwright | 登录→对话→流式→审批；任务列表→停止；用量导出 |
| 契约 | pytest + smoke | FE 用到的端点逐个 200/4xx |

**E2E 数据**：临时 DB + `POLY_ADMIN_PASSWORD` + `POLY_MODEL_*=""`（FakeModel）；

**CI 顺序**：

```

git diff --exit-code src/polyopus/web
pnpm --dir web lint && pnpm --dir web typecheck
pnpm --dir web test
pnpm --dir web e2e
```

禁止：只断言 HTML 里的字符串；skip E2E；用真模型跑 UI E2E。

### 11.1 测试矩阵（按接缝，不按页面）

| 接缝 | 必测 |
|---|---|
| SSE parser | 分包/半帧/`: ping`/未知 type/多行 data |
| seq/gap | 顺序/重复/跳号 → snapshot |
| stream store | delta 合并、completed 覆盖、finished 清理、seal prior |

## 12. 构建与部署

- Vite `base: "/"`；产物到 `src/polyopus/web/`（`index.html` + `assets/`）。
- dist **入库**；CI `pnpm build && git diff --exit-code` 防漂移。
- FastAPI：
  - `GET /assets/*` → `StaticFiles`，`Cache-Control: public, max-age=31536000, immutable`。
  - `GET /` 与所有非 `/api`、`/healthz`、`/assets` 的 GET → `index.html`，`Cache-Control: no-store`。
  - 未知 `/api/*` 仍返回 JSON 404，不被 SPA fallback 吞。
- 开发：Vite proxy `/api`、`/healthz` → `http://127.0.0.1:8000`；同源 cookie；不开 CORS。
- SSE 代理：实测不缓冲；若缓冲，dev 直连 8000 + 精确 CORS 白名单（仅 dev）。
- Vite 构建：`manualChunks` 拆 `vendor-react`/`vendor-query`/`vendor-ui`；`ANALYZE=true` 可选 visualizer；
  prod `drop console.log/debug/info`；`base` 支持 `VITE_BASE_PATH`（子路径部署）。
- 部署换版：监听 `vite:preloadError` / 动态 import 失败；sessionStorage 一次性标记，软刷新一次；
  v0.5 无 SW，但要防止"旧页签加载已删除 hash chunk"白屏。
- 资源缓存：`index.html` no-store；`assets/*` immutable；chunk 名带 hash。
- prod `sourcemap: false`（或 hidden 上传内部），不把源码 map 发布到静态目录。

## 13. 开源对照

| 产品 | 栈/做法 | 我们取什么 | 我们不取什么 |
|---|---|---|---|
| **Vercel AI Chatbot**（vercel/ai-chatbot） | Next.js + AI SDK + shadcn/ui + Tailwind；`useChat` 管流式、工具卡、乐观 UI | 流式状态机、工具/审批卡的即时渲染、错误重试 | Next/SSR、Tailwind、Postgres |
| **Open WebUI** | SvelteKit；聊天流、模型选择、会话侧栏 | 聊天布局、断线重连、空态 | Svelte 栈 |
| **LobeChat** | Next.js + Zustand；feature slice、主题 token、插件/工具 UI | feature 切分、主题 token、工具消息形态 | 全局 Zustand、AntD 风格 |
| **Cal.com** | Next.js + tRPC + Prisma + Turborepo；Playwright | 类型安全客户端、E2E 纪律、设置页结构 | tRPC、monorepo |
| **Supabase Studio** | Next.js + TanStack Query；数据密集页 | Query key/失效/轮询模式 | 其表格/编辑器复杂度 |
| **Plane** | React + Django；Issue 详情、活动时间线 | 工单 timeline 的信息结构 | 其状态模型 |
| **Linear**（设计参考，非 OSS） | 同步引擎、乐观 UI、URL 状态、命令面板 | URL 即视图、乐观更新、键盘优先 | 自研同步引擎（v0.5 不需要） |
| **Grafana** | React + Redux；时间范围/面板进 URL | URL 查询参数 schema | Redux 全量状态 |
| **shadcn/ui** | Radix + Tailwind；组件归项目所有 | Radix primitives、组件可改 | Tailwind |
| **GitHub Primer** | Design tokens + React | token 命名、a11y 基线 | 整套组件库 |
| **Mattermost/Rocket.Chat** | WebSocket/SSE；心跳、重连、消息去重 | 心跳/退避/去重 | WS 协议（v0.5 只有 SSE） |

**结论**：我们取"流式状态机 + Query 缓存 + URL 状态 + Radix/a11y + Playwright"，
不取"Next/SSR、Tailwind、全局 store、monorepo、WS"。

### 13.1 Octop dashboard 对照（本地 1.0.3b4）

| 维度 | Octop | 本设计 | 判断 |
|---|---|---|---|
| 栈 | React 18 + Vite 6 + AntD 5/antd-style + ahooks + i18next；无 TanStack Query | React 19 + Vite 7 + Query v5 + CSS Modules + Radix | 我们更轻、边界更清楚；不取 AntD |
| 规模 | 1101 TS/TSX、290 测试文件；约 19.7 万行 | v0.5 约 3 页 + 底座 | 不追规模 |
| 认证 | JWT 存 localStorage/sessionStorage；滑动续期 header；401 事件 | HttpOnly cookie；401→登录；无 refresh | 我们更安全；不取 localStorage JWT |
| 聊天传输 | WebSocket `/chat/ws`；EventSource 轨迹（token 在 query） | fetch SSE；token 不进 query | 我们更简单/安全；v1.0 用 transport 适配器上 WS |
| 流式状态 | module Map + useSyncExternalStore；50ms paint；in-flight cache；history merge；watchdog；seal prior；HITL resume | 同类但缺 in-flight/history merge/watchdog | **补齐**（V05-23） |
| 数据层 | `useAsyncResource` 手写缓存 | TanStack Query | 我们更体系化 |
| 路由 | lazy + pathToKey + 权限 wrapper；19+ 路径 | 8+3 + 3 真页；无 RBAC | v0.5 不假装权限 |
| 主题 | `--fn-*` + 8 palettes + bootTheme | tokens + 明/暗 + FOUC script | v0.5 够用；palette 留 v1.0 |
| 构建 | outDir 到 Python 静态；manualChunks；PWA；visualizer；console drop | dist 入库 + drift；chunk split；无 PWA | 取构建细节，PWA 延后 |
| 测试 | Vitest 290 文件；无 Playwright | Vitest + Playwright | 我们补 E2E；仍要学其 store 单测深度 |

**结论**：Octop 的底座在"流式恢复/刷新合并/长会话"上比我们成熟，值得吸收；
它的 localStorage JWT、EventSource token query、AntD 重栈、pages/components 混放、无 E2E 是我们明确不取的。

## 14. 剩余问题逐项设计

### P0-1 · SSE 心跳与代理缓冲

- **设计**：后端每 15s `: ping`；响应头 `Cache-Control: no-cache`、`X-Accel-Buffering: no`；
  FE 45s 无帧判 stale，abort + 重连。
- **实现**：`api/routers/threads.py` 的 `frames()` 加 ping；`lib/stream` 加 stale timer。
- **验收**：60s 空闲连接收到 ≥3 ping；dev proxy 下首字逐个到达；断网 5s 后自动恢复。
- **卡**：V05-22（后端）+ V05-02（客户端）。

### P0-2 · 已实现端点白名单

- **设计**：`tools/export_implemented.py` 内省 FastAPI 路由 → `schemas/api/implemented.json`；
  FE `endpoints/` 只包白名单；CI `--check`。
- **实现**：脚本 + `lib/api/endpoints` 单测（每 wrapper smoke）。
- **验收**：wrapper 路径 100% 在白名单；调用未实现路径的测试直接红。
- **卡**：V05-02。

### P0-3 · 流式单一真相

- **设计**：§4.3 事件 → 动作表；活动流只活在 stream store；结束即清。
- **实现**：`features/chat/stream-store.ts`（useSyncExternalStore）+ `useStream` 契约测试。
- **验收**：完成后不出现重复/闪回；刷新与事件结果一致；重连无重复 delta。
- **卡**：V05-02/03。

### P0-4 · 静态产物与服务

- **设计**：§12 的 mount/cache/fallback 规则。
- **实现**：`api/app.py` 挂 `StaticFiles` + catch-all；Vite `base:"/"`。
- **验收**：刷新 `/tasks` 200；`/assets/*` 长缓存；`/api/unknown` 仍 JSON 404；`index.html` no-store。
- **卡**：V05-01。

### P0-5 · Cookie 认证与 CSRF 边界

- **设计**：§6；cookie 标志 + Origin 校验；prod `Secure`；v1.0 加 token/CSP。
- **验收**：跨站 POST 被拒；同源 POST/SSE 正常；logout 后旧会话失效。
- **卡**：V05-01/02 + 后端小改。

### P0-6 · 401 中断流式

- **设计**：fetch SSE 读状态；401 → abort、保存草稿、`returnTo` 登录。
- **验收**：手动过期 token 后发消息 → 跳登录，登录后草稿与原页恢复。
- **卡**：V05-02/03。

### P1-1 · URL 即视图

- **设计**：§8 参数表 + 默认值省略 + 前进后退。
- **验收**：三个页面的筛选/选中项刷新可恢复；分享 URL 打开同一视图。
- **卡**：V05-03/04/05。

### P1-2 · 四态与错误映射

- **设计**：§7.3 + `components/ui` 四态组件。
- **验收**：每页有 loading/empty/error/forbidden；错误显示 traceId；422 不丢输入。
- **卡**：V05-02/06。

### P1-3 · 事件联合与 seq gap

- **设计**：§5.3；未知事件忽略；gap → 拉 messages 快照。
- **验收**：注入未知 type 不崩；人为跳 seq 触发快照重建。
- **卡**：V05-02。

### P1-4 · 50ms 批处理

- **设计**：per-message buffer；结构化事件立即 paint；行 memo。
- **验收**：长回答 60fps；审批卡不延迟；1,000 条消息切换不卡。
- **卡**：V05-03。

### P1-5 · Tasks 信息缺口

- **设计**：新增 `GET /tickets/counts`、`GET /tickets/{id}/timeline`（白名单字段）。
- **验收**：counts 与列表一致；timeline 升序含 trigger/ticket/assignment/report/attention。
- **卡**：V05-22。

### P1-6 · E2E 用 FakeModel

- **设计**：Playwright 启动 `poly serve` 时强制 `POLY_MODEL_*=""`；临时 DB + 种子。
- **验收**：E2E 稳定 < 3 分钟；连续 10 次不 flaky。
- **卡**：V05-01/03。

### P1-7 · 状态库/路由模式

- **设计**：不引 Zustand；stream store 用 `useSyncExternalStore`；React Router library mode。
- **验收**：review 无全局 store；无 framework mode 构建。
- **卡**：V05-01/02。

### P1-8 · 边界 lint

- **设计**：ESLint `no-restricted-imports`/`no-restricted-globals`：
  features 互斥、组件禁直接 fetch/EventSource、禁 localStorage token。
- **验收**：故意越界能红。
- **卡**：V05-01。

### P1-9 · a11y 与主题闪

- **设计**：Radix + token + 首屏 inline 主题脚本。
- **验收**：键盘走完登录→发消息→审批；明暗首屏不闪；1280/1024 截图。
- **卡**：V05-06。

### P1-10 · 消息渲染与 XSS

- **设计**：v0.5 纯文本；上 markdown 时 `react-markdown + rehype-sanitize`；
  禁止 `dangerouslySetInnerHTML`。
- **验收**：注入 `<img onerror>` 按文本显示。
- **卡**：V05-03（纯文本）。

### P1-11 · 刷新/断线恢复（Octop 的核心优势）

- **设计**：§4.5 的 in-flight tail cache + history merge + watchdog + seal prior。
- **实现**：`features/chat/inflight-cache.ts`、`merge-history.ts`、`useStream` 的 watchdog；
  cache 用 sessionStorage，200ms 防抖，pagehide flush。
- **验收**：流式中刷新不丢已生成文本、不重复；断网 5s 自动恢复；两个气泡不会同时 streaming。
- **卡**：V05-23。

### P1-12 · 传输适配器

- **设计**：§5.6 `StreamTransport`；v0.5 只实现 SSE。
- **验收**：store/页面不 import SSE 具体实现；换一个假 transport 能跑 store 单测。
- **卡**：V05-02。

### P1-13 · 陈旧 chunk / 部署换版

- **设计**：`vite:preloadError`/动态 import 失败 → 一次性软刷新（sessionStorage 标记）；
  不做 PWA/SW。
- **验收**：改 dist 后旧页签点路由触发一次刷新并恢复，不白屏、不循环。
- **卡**：V05-01。

### P1-14 · 单飞 401

- **设计**：全局 `poly:unauthorized` 事件；首个 401 负责清理+跳转，其余只 abort；
  保存草稿与 `returnTo`。
- **验收**：并发 5 个请求同时 401，只跳一次登录；登录后回原页。
- **卡**：V05-02。

### P1-15 · 宽容解析

- **设计**：未知事件 type 忽略；usage/metadata/content block 变体归一；
  缺字段给默认值，不抛错。
- **验收**：注入未知 type/缺字段事件，页面不崩；usage 计数不出现 NaN。
- **卡**：V05-02。

## 15. 标准与 DoD

### 15.1 代码标准

- TS `strict`；禁 `any`（必要时 `unknown` + 收窄）；禁 `@ts-ignore`。
- 组件函数式 + hooks；一个文件一个默认导出组件；props 显式类型。
- 命名：`PascalCase.tsx`、`useXxx.ts`、`xxx.api.ts`、`xxx.store.ts`。
- 不写 `console.log` 进主分支；错误走统一错误模型。
- 单文件 ≤ 300 行；函数 ≤ 50 行（软约束，review 判断）。

### 15.2 页面 DoD

- [ ] URL 状态可恢复；前进/后退正确
- [ ] loading/empty/error/forbidden 四态
- [ ] 401/403/409/422 映射正确
- [ ] 键盘可完成主操作；焦点可见
- [ ] 1280/1024 不溢出
- [ ] 无 console error/warning
- [ ] Playwright 主链通过
- [ ] 流式中刷新：不丢已生成文本、不重复、不双光标
- [ ] 断网/部署换版：可恢复，不白屏
- [ ] 首包预算内

### 15.3 API wrapper DoD

- [ ] 路径在 `implemented.json` 白名单
- [ ] 入参/出参用 generated 类型
- [ ] 错误走 `ApiError`
- [ ] 有 smoke 测试（200 + 一个 4xx）
- [ ] 不泄露 token/绝对路径

### 15.4 组件 DoD

- [ ] 无业务依赖（不 import features）
- [ ] a11y（aria/键盘/焦点）
- [ ] 受控/非受控边界清晰
- [ ] 有 story 或测试用例（至少四态）
- [ ] 样式走 token，不写魔法值

### 15.5 Release DoD

- [ ] `pnpm build` 后 `git diff --exit-code src/polyopus/web` 为空
- [ ] `contracts.generate` 无 diff
- [ ] 全量 pytest 绿
- [ ] Playwright 绿
- [ ] 无 `unpriced` 误显示为 ¥0
- [ ] 变更说明含回滚方式

## 17. 风险

| 风险 | 信号 | 回退 |
|---|---|---|
| SSE 被代理缓冲 | dev 整段出现 | dev 直连 8000 + CORS 白名单；或换端口代理配置 |
| 契约/实现漂移 | wrapper 404 | `implemented.json` 白名单 + smoke 门禁 |
| 状态双写 | 消息重复/闪回 | 活动流单一真相 + 契约测试 |
| 构建产物漂移 | dist 与源码不一致 | CI `build && diff` |
| React 19/Radix 兼容 | 运行时警告 | 钉兼容版本；必要时降 React 18 |
| Playwright flaky | CI 偶发红 | FakeModel + 固定种子 + 重试 1 次 |
| 刷新丢 token/重复消息 | 刷新后文本缺失或双份 | in-flight cache + history merge + 单测；V05-23 |
| 部署后旧 chunk 404 | 旧页签点路由白屏 | `vite:preloadError` 一次性软刷新 |
| 401 并发重定向 | 多个登录跳转/页面抖动 | 单飞 unauthorized 事件 |
| 范围回涨 | 开始做 8+3 全页 | 只做 3 页；占位标 v1.0 |

# PolyOpus 功能全景与取舍

> **历史文档（b2 基线）**：本文保留作能力盘点与取舍依据；当前需求/契约/表/交互以 `28–40` 为准，b4 增量见 `37`。
>
> 目的：把 Octop 的**每一个功能项**拆到可决策粒度，逐项给出"它到底做了什么、代码在哪、值不值得做、在新项目里怎么做"。
> 结论先行：Octop 的能力面去重后约 **110 项**，其中建议 **保留 66 / 增强 33 / 重做 15 / 暂缓 13 / 砍 3**（含少量跨域重复计数的原始条目共 130）。
> 另有 **16 项 Super-agent 能力**（§N）是 Octop 没有、但常驻型 Agent 必需的，已纳入修订后的版本范围。
> 记法：✅ 保留（照做）｜⬆ 增强（做但改设计）｜🔁 重做（能力要、实现换）｜⏸ 暂缓（v2+）｜✂ 砍掉（不做）。

### 0.2 三条取舍原则

1. **凡是"状态在进程内"的能力，一律重做**（团队在途任务、steer 队列、HITL park、浏览器会话）。它们在单机 Demo 里没问题，在生产里就是"重启丢活"。
2. **凡是"绕过统一抽象"的能力，一律增强**（工具治理四套机制、模型解析散落、附件放 workspace）。功能不改，改的是接入点。
3. **凡是"重资产、低频、强平台绑定"的能力，一律暂缓**（远程安卓、FnOS 打包、媒体生成、云端一键部署）。它们对核心闭环没有贡献，却显著拉高维护面。

## N. Super-agent 补充能力（2026-11 修订，16 项）

> 来源：DeepSeek Harness《Super-agent 设计探索》与 `dsh-superagent-prototype` 的领域模型（见 `07`）。这些能力 Octop 没有或只有雏形，但对"常驻、并行、主动、可恢复"的工作系统是必需的。

| # | 能力 | 做法 | 为什么必需 | 版本 |
|---|---|---|---|---|
| S1 | **Source 统一接入** | 每个来源一个 adapter：GitHub / IM / 邮件 / Webhook / 定时；自持读取位点、bot 身份、Thread/Channel 映射 | 重启不重放；多来源一致 | v0.5 |
| S2 | **Trigger 不可变事件** | `(source_id, dedupe_key)` 唯一；同事件接受两次只建一个工单 | 幂等是所有自动化的地基 | v0.5 |
| S3 | **Disposition 去向审计** | 每条 Trigger 记录 filtered/evaluated/fanned_out + 原因 | 可解释"为什么没接"；调参依据 | v0.5 |
| S4 | **Gate 确定性准入** | 来源/身份/白名单/bot/限流/显式请求，毫秒级 | 便宜且可测；挡住 90% 噪声 | v0.5 |
| S5 | **Assessment 模型研判** | 便宜模型判断接不接、scope、explicit/inferred；输出结构化 Decision | 处理"这条 issue 值得做吗"这类语义判断 | v0.5 |
| S6 | **Policy 版本化** | 规则 + 各 Source 准入表/同步/机器人名单；每次 Mandate 记版本 | 规则可演进、可回滚、可解释 | v0.5 |
| S7 | **Mandate 工作授权** | 不可变：policy_version/scope/strength/matched_rules/actor | 主动性场景必须能回答"谁允许、能做多大" | v0.5 |
| S8 | **Ticket 工作单元** | `open ↔ ended`；人发消息可恢复（同 Mandate）；只有人能 stop | 跨多轮、可恢复、可停止 | v0.5 |
| S9 | **Assignment 执行绑定** | Ticket↔Executor，`pending→running→ended`，可多次/可换执行器 | 执行器可替换；失败可重派 | v0.5 |
| S10 | **Subscription 事件扇出** | Ticket 订阅 event_thread；后续事件直达，不再过 Router | 省 Router 决策（实测 +30% 决策、+37% token） | v0.5 |
| S11 | **Attention 结构化待决** | 审批/提问/受阻三类；结构化字段，不从自由文本推断 | 注意力是稀缺资源；避免"假等待" | v0.5 |
| S12 | **Watchdog 独立巡检** | 独立定时任务；心跳超时判 stalled，便宜模型判 drifting | Router 挂了它还在；卡住可发现 | v1.0 |
| S13 | **异步工具（全双工）** | `ToolSpec.execution=sync\|async`；`start()` 立即返回，结果作为新事件 | 长任务不阻塞；可边跑边接新指令 | v0.5 |
| S14 | **Chain of Recall** | Trigger/Thread/Ticket/Assignment/Run 稳定 ID 引用图；内联摘要 + 指针 + `recall()` | 长任务的多跳记忆，避免巨型 prompt | v1.0 |
| S15 | **回复塑形** | 按渠道策略输出：IM ≤100 词、GitHub 结构化、Web 全量 | 同一个 Agent 在不同渠道像"人" | v0.5 |
| S16 | **投机执行** | `strength=inferred` 时静默复现/修复，只有确认简单修复才出声 | 主动性不等于打扰；符合"最小注意力"原则 | v1.0 |

**与 Octop 的对照**：Octop 有"渠道 + 定时 + Webhook"，但没有 Trigger 幂等、没有 Gate/Assessment 分层、没有 Policy 版本与 Mandate、没有 Ticket/Assignment、没有 Attention、没有 Watchdog。所以这 16 项不是"增强"，而是**新域**。

**优先级**：S1–S11 + S13 + S15 进 v0.5（约 +6 人周）；S12/S14/S16 进 v1.0。

## O. 新项目相对 Octop 的 12 个"人无我有"

1. **持久化执行**：重启不丢进行中的对话、审批、派工。
2. **成本与配额**：不只是 token 计数，而是可计费的成本账本 + 三层配额。
3. **Agent 版本化**：草稿/发布/回滚，会话锁版本，可复现。
4. **工作流 DAG**：可视化编排 + 节点级重试/补偿/审批。
5. **运行回放**：任意 run 可重放到 UI，排障与演示一体化。
6. **检索评测**：知识库入库即跑黄金集，质量可见。
7. **策略引擎**：工具/命令/网络/数据访问统一治理，规则可单测。
8. **多租户**：从第一天支持团队/组织隔离。
9. **开放 API Key + 作用域**：可被第三方系统安全集成。
10. **可观测标准**：OTel 全链路，不绑定单一厂商。
11. **插件权限与开发模式**：从"任意 Python"升级为"可审计扩展"。
12. **数据可携带**：全量导出/导入，记忆与知识格式开放。

## Q. 每项功能的"完成定义"（DoD）

任何标 ✅/⬆/🔁 的功能，合入前必须同时满足：

1. **接口**：HTTP/WS 契约进 OpenAPI 或事件 Schema，前端类型由生成器产出（不手写两份）。
2. **权限**：有明确的权限点与越权测试用例（至少 1 条负向）。
3. **错误**：有稳定错误码 + 可读文案（中英）+ 前端兜底 UI。
4. **可观测**：关键路径有 span 与至少 1 个指标。
5. **测试**：单元测试覆盖核心分支；涉及流式/恢复的必须有集成测试。
6. **文档**：`docs/features/<id>.md` 一页，含截图与限制说明。

## 1. 逐项设计补齐

### 1.1 对话 → 任务升级（懒 Ticket 的交互）

**Octop 参考**

- Octop 没有 Ticket，所有入口都落到 `session → thread → turn`；cron 用 `cron_runs.lease_token`，团队用 job id。
- 可借：**不打断对话**、内联卡片、会话内继续；不借：没有授权信封。

**PolyOpus 设计**

1. **触发**：写工具 / `risk>=medium` / 审批 / 预算 / 异步 / 长任务 / IM/cron/webhook/团队入口。
2. **交互**：
   - 执行前在消息流插入「任务卡」：标题、触发原因、scope chips、预算、执行器。
   - 主按钮「开始任务」；次按钮「取消」；只读对话不出现卡片。
   - 创建后消息流显示 `已创建任务 #tk_...`，会话头出现任务 chip。
   - 审批/预算/失败都在同一张卡上更新，不跳页。
3. **数据**：`turn.ticket_id` 回填；`ticket.source=web`；Mandate 来自会话策略 + 用户显式请求。
4. **降级**：用户取消 → 不执行工具，保留消息；超时 → 转为 Attention，不静默丢。

**文档改动**：`04 §4` 加“任务卡”章节；`30 §3` 加卡片状态；`28 CHAT-015` 补验收句；`32 §4/§6` 已定规则。

**验收**：同一句“改文件并跑测试”在 Web 与 IM 都产生 Ticket + Mandate；只读问答不产生 Ticket。

### 1.2 任务中心的状态可视化

**Octop 参考**

- 运行轨迹抽屉（trajectory）：user/assistant/tool/context/compacted/system 时间线。
- cron 运行历史、团队房间的 speaker 渲染。

**PolyOpus 设计**

1. **统一时间线**：从 `events` 投影，阶段固定为 `trigger → gate → eval → ticket → assignment → report → attention → channel`。
2. **状态解释**：每个 bucket 显示“为什么在这”（等待审批/预算耗尽/执行器离线/心跳超时）。
3. **动作**：停止（只停 Assignment）、改派、追加预算、重试、查看产物；危险操作二次确认。
4. **预算/成本**：卡片上显示已用/上限，超限前 80% 预警。
5. **团队/云**：派工与 `cloud_ops` 复用同一时间线，不另做一套。

**文档改动**：`12` 补时间线组件 props；`30 §4` 补状态矩阵；`29` 已有 timeline 端点。

**验收**：任一工单可在 3 次点击内回答“现在在等谁/为什么停/下一步做什么”。

### 1.3 技能渐进披露与技能包

**Octop 参考**

- `SKILL.md` 只把索引放进 system prompt，正文按需 `read_file`；per-turn allowlist；技能包文件树、共享、头像、复制策略。

**PolyOpus 设计**

1. **索引**：只放 `name + description + when_to_use`；正文 `skill.read(slug)`，≤32KB，带 hash。
2. **选择器**：输入框 `+` 菜单可搜索技能；每轮可传 `skills=[...]`；禁用技能不出现在索引。
3. **可见性**：消息里显示“本轮使用了哪些技能”，点击跳到技能详情。
4. **技能包**：文件树编辑器、版本/依赖、共享范围、头像、复制策略（snapshot/lock/deny）。
5. **校验**：路径穿越、文件数、总大小、依赖缺失拒绝启用。

**文档改动**：`02 §7.1.1` 已有规则；补 `23` 专家抽屉技能分区；`30 §8` 文件树/共享/头像状态；`28 CAP-008/009`。

**验收**：装 50 个技能时 system prompt 只增加索引；禁用技能无法被 `skill.read` 读取。

### 1.4 知识库：评测、SQLite 路径、检索调试

**Octop 参考**

- 就绪门禁（模型/凭证/可嵌入性）、文档预览/重建、每 KB 独立索引；不借固定切片与暴力扫描。

**PolyOpus 设计**

1. **评测**：50 条黄金问答，`recall@5 ≥ 0.8`、`faithfulness ≥ 0.9`；入库即跑，CI 阻断回归。
2. **SQLite 路径**：FTS5 + sqlite-vec；pgvector 作为增强，不是唯一路径。
3. **检索调试面板**：命中 chunk、分数、耗时、ACL 过滤前后数量；空结果说明原因。
4. **摄取**：文档 hash、失败重试、死信、状态 `pending/processing/ready/failed`；失败不静默。
5. **引用**：chunk 存 `page/char_start/char_end`，引用可跳转。

**文档改动**：`03 §7` 补降级与 ACL 顺序；`28 KB-009/010`；`30 §7` 调试面板；`29` 已加 eval/reindex。

**验收**：换 embedding 模型可全量重建；SQLite 单机能跑通 50 问；空结果有可读原因。

### 1.5 记忆：从三层到“够用的五层”

**Octop 参考**

- 规则优先晋升（value→evidence→entity→duplicate→conflict）、BM25 + 多维打分、1500 token/200ms、人工复核、重启不重跑。

**PolyOpus 设计（v1）**

1. **三层**：raw → candidate → atom；candidate 有 TTL 与晋升规则。
2. **规则优先**：先确定性去重/冲突，再 LLM 判定；冲突保留双方 + `valid_from/to`。
3. **召回**：向量 + BM25；1500 token、200ms；晋升后缓存立即失效。
4. **幂等**：抽取任务 `lease/attempts`；`event_id` 唯一；重启不重跑。
5. **复核**：记忆页显示“为什么记这条”（证据 turn）；支持纠正/删除/导出/暂停。
6. **评测**：20 条探针；命中率/矛盾率/陈旧率/污染率。

**v1.5**：episode 聚合、entity/page、图谱。

**文档改动**：`13 §4` 补 BM25 参数、幂等、复核；`31` 已有表；`30 §14A.4`；`28 MEM-*`。

**验收**：长会话重启不重复抽取；冲突不静默覆盖；探针命中 ≥85%。

### 1.6 团队 / 渠道 / 控制面：交互先于实现

**Octop 参考**

- 团队房间 speaker 渲染、workbench 三 Tab、渠道 probe 返回缺什么凭证；不借进程内 job tracker、IM 身份归 owner。

**PolyOpus 设计**

1. **团队**：成员卡显示 `idle/busy` + 当前 delegation；派工时间线；停止分“协调者/整个房间”；失败可重派。
2. **渠道**：三步绑定向导（账号 → 探测 → 绑定 Agent）；探测结果列出缺失凭证；入站调试表（external_id/thread/状态）；`source_actor` 归属。
3. **控制面**：工作台三 Tab（终端/浏览器/云服务器）；默认 Tab 按权限；终端默认禁用；接管/关闭需确认；所有输入写审计。
4. **空/错态**：每个 Tab 有独立空态、权限 403、上游不可达提示。

**文档改动**：`03 §9/10/11`；`30 §14A.1–3/7`；`28 ORG/CHAN/CTL`；`04` 路由。

**验收**：成员忙时添加/移除被阻止且给出原因；IM 消息归属 `source_actor`；终端默认不可用。

### 1.7 云主机 / 通知：把 v1.1 交互补成可点击

**Octop 参考**

- 云主机：一键授权 → 浏览器登录 → 复制验证码 → 回填；或 tccli 导入；地域/实例/指标热力图/集群趋势/启停确认/AI 运维面板。
- 通知：后台标签页提醒改系统通知。

**PolyOpus 设计**

1. **云主机**：授权空态三步引导；账号卡（active/expired/error）；地域筛选；实例表；指标/趋势；启停确认 + 原因；AI 面板只读；凭证过期禁用所有操作。
2. **通知**：铃铛 + 未读角标；单条/全部已读；系统通知权限拒绝 → 站内降级；TTL 清理；点击跳转。
3. **安全**：凭证加密、不回显；云操作先写 `cloud_ops` 再调 API；审计。

**文档改动**：`30 §14A.7/8` 已有；补 `04` 路由与原型；`28 CLOUD/NOTIF`；`29 §3.14/3.16`。

**验收**：未授权时只显示引导；过期时操作禁用；通知权限拒绝不丢通知。

### 1.8 管理端：批量、导入、配额、审计

**Octop 参考**

- 批量用户启停/删除、邀请码、角色模板、分组、资源可见性、审计。

**PolyOpus 设计**

1. 用户批量启停/删除，逐项结果（部分失败）。
2. CSV 导入用户 + 邀请；重复/非法行报告。
3. 角色权限矩阵可编辑；内置角色不可删；last-admin 保护。
4. 分组资源授权（6 类资源）；默认私有。
5. 配额仪表盘（租户/用户/Agent）；成本价格表。
6. 审计筛选/导出/详情；不可修改。

**文档改动**：`29 §3.1/3.15`；`30 §10`；`28 ADM-*`。

**验收**：批量操作部分失败可读；不能删除最后一个 admin；无 grant 资源默认不可见。

### 2.2 设计完成定义（Design DoD）

任何域进入编码前，必须同时有：

1. 需求 ID + 验收句（正/负）。
2. API 契约（OpenAPI 或事件）。
3. 表/索引/迁移。
4. 页面结构 + 四态（loading/empty/error/disabled）+ 权限 + 危险确认。
5. 可点击原型（至少 1 条主流程 + 1 条失败流程）。
6. 测试 ID（正/负），并进 `coverage_check`。

缺一项即不进入实现。

# 46 · DSH 公开版对照与 7 项补丁

> 对象：[`deepseek-ai/dsh-superagent-prototype`](https://github.com/deepseek-ai/dsh-superagent-prototype)（MIT，研究原型，2026-11 快照）
> 结论：**领域模型已吸收；代码不复用；作为 v1.5 可选执行器；补 7 个设计缺口。**
> 本文是 `45` 路线文档的证据补充，**不改变路线**，只给"抄什么、不抄什么、还差什么"。

---

## 0. 一句话

它是**有意降级的 Super-agent 公开版**：降掉的是产品面与企业面（租户/保留/控制面/多实例），
**保住的是七条最难想对的不变量**；我们的架构不需要改，需要把其中两条不变量与五项工程约束写成硬约束。

## 1. 它是什么 / 不是什么

| 项 | 事实 | 来源 |
|---|---|---|
| 定位 | 监听**单个 GitHub 仓库**的主动式编码 Agent（可选飞书）：开 work item → 独立 Session/目录 → 回原对话/开 PR | README |
| 性质 | "Research prototype for reference only, not an official DeepSeek product"；"Treat it as research code, not production-ready software" | README |
| 与内部版关系 | 为公开发布做过改编，**与内部版本不同**；文章里部分设计是"未来方向"，未在本仓库实现 | README |
| 语言/构建 | TypeScript + pnpm + tsdown + vitest + `cordis` 插件体系 | 仓库根配置 |
| 运行时 | **自己不是内核**：`DshExecutor` 投递 launch/delivery effect，真正跑循环的是 **DeepSeek Harness** 的 Session（main Session + 每 Ticket 一个 Executor Session） | `docs/007-architecture.md` |
| 状态 | 一个 `<stateDir>/orchestrator.sqlite` + **目录锁**；Store 独占；单进程 | 同上 |
| 表 | `trigger / disposition / trigger_thread / thread / ticket / decision / effect / outbox / kv` | 同上 |
| 自述缺口 | **没有任何删除/保留策略，表会无限增长**；部分面板动作没有对应工具；部分事件无消费者；"钉死 Harness 版本 + 部署隔离"仍是 open question | 同上 |
| 许可 | MIT（可复用代码，但需保留版权声明；本文只复用思想与参数，不复用代码） | LICENSE |

**结论**：它不是可嵌入的引擎，而是**跑在 Harness 上的单仓库参考实现**。

## 2. 降级的八个轴（降级 ≠ 错误）

| 轴 | 公开版 | 内部/文章目标 | 性质 |
|---|---|---|---|
| 范围 | 单 GitHub 仓库 + 可选飞书 | 多来源、多仓库 | 范围降级 |
| 主体 | 无 Principal/Membership，跨源身份"当提示词文本" | 组织/成员/身份映射 | **主动拒绝**（Rejected concepts） |
| 部署 | 单进程 + 目录锁 + 单 SQLite | 多实例、隔离部署 | 运维降级（未解） |
| 数据 | 无删除/保留，表无限增长 | 保留/归档/合规 | 未做 |
| 产品面 | Panel 只列 attention；部分动作无工具；部分事件无消费者 | 完整控制面 | 未做 |
| 运行时 | 钉死一个 Harness 安装 | 版本解耦 | 未解 |
| 编排 | 单个 main Session 做路由/研判 | 横向扩展 | 未做 |
| 计量 | 无计费、无评测、无配额 | 企业化 | 未做 |

**为什么降级得这么狠仍然有价值**：它砍掉的都是"机械但昂贵"的部分（租户/保留/RBAC/API/计费），
留下的是"想错就全盘错"的部分（授权、幂等、状态归属）。这正是研究原型该有的取舍。

**反过来暴露的一件事**：公开版只留两个 Source 才能把演示做稳——**多来源的 Assessment 成本与误判率是超线性的**。
这直接支撑我们的 v1 来源封顶决策（见 `09 §1.4`）。

## 3. 它保住的七条不变量 vs PolyOpus

| # | 不变量（DSH 规则） | PolyOpus 落点 | 判定 |
|---|---|---|---|
| I1 | **Trigger 幂等**：同一 Trigger 投两次只建一个 Ticket | `09 §2.1` `(source, dedupe_key)`；`28 INTAKE-002` | 一致 |
| I2 | **Mandate 不可变**，Policy 版本写进 Mandate；改 Policy 不追溯已授权工作 | `09 §5.2`、`09 §6`、`31 mandates` | 一致 |
| I3 | **Ticket 状态不跟随 Executor Session** | `09 §7.1`、`32 §13B`（本次补写成不变量） | 一致 |
| I4 | **Subscription 只给上下文，不给授权** | `09 §7.3`、`32 §13B`（本次补写） | 一致 |
| I5 | **Eval 无状态**，没有"等待中"状态 | `09 §4`、`32 §13A` | 一致 |
| I6 | **Attention 结构化**，不从报告自由文本推断 | `09 §9`（本次补成硬约束） | **本次补** |
| I7 | **Disposition 全量记录**（含被过滤/重复/不可用） | `09 §2.4`、`31 trigger_threads.disposition`、180 天保留 | 一致 |

> 差异：I2 的"不追溯"在 DSH 是**不投递**；我们在 `09 §5.2` 对 deny/revoke **投递 `ticket.mandate_invalidated`**，
> 但不强制停（下次工具调用时校验）。这是更严格的一版，保留。

## 4. 被验证的三个技术选型

| 选型 | DSH 的证据 | 结论 |
|---|---|---|
| **用 DB 表当队列/effect 队列** | `effect` 表 + 每 2 秒 Pass + 按 kind 限流 + 退避 | 同构；我们加 `SKIP LOCKED` + 租约，是升级不是冒险 |
| **单进程默认、状态全在库** | 目录锁 + 单写者 + SQLite；重启靠表恢复 | 同构；我们用租约替代目录锁，可平滑扩到多实例 |
| **内核外置 / 执行器端口** | `DshExecutor` 只管投递与收报，循环归 Harness；ADR-014 舱 2 现在有两个真实供应商（harness、dsh） | 自研内核从"唯一路径"降为"默认路径 + 可验证退路" |

**一个新认识**：它的面板极简（只显示"需要人处理的事"），而我们有 17 个页面域——
**真正的工作量在前端，不在内核**。这印证 `45` 的"切片只做一屏"，也说明 M1 的前端范围必须继续收窄。

## 5. 七个缺口（已在代码/文档中核对，非推测）

| # | 缺口 | 证据 | 后果 |
|---|---|---|---|
| G1 | Attention 没有"只能由结构化字段创建"的硬约束 | `09/32` 无此句；DSH 明确列为不变量 | 实现时易解析 Report summary，审批语义腐化，违反 ADR-001 |
| G2 | 注意力/结果指标没进需求与 SLO | `28` 无"自动完成率/干预密度"；`16` 只有"审批等待 p95（仅统计）" | "省注意力"不可证 |
| G3 | effect/outbox 无按类并发配额；人工消息无优先 | `16 §5` 只有全局背压与每租户执行器并发 | 慢 effect 饿死其他类；人消息排在后台任务后 |
| G4 | Eval 输入的有界参数不完整 | `09 §4.1` 只有正文 ≤4000 字 | thread 窗口/Stub/分页无默认值，成本随 Thread 线性涨 |
| G5 | SourceAdapter 缺集中验收清单 | 四件事分散在 `09 §1` 各处 | 加第 N 个来源必漏"自我消息/读位点" |
| G6 | Router 层引入条件未预注册 | `34` 无此条 | 并发上来只能拍脑袋加层 |
| G7 | 没有"拒绝概念"负向清单 | `32 §13B` 只有正向不变量 | 实现者会顺手加"等待中 Eval/Subscription 准入" |

## 6. 七项补丁

### P0（语义正确性，先落文档）

| 项 | 落点 | 内容 | 验收 |
|---|---|---|---|
| **P0-1 Attention 结构化** | `09 §9`、`32 §13B` | attention 只能由 `Report.state=waiting` + `question{text,options,blocking}` 或 `approval.requested` 创建；禁止解析自由文本；缺字段的 waiting 降级 `blocked` 并标 `missing_structured_question` | e2e：报告只说"需要确认"但无字段 → 不生成 attention，进 Watchdog 报表 |
| **P0-2 注意力指标** | `28 OPS-006..009`、`16 §1` | 自动完成率、干预密度、attention 首响 p95、单工单成本 p50/p95 | 任务中心/用量页可见；SLO 表有目标与告警 |

### P1（M1 之前）

| 项 | 落点 | 内容 |
|---|---|---|
| **P1-3 effect 配额 + 人工优先** | `09 §8.1`、`16 §5` | assessment 4 / launch 按空槽 / delivery 4 / relay·notice·reply 1；每类独立退避；人消息唤醒优先 |
| **P1-4 Intake 有界上下文** | `13 §3.8`、`09 §4.1` 引用 | trigger 4000 字（首尾各 1500）；thread 首 5 + 两侧各 5；Ticket stub 50 字；列表 20/50 条、4000/8000 字 |
| **P1-5 v1 来源封顶** | `09 §1.4`、`28 §1` | v1 只启用 Web / webhook / schedule；GitHub、邮件、IM 全部 v1.1 |

### P2（v1.5 前，登记即可）

| 项 | 落点 | 内容 |
|---|---|---|
| **P2-6 Router 触发器** | `34` ADR-014 补充 | Ticket 并发 >10 持续 1 周 / Eval p95 >8s / Router 上下文 >60%，任一即引入独立 Router Session；在此之前明确不做 |
| **P2-7 dsh executor spike** | `41 §5A`、`34` ADR-015 | 3 天：scope 外拒绝并开 Attention、Report 六态映射、`stop()` 杀进程树、Harness 版本可复现 |

## 7. 明确不做

1. **不切 TS / 不引入 Harness 依赖**——它自己的部署隔离与版本钉死都还是 open question。
2. **不做"提示词身份映射"**——单租户下的合理简化，我们多租户必须建模为 `source_actors`。
3. **不把 Router 做进 v1**——单层 thread+turn 是 4 人团队的正确答案，用 P2-6 触发器兜底。
4. **不复制"无保留/无租户/面板即产品"**——这三条是它自认的债。
5. **不把 DSH 当底座**——复用不变量与参数，代码一行不进主干。

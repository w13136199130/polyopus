# 08 · 内核、执行器与 Codex 的关系

> 这篇只回答一个问题：**"内核"到底指什么？是不是就是调用 Codex？**
> 先给结论：**不是。** 内核是**我们自己写的 Agent 循环**；Codex / Claude Code / DSH 是**外部执行器**，属于"可插拔的第三方内核"，不是必需品。两者是"发动机"与"可换发动机的接口"的关系。

---

## 1. 四层拆开看

```
┌──────────────────────────────────────────────────────────────┐
│ 产品层  Intake / Policy / Ticket / 任务中心 / 知识 / 记忆       │  ← 我们的差异化
├──────────────────────────────────────────────────────────────┤
│ 执行器  Executor（端口）                                       │
│   ├─ 内置执行器：调我们的内核                                   │
│   └─ 外部执行器：调 Codex / Claude Code / DSH（它们自带内核）    │  ← 可替换
├──────────────────────────────────────────────────────────────┤
│ 内核    Agent Loop：prompt 组装 → 调模型 → 解析工具 → 回填 → 循环 │  ← 我们写（薄）
├──────────────────────────────────────────────────────────────┤
│ 模型    DeepSeek / Claude / GPT / 本地模型                      │  ← 只产出 token
└──────────────────────────────────────────────────────────────┘
```

| 层 | 是什么 | 谁提供 | 类比 |
|---|---|---|---|
| 模型 | 只会"下一个 token"的推理服务 | 模型厂商 | 燃料 |
| **内核** | 决定"下一步做什么、调什么工具、怎么把结果拼回上下文"的循环 | **我们写**（约 3–5k 行） | 发动机 |
| **执行器** | "把一个工单跑起来"的边界：启动会话、给工作目录、收进度、收结果 | 我们定义接口；内置或外部实现 | 变速箱/接口 |
| 产品层 | 谁允许做、做到什么程度、做完回哪里、人怎么介入 | 我们写 | 整车 |

**Codex 在哪？** 它属于"外部执行器"：一个**自带内核、工具、沙箱和编码专长**的第三方 Agent。调用它 = 把 `Ticket` 翻译成一次 Codex 会话，把它的输出翻译成 `Report`。它**不参与**我们的内核，也不是必须接。

---

## 2. 内核具体包含什么

内核只做一件事：**把"一次任务"从输入推进到输出**。它是纯逻辑，不认识数据库、HTTP、租户。

```python
class TurnEngine(Protocol):
    async def run(self, ctx: TurnContext) -> AsyncIterator[EngineEvent]: ...

@dataclass
class TurnContext:
    agent: AgentSpec            # 人格/模型/工具/预算
    messages: list[ChatMessage] # 已有上下文
    tools: list[ToolSpec]       # 可用工具
    model: ModelGateway         # 模型调用
    executor: ToolExecutor      # 工具执行
    approvals: ApprovalGate     # 审批中断
    steer: SteerQueue           # 中途插话
    budget: TokenBudget         # 预算
```

内部循环（简化）：

```
while step < max_steps:
    prompt = compose(system, memory, knowledge, history, budget)   # 提示词组装
    completion = model.stream(prompt, tools)                        # 调模型
    if completion.has_tool_calls:
        for call in completion.tool_calls:
            decision = approvals.gate(call)                         # 审批
            result = executor.run(call)                             # 执行工具
            messages.append(tool_result(result))                    # 回填
        continue
    return completion.text                                          # 结束
```

**必须由内核负责的 8 件事**（这些是产品差异，外部执行器给不了）：

1. 提示词组装与**上下文预算/压缩**；
2. 模型路由、重试、fallback、**流式归一化**；
3. 工具 schema 校验、超时、**并发/串行**；
4. **审批中断**（挂起/恢复/多端同步）；
5. **中途插话**（安全边界注入）；
6. **预算与步数**控制（防跑飞）；
7. **事件发射**（token/tool/usage/plan，驱动 UI）；
8. **取消**传播（模型流 + 工具 + 子进程）。

> 换句话说：内核不是"调模型"，而是"**调模型 + 管住它**"。Codex 也有自己的这 8 件事，只是不归我们管。

## 3. 执行器端口长什么样

```python
class Executor(Protocol):
    kind: str                      # builtin | codex | claude_code | dsh

    async def start(self, assignment: Assignment, ticket: Ticket, workdir: Path) -> ExecutorSession: ...
    async def send(self, session: ExecutorSession, input: TicketInput) -> None: ...
    async def stop(self, session: ExecutorSession) -> None: ...
    def health(self) -> ExecutorHealth: ...
```

- **内置执行器**：`start()` 内部起一个 `TurnEngine`，把内核事件翻译成 `Report`（progress/waiting/ready/blocked/failed）。
- **Codex 执行器**：`start()` 调 `codex exec`（或 ACP/JSON 模式），把工单描述 + 工作目录传进去；解析它的 stdout/事件，映射成 `Report`；`stop()` 杀进程树。
- **Claude Code 执行器**：同理，走它的 headless/ACP 模式。
- **DSH 执行器**：走插件/协议，把 Assignment 变成一个 DSH session。

**统一约束**（`07` §4.6 已有）：
- 每个 Ticket 一个 session + 一个 workdir；
- 执行器**只能**通过 `Report` 回报，不能直接改 Ticket 状态；
- 心跳/租约由平台管，执行器死了就重派。

## 4. 为什么不直接全用 Codex？

| 维度 | 全用外部执行器 | 自研内核（+ 可选外部执行器） |
|---|---|---|
| 出 Demo 速度 | 快（几天接一个 CLI） | 慢（3–4 周） |
| 编码任务能力 | 强（Codex/Claude Code 专精） | 中（要自己写工具与提示） |
| 通用任务（问答/IM/知识/浏览器） | 弱/不适配 | 强 |
| 审批/插话/预算/多端 | 外部执行器不暴露细粒度事件，难做 | 完全可控 |
| 多租户/计费/审计 | 只能包一层，粒度粗 | 原生 |
| 依赖风险 | 高（CLI 协议/版本/配额变动） | 低（模型 API 是稳定契约） |
| 成本 | 外部 Agent 通常更贵（自带长上下文） | 可控（自己的压缩与路由） |

**结论**：**内核是必须的**（否则通用场景做不了、平台差异做不了）；**外部执行器是加分项**（把"重编码活"外包给更强的专用 Agent）。

## 5. 什么时候接 Codex？

| 阶段 | 做什么 | 为什么 |
|---|---|---|
| **M0** | 定义 `Executor` 端口与 `Report` 契约 | 先定边界，后面不返工 |
| **M1** | 实现**内置执行器**（包住 TurnEngine） | 单机聊天/知识/IM 都要它 |
| **M3a** | 执行器选择（每个 Ticket 可指定 `executor_kind`） | Intake 派工需要 |
| **v1.5** | 接 **Codex / Claude Code** 作为"编码执行器" | 重编码任务交给专精 Agent，平台负责入口/授权/审计 |

> 接 Codex 的具体形态：优先 **ACP**（Agent Client Protocol，双向、结构化），其次 CLI JSON 模式，最后才是 PTY 抓屏。三者的事件粒度依次下降，`Report` 的丰富度也依次下降——UI 要能降级。

---

## 6. 一句话回答

- **内核** = 我们自己写的"调模型 + 管住模型"的循环（prompt、工具、审批、插话、预算、事件）。
- **执行器** = 跑工单的插槽；内置执行器用我们的内核，外部执行器用别人的内核。
- **Codex** = 一种外部执行器，**可选**，不是内核，也不是必须。
